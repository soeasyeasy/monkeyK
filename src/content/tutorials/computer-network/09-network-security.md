# 第9章：网络安全基础

## 本章导读

在学这一章之前，你可能会有这些疑问：

- 对称加密和非对称加密有什么区别？
- 数字证书是什么？为什么 HTTPS 需要证书？
- 防火墙是怎么保护网络的？
- 黑客是怎么攻击网络的？如何防范？

这一章就是为了解答这些问题。我们会先搞清楚**加密技术的基本原理**，再学习**数字证书和身份认证**，最后了解**防火墙和入侵检测系统**。

---

## 9.1 为什么需要网络安全？

### 痛点分析

如果没有网络安全：

- 密码、银行卡号等敏感信息会被窃听
- 数据容易被篡改，无法保证完整性
- 无法验证对方身份，容易被冒充
- 就像**寄明信片**，任何人都能看到内容

### 解决方案

网络安全技术提供：

| 安全目标 | 技术手段 | 生活类比 |
|----------|----------|----------|
| 机密性 | 加密技术 | 保险箱锁起来 |
| 完整性 | 数字签名、哈希 | 封条防篡改 |
| 身份认证 | 数字证书 | 身份证验证 |
| 不可否认性 | 数字签名 | 签字画押 |

---

## 9.2 加密技术

### 对称加密

**原理**：加密和解密使用相同的密钥

**常见算法**：
- DES（56 位，已不安全）
- 3DES（168 位，较慢）
- AES（128/192/256 位，推荐）

**优势**：速度快，适合大量数据

**缺点**：密钥分发困难

**生活类比**：像**普通锁**，锁和钥匙一样，给别人的时候容易被复制。

### 非对称加密

**原理**：使用一对密钥，公钥加密，私钥解密

**常见算法**：
- RSA（基于大数分解）
- ECC（基于椭圆曲线）
- DSA（数字签名）

**优势**：解决密钥分发问题

**缺点**：速度慢，不适合大量数据

**生活类比**：像**密码箱**：
- 公钥是锁，任何人都可以锁
- 私钥是钥匙，只有主人有
- 用公钥锁上的箱子，只有私钥能打开

### 对称 vs 非对称加密

| 对比项 | 对称加密 | 非对称加密 |
|--------|----------|------------|
| 密钥数量 | 1 个 | 2 个（公钥+私钥） |
| 速度 | 快 | 慢 |
| 安全性 | 密钥分发困难 | 相对安全 |
| 应用场景 | 大量数据加密 | 密钥交换、数字签名 |
| 代表算法 | AES、DES | RSA、ECC |

### 混合加密（实际应用）

**原理**：结合对称和非对称加密的优势

**过程**：

```
1. 使用非对称加密传输对称密钥（会话密钥）
2. 使用对称密钥加密实际数据
3. 后续通信使用对称加密
```

**应用**：HTTPS、SSL/TLS

## 9.3 哈希函数

### 什么是哈希函数？

**定义**：将任意长度的输入转换为固定长度的输出（哈希值）

**特性**：
- 单向性：无法从哈希值反推原始数据
- 确定性：相同输入总是产生相同输出
- 抗碰撞：很难找到两个不同输入产生相同输出
- 雪崩效应：输入微小变化导致输出巨大变化

### 常见哈希算法

| 算法 | 输出长度 | 安全性 | 应用 |
|------|----------|--------|------|
| MD5 | 128 位 | 不安全（已破解） | 文件校验（不推荐） |
| SHA-1 | 160 位 | 不安全（已破解） | 数字证书（不推荐） |
| SHA-256 | 256 位 | 安全 | 数字证书、区块链 |
| SHA-3 | 可变 | 安全 | 新一代标准 |

### 哈希的应用

- **密码存储**：存储密码的哈希值，不存储明文
- **文件校验**：验证文件完整性
- **数字签名**：对消息摘要签名
- **区块链**：工作量证明

---

## 9.4 数字签名

### 什么是数字签名？

**定义**：用私钥对消息摘要加密，用于验证消息来源和完整性

### 数字签名过程

```
发送方：
1. 计算消息的哈希值（摘要）
2. 用私钥加密哈希值，得到数字签名
3. 将消息和签名一起发送

接收方：
1. 用发送方的公钥解密签名，得到哈希值 A
2. 计算接收消息的哈希值 B
3. 比较 A 和 B：
   - 相同：消息未被篡改，来源可信
   - 不同：消息被篡改或来源不可信
```

**生活类比**：像**盖章**：
- 印章是私钥，只有你有
- 盖的章是签名，任何人都能验证
- 章是真的，文件就是真的

## 9.5 数字证书

### 什么是数字证书？

**定义**：由 CA（证书颁发机构）签发的电子文档，包含公钥和身份信息

### 证书内容

```
- 版本号
- 序列号
- 签名算法
- 颁发者（CA）
- 有效期
- 主体（证书持有者）
- 主体公钥
- CA 签名
```

### 证书验证过程

```
1. 浏览器收到服务器证书
2. 检查证书是否由可信 CA 签发
3. 用 CA 的公钥验证证书签名
4. 检查证书是否过期
5. 检查证书域名是否匹配
6. 检查证书是否被吊销（CRL/OCSP）
7. 验证通过，使用证书中的公钥
```

### 证书链

```
根证书（Root CA）
  └── 中间证书（Intermediate CA）
       └── 服务器证书（End Entity）
```

**验证过程**：从服务器证书逐级验证到根证书

## 9.6 防火墙

### 什么是防火墙？

**定义**：位于内部网络和外部网络之间的安全设备，控制网络访问

### 防火墙类型

#### 包过滤防火墙

**工作层级**：网络层

**原理**：根据 IP 地址、端口号、协议类型过滤数据包

**优势**：速度快

**缺点**：无法检测应用层内容

#### 状态检测防火墙

**原理**：跟踪连接状态，只允许合法的数据包通过

**优势**：比包过滤更安全

#### 应用层防火墙（代理防火墙）

**工作层级**：应用层

**原理**：代理内部和外部之间的通信，深度检查应用层内容

**优势**：安全性高

**缺点**：速度慢

### 防火墙规则示例

```
# 允许外部访问 Web 服务器
allow tcp any to 192.168.1.100 port 80
allow tcp any to 192.168.1.100 port 443

# 允许内部访问外部
allow tcp 192.168.1.0/24 to any

# 拒绝其他所有流量
deny ip any to any
```

## 9.7 入侵检测系统（IDS）

### 什么是 IDS？

**定义**：监控网络或系统活动，检测恶意行为

### IDS 类型

#### 基于网络的 IDS（NIDS）

**监控对象**：网络流量

**部署位置**：网络边界

**优势**：监控范围广

#### 基于主机的 IDS（HIDS）

**监控对象**：主机日志、文件变化

**部署位置**：关键服务器

**优势**：检测精度高

### 检测方法

#### 误用检测（签名检测）

**原理**：匹配已知攻击模式

**优势**：准确率高

**缺点**：无法检测未知攻击

#### 异常检测

**原理**：建立正常行为模型，检测偏离行为

**优势**：能检测未知攻击

**缺点**：误报率高

---

## 9.8 常见网络攻击

### DDoS 攻击

**原理**：分布式拒绝服务攻击，大量请求淹没服务器

**防御**：流量清洗、CDN、负载均衡

### SQL 注入

**原理**：在输入中插入 SQL 代码，操纵数据库

**防御**：参数化查询、输入验证、WAF

### XSS 攻击

**原理**：跨站脚本攻击，注入恶意脚本

**防御**：输入过滤、输出编码、CSP

### 中间人攻击

**原理**：攻击者插入通信双方之间，窃听和篡改

**防御**：HTTPS、证书验证

## 9.9 核心知识点总结

| 知识点 | 说明 |
|--------|------|
| 对称加密 | 同一密钥加解密，速度快 |
| 非对称加密 | 公钥加密私钥解密，解决密钥分发 |
| 哈希函数 | 单向、固定长度、抗碰撞 |
| 数字签名 | 私钥签名，公钥验证 |
| 数字证书 | CA 签发，包含公钥和身份 |
| 防火墙 | 包过滤、状态检测、应用代理 |
| IDS | 误用检测、异常检测 |

## 9.10 新手常见误区

### 误区 1："HTTPS 绝对安全"

**错！** HTTPS 提供加密和身份验证，但如果证书被窃取、私钥泄露或存在漏洞，仍然不安全。安全是相对的，需要持续维护。

### 误区 2："防火墙可以防止所有攻击"

不对。防火墙主要控制网络访问，无法防止应用层攻击（如 SQL 注入、XSS）。需要配合 WAF、IDS 等设备。

### 误区 3："密码用 MD5 加密就安全了"

不准确。MD5 已被破解，容易被碰撞和彩虹表攻击。应使用 SHA-256 或 bcrypt、scrypt 等算法，并加盐。

### 误区 4："内网是安全的，不需要防护"

不对。内网也可能被入侵（如员工电脑中毒、内部人员恶意操作）。需要零信任架构，持续验证。

### 练习 2：数字签名验证

假设 Alice 发送消息给 Bob，并使用数字签名。请描述签名和验证的过程。

<details>
<summary>点击查看答案</summary>

```
签名过程（Alice）：
1. Alice 计算消息的哈希值 H1
2. Alice 用自己的私钥加密 H1，得到签名 S
3. Alice 发送消息和签名 S 给 Bob

验证过程（Bob）：
1. Bob 收到消息和签名 S
2. Bob 用 Alice 的公钥解密签名 S，得到哈希值 H2
3. Bob 计算收到消息的哈希值 H3
4. 比较 H2 和 H3：
   - 相同：消息来自 Alice，且未被篡改
   - 不同：消息被篡改或不是 Alice 发送
```

</details>

### 练习 3（挑战）：证书链验证

假设证书链为：根证书 → 中间证书 → 服务器证书。请描述验证过程。

<details>
<summary>点击查看答案</summary>

```
证书链验证过程：

1. 浏览器收到服务器证书
2. 浏览器检查是否有中间证书：
   - 如果没有，从服务器获取
3. 验证服务器证书：
   - 用中间证书的公钥验证服务器证书签名
   - 检查服务器证书有效期
   - 检查服务器证书域名
4. 验证中间证书：
   - 用根证书的公钥验证中间证书签名
   - 检查中间证书有效期
5. 验证根证书：
   - 根证书内置在浏览器/操作系统中
   - 检查根证书是否可信
6. 检查证书吊销状态（CRL/OCSP）
7. 所有验证通过，信任服务器证书
```

</details>
