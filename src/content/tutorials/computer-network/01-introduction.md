# 第1章：计算机网络概述

## 本章导读

在学这一章之前，你可能会有这些疑问：

- 什么是计算机网络？为什么需要学习它？
- OSI 七层模型和 TCP/IP 四层模型有什么区别？
- 网络协议到底是怎么工作的？
- 学完网络基础对我找工作有帮助吗？

这一章就是为了解答这些问题。我们会先搞清楚**网络的基本概念**，再理解**分层模型的设计思想**，最后对比两种主流模型。

---

## 1 为什么需要计算机网络？

### 痛点分析

想象一下，如果没有网络：

- 你想查资料，必须去图书馆翻书
- 你想和朋友聊天，必须打电话或见面
- 公司里的 10 台电脑要共享文件，必须用 U 盘拷贝
- 你想看视频，必须买光盘或下载

这就像**没有快递的年代**，你要寄信给朋友，必须自己开车送过去。

### 解决方案

计算机网络就是**让多台计算机通过通信线路连接起来，实现资源共享和信息传递**。

打个比方：

> 网络就像**城市的交通系统**，计算机是房子，网线/无线是道路，协议是交通规则。有了这套系统，数据（车辆）就能从一台电脑（房子）快速到达另一台电脑（房子）。

### 网络的核心功能

| 功能 | 说明 | 生活例子 |
|------|------|----------|
| 资源共享 | 共享文件、打印机、数据库 | 公司共享打印机 |
| 信息传递 | 发邮件、即时通讯 | 微信聊天 |
| 分布式处理 | 多台机器协同完成任务 | 云计算 |
| 提高可靠性 | 数据备份、冗余存储 | 网盘多副本 |

## 2 网络的发展历程

### 阶段一：面向终端的网络（1960s）

- 一台大型主机 + 多个终端
- 终端没有独立处理能力
- 像**老师讲课，学生只能听**

### 阶段二：分组交换网络（1970s）

- ARPANET 诞生，互联网雏形
- 数据被切分成"包"传输
- 像**快递分拣，包裹可以走不同路线**

### 阶段三：网络互连（1980s）

- TCP/IP 协议标准化
- 不同网络可以互相连接
- 像**不同城市的公路网连在一起**

### 阶段四：信息高速公路（1990s-至今）

- WWW 万维网普及
- 移动互联网、物联网
- 像**从单车道变成高速公路，再到高铁网络**

## 3 网络分层模型

### 为什么需要分层？

网络通信非常复杂，如果所有功能都混在一起，维护和调试都是噩梦。

打个比方：

> 分层就像**公司组织架构**：CEO 只管战略，经理管部门，员工管具体执行。每层只关心自己的事，不用操心其他层的细节。

### OSI 七层模型

OSI（Open System Interconnection）是国际标准化组织提出的理论模型：

```
第7层：应用层    → 为用户提供服务（HTTP、FTP、SMTP）
第6层：表示层    → 数据格式转换、加密（JPEG、ASCII）
第5层：会话层    → 建立、管理、终止会话（RPC、SQL）
第4层：传输层    → 端到端可靠传输（TCP、UDP）
第3层：网络层    → 路由选择、逻辑寻址（IP）
第2层：数据链路层 → 帧传输、物理寻址（以太网、WiFi）
第1层：物理层    → 比特流传输（网线、光纤）
```

记忆口诀：**"应表会传网数物"**（从上到下）

### TCP/IP 四层模型

TCP/IP 是实际使用的模型，更简洁实用：

```
第4层：应用层      → 对应 OSI 的应用+表示+会话层
第3层：传输层      → 对应 OSI 的传输层
第2层：网际层      → 对应 OSI 的网络层
第1层：网络接口层  → 对应 OSI 的数据链路+物理层
```

### 五层模型（教学常用）

结合了理论性和实用性：

```
第5层：应用层
第4层：传输层
第3层：网络层
第2层：数据链路层
第1层：物理层
```

## 4 各层功能详解

### 应用层

**做什么**：直接为用户服务

**协议举例**：
- HTTP：浏览网页
- SMTP：发邮件
- FTP：文件传输
- DNS：域名解析

**生活类比**：像**餐厅的服务员**，直接面对顾客，接收点单。

### 传输层

**做什么**：提供端到端的可靠传输

**核心协议**：
- TCP：可靠、面向连接
- UDP：不可靠、无连接、速度快

**生活类比**：像**快递公司**，TCP 是顺丰（保证送达），UDP 是平邮（不保证）。

### 网络层

**做什么**：路由选择，找到最佳路径

**核心协议**：IP、ICMP、ARP

**生活类比**：像**导航软件**，帮你规划从 A 到 B 的最佳路线。

### 数据链路层

**做什么**：在相邻节点间可靠传输帧

**核心功能**：
- 成帧：把比特流分成帧
- MAC 寻址：物理地址
- 差错检测：CRC 校验

**生活类比**：像**快递分拣中心**，把包裹按地址分类。

### 物理层

**做什么**：传输比特流（0 和 1）

**传输介质**：
- 有线：双绞线、光纤、同轴电缆
- 无线：WiFi、蓝牙、4G/5G

**生活类比**：像**公路本身**，只负责让车能跑，不管车里装什么。

## 5 数据封装与解封装

### 封装过程

当数据从应用层传到物理层时，每层都会加上自己的"头部"：

```
应用层：数据 → [应用层头部 + 数据]
传输层：    → [传输层头部 + 应用层头部 + 数据]
网络层：    → [网络层头部 + 传输层头部 + 应用层头部 + 数据]
数据链路层：→ [链路层头部 + 网络层头部 + ... + 数据 + 链路层尾部]
物理层：    → 转换成比特流传输
```

**生活类比**：

> 像**寄快递**：你把礼物（数据）装进盒子（应用层），再装进快递袋（传输层），再贴上地址标签（网络层），最后快递员贴上运单（链路层）。

### 解封装过程

接收方收到数据后，从物理层往上，每层去掉对应的头部：

```
物理层：接收比特流
数据链路层：去掉链路层头部和尾部
网络层：去掉网络层头部
传输层：去掉传输层头部
应用层：去掉应用层头部，得到原始数据
```

## 6 核心知识点总结

| 知识点 | 说明 |
|--------|------|
| 网络定义 | 多台计算机通过通信线路连接，实现资源共享 |
| OSI 七层 | 应用、表示、会话、传输、网络、数据链路、物理 |
| TCP/IP 四层 | 应用、传输、网际、网络接口 |
| 五层模型 | 应用、传输、网络、数据链路、物理 |
| 封装 | 数据从上到下，每层加头部 |
| 解封装 | 数据从下到上，每层去头部 |

## 7 新手常见误区

### 误区 1："OSI 模型在实际网络中广泛使用"

**错！** OSI 只是理论模型，实际用的是 TCP/IP 模型。OSI 的价值在于提供了一个标准框架，帮助理解网络分层思想。

### 误区 2："每层都是独立工作的，互不影响"

不是的。每层依赖下层提供的服务，同时为上层提供服务。就像公司里，员工的工作依赖同事，同时为经理提供支持。

### 误区 3："TCP/IP 只有四层，没有物理层"

不准确。TCP/IP 的网络接口层包含了数据链路层和物理层的功能，只是没有明确区分。

### 误区 4："数据封装只是简单加头部"

不对。每层封装都有特定格式，包含控制信息（如源地址、目的地址、校验和等），不是随便加的。

### 练习 2：对比分析

对比 OSI 七层模型和 TCP/IP 四层模型的异同。

<details>
<summary>点击查看答案</summary>

```
相同点：
- 都采用分层思想
- 都能实现网络通信
- 都有应用层、传输层、网络层

不同点：
- OSI 是理论模型，TCP/IP 是实际标准
- OSI 有 7 层，TCP/IP 有 4 层
- OSI 先有模型后有协议，TCP/IP 先有协议后有模型
- OSI 支持无连接和面向连接，TCP/IP 只支持无连接（网络层）
```

</details>

### 练习 3（挑战）：数据封装

假设你在浏览器输入 `www.example.com`，请描述数据从应用层到物理层的封装过程。

<details>
<summary>点击查看答案</summary>

```
1. 应用层：浏览器生成 HTTP 请求报文
   → [HTTP 头部 + 请求数据]

2. 传输层：TCP 添加头部（源端口、目的端口、序列号等）
   → [TCP 头部 + HTTP 报文]

3. 网络层：IP 添加头部（源 IP、目的 IP、TTL 等）
   → [IP 头部 + TCP 报文]

4. 数据链路层：以太网添加头部（源 MAC、目的 MAC）和尾部（FCS 校验）
   → [以太网头部 + IP 数据报 + FCS]

5. 物理层：转换成电信号/光信号，通过网线/光纤传输
```

</details>
