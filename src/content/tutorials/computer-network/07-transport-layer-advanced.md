# 第7章：传输层进阶

## 本章导读

在学这一章之前，你可能会有这些疑问：

- TCP 是怎么保证数据可靠传输的？
- 什么是拥塞控制？为什么需要它？
- 流量控制和拥塞控制有什么区别？
- TCP 的滑动窗口是怎么工作的？

这一章就是为了解答这些问题。我们会先搞清楚**TCP 的可靠传输机制**，再学习**流量控制和拥塞控制的原理**，最后理解**TCP 的性能优化策略**。

---

## 7.1 为什么需要拥塞控制？

### 痛点分析

如果没有拥塞控制：

- 多个发送方同时发送大量数据，路由器缓存溢出
- 数据包大量丢失，网络性能急剧下降
- 严重时导致"拥塞崩溃"，网络几乎无法工作
- 就像**多条高速公路汇入同一条路**，没有红绿灯就会大堵车

### 解决方案

TCP 拥塞控制通过**动态调整发送速率**，避免网络过载。

打个比方：

> 拥塞控制就像**智能导航**，发现前方堵车就减速或绕路，避免所有车都挤在同一条路上。

---

## 7.2 TCP 可靠传输机制

### 序号与确认号

**序号（Sequence Number）**：每个字节都有一个序号，用于排序

**确认号（Acknowledgment Number）**：期望收到的下一个字节序号

**例子**：

```
发送方发送数据：seq=1000，数据长度 500 字节
接收方回复：ack=1500（表示 1000-1499 的字节都已收到）
```

### 超时重传

**原理**：

```
1. 发送方发送数据，启动定时器
2. 如果在超时时间内收到确认，取消定时器
3. 如果超时未收到确认，重传数据
```

**超时时间计算**：

```
RTT（往返时间）的动态估计：
EstimatedRTT = (1 - α) × EstimatedRTT + α × SampleRTT
其中 α = 0.125

超时时间 = EstimatedRTT + 4 × RTTDeviation
```

### 快速重传

**原理**：收到 3 个重复确认，立即重传，不等超时

**过程**：

```
发送方发送：包1、包2、包3、包4
接收方收到：包1、包3、包4（包2丢失）

接收方回复：
- 收到包1：ack=包1结束位置
- 收到包3：ack=包1结束位置（重复确认1）
- 收到包4：ack=包1结束位置（重复确认2）
- 收到包5：ack=包1结束位置（重复确认3）

发送方收到 3 个重复确认，立即重传包2
```

**优势**：比等待超时更快恢复

## 7.3 流量控制

### 为什么需要流量控制？

如果发送方发得太快，接收方来不及处理，会导致缓冲区溢出，数据丢失。

### 滑动窗口机制

**原理**：

```
发送窗口：
┌─────────────────────────────────────┐
│ 已发送未确认 │ 可以发送 │ 不能发送  │
└─────────────────────────────────────┘

接收窗口：
┌─────────────────────────────────────┐
│ 已接收未读取 │ 可以接收 │ 不能接收  │
└─────────────────────────────────────┘
```

**窗口大小**：由接收方在 TCP 头部的"窗口大小"字段告知发送方

**动态调整**：

```
接收方缓冲区满：窗口大小 = 0，发送方暂停发送
接收方缓冲区空：窗口大小 = 缓冲区大小，发送方可以全速发送
```

### 零窗口与窗口探测

**零窗口**：接收方缓冲区满，窗口大小为 0

**窗口探测**：发送方定期发送探测报文，询问窗口大小

**紧急数据**：即使零窗口，也可以发送紧急数据

## 7.4 拥塞控制

### 拥塞控制算法

TCP 拥塞控制包含四个算法：慢开始、拥塞避免、快重传、快恢复。

### 慢开始（Slow Start）

**原理**：

```
初始：cwnd = 1 MSS（拥塞窗口大小）
每收到一个确认：cwnd = cwnd + 1
效果：每经过一个 RTT，cwnd 翻倍（指数增长）

第1轮：发送1个，收到确认，cwnd=2
第2轮：发送2个，收到确认，cwnd=4
第3轮：发送4个，收到确认，cwnd=8
...
```

**阈值**：当 cwnd 达到 ssthresh 时，切换到拥塞避免

**生活类比**：像**开车起步**，先慢慢加速，试探路况。

### 拥塞避免（Congestion Avoidance）

**原理**：

```
每经过一个 RTT：cwnd = cwnd + 1
效果：线性增长，每个 RTT 增加 1 MSS

第1轮：cwnd=10，发送10个
第2轮：cwnd=11，发送11个
第3轮：cwnd=12，发送12个
...
```

**生活类比**：像**在高速公路上匀速行驶**，慢慢增加车流量。

### 快重传（Fast Retransmit）

**原理**：收到 3 个重复确认，立即重传丢失的报文

**触发条件**：

```
发送方收到 ack=1000（重复确认1）
发送方收到 ack=1000（重复确认2）
发送方收到 ack=1000（重复确认3）
→ 立即重传 seq=1000 开始的报文
```

### 快恢复（Fast Recovery）

**原理**：

```
收到 3 个重复确认时：
1. ssthresh = cwnd / 2
2. cwnd = ssthresh + 3
3. 重传丢失的报文
4. 收到确认后，cwnd = ssthresh，进入拥塞避免
```

**优势**：避免因为单个报文丢失而回到慢开始

### 拥塞控制完整流程

```
cwnd
 │
 │        /\
 │       /  \      /\
 │      /    \    /  \
 │     /      \  /    \
 │    /        \/      \
 │   /         慢开始   \
 │  / 慢开始   拥塞避免  \
 │ /                     \
 └─────────────────────────── RTT
         ↑           ↑
      丢包检测     3个重复确认
      cwnd=1       cwnd/2
```

## 7.5 TCP 性能优化

### 窗口缩放（Window Scaling）

**问题**：TCP 头部窗口大小字段只有 16 位，最大窗口 64 KB

**解决**：使用窗口缩放选项，将窗口大小左移 N 位

```
实际窗口大小 = 头部窗口值 × 2^N
N 最大为 14，最大窗口可达 1 GB
```

### 选择性确认（SACK）

**问题**：传统 TCP 只确认连续接收的数据，丢失一个报文会导致后续报文重传

**解决**：SACK 允许接收方告知哪些报文段已成功接收

```
传统确认：收到 1、3、4、5 → ack=2（只确认到2）
SACK：收到 1、3、4、5 → ack=2，SACK=3-5（告知3-5已收到）
```

**优势**：发送方只需重传报文 2，不用重传 3、4、5

### 时间戳（Timestamps）

**作用**：
- 更精确地计算 RTT
- 防止序号回绕（PAWS）

### Nagle 算法

**问题**：小数据频繁发送，效率低

**解决**：积累小数据，凑够一定量再发送

**延迟确认**：接收方不立即确认，等待一段时间，看是否有数据要发送，一起确认

## 7.6 核心知识点总结

| 知识点 | 说明 |
|--------|------|
| 序号与确认号 | 用于排序和确认接收 |
| 超时重传 | 定时器超时未确认则重传 |
| 快速重传 | 3 个重复确认立即重传 |
| 滑动窗口 | 流量控制，允许连续发送 |
| 慢开始 | 指数增长拥塞窗口 |
| 拥塞避免 | 线性增长拥塞窗口 |
| 快恢复 | 丢包后不回到慢开始 |
| SACK | 选择性确认，减少重传 |

## 7.7 新手常见误区

### 误区 1："流量控制就是拥塞控制"

**错！** 流量控制是端到端的，防止接收方过载；拥塞控制是全局的，防止网络过载。流量控制由接收窗口决定，拥塞控制由拥塞窗口决定。

### 误区 2："慢开始是慢速传输"

不对。慢开始是指初始窗口小，指数增长，实际上很快就会达到较大窗口。名字容易误解，实际是"慢慢启动，快速加速"。

### 误区 3："TCP 丢包后总是回到慢开始"

不准确。如果是超时丢包，回到慢开始；如果是 3 个重复确认，使用快恢复，cwnd 减半后进入拥塞避免。

### 误区 4："窗口越大越好"

不对。窗口太大会导致缓冲区溢出，增加延迟；太小会限制吞吐量。需要根据网络状况动态调整。

## 7.8 动手练习

### 练习 1：流量控制

假设接收方缓冲区大小为 64 KB，当前已接收但未读取的数据为 20 KB。请问发送方的发送窗口大小是多少？

<details>
<summary>点击查看答案</summary>

```
接收窗口大小 = 缓冲区大小 - 已接收未读取数据
接收窗口大小 = 64 KB - 20 KB = 44 KB

发送方的发送窗口大小 = 接收窗口大小 = 44 KB

这意味着发送方最多可以发送 44 KB 的数据，
直到接收方读取数据并更新窗口大小。
```

</details>

### 练习 2：拥塞控制分析

假设当前 cwnd = 16，ssthresh = 8。发生超时丢包后，请计算接下来的 cwnd 变化。

<details>
<summary>点击查看答案</summary>

```
超时丢包处理：
1. ssthresh = cwnd / 2 = 16 / 2 = 8
2. cwnd = 1（回到慢开始）

接下来的变化：
- 第1轮：cwnd=1（慢开始）
- 第2轮：cwnd=2（慢开始）
- 第3轮：cwnd=4（慢开始）
- 第4轮：cwnd=8（达到 ssthresh，切换到拥塞避免）
- 第5轮：cwnd=9（拥塞避免，线性增长）
- 第6轮：cwnd=10
- ...
```

</details>

### 练习 3（挑战）：TCP 性能分析

假设 RTT = 100 ms，MSS = 1 KB，窗口大小不受限制。请计算从 cwnd=1 开始，经过 5 个 RTT 后，总共发送了多少数据？

<details>
<summary>点击查看答案</summary>

```
慢开始阶段（cwnd 指数增长）：

第1个 RTT：
- 发送：1 MSS = 1 KB
- 结束时：cwnd = 2

第2个 RTT：
- 发送：2 MSS = 2 KB
- 结束时：cwnd = 4

第3个 RTT：
- 发送：4 MSS = 4 KB
- 结束时：cwnd = 8

第4个 RTT：
- 发送：8 MSS = 8 KB
- 结束时：cwnd = 16

第5个 RTT：
- 发送：16 MSS = 16 KB
- 结束时：cwnd = 32

总共发送：1 + 2 + 4 + 8 + 16 = 31 KB
```

</details>
