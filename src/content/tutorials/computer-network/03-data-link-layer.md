# 第3章：数据链路层

## 本章导读

在学这一章之前，你可能会有这些疑问：

- 数据链路层到底是做什么的？
- MAC 地址和 IP 地址有什么区别？
- 交换机是怎么工作的？和集线器有什么不同？
- 为什么需要 ARP 协议？

这一章就是为了解答这些问题。我们会先搞清楚**数据链路层的核心功能**，再学习**MAC 地址和以太网帧结构**，最后理解**交换机的工作原理**。

---

## 1 为什么需要数据链路层？

### 痛点分析

如果没有数据链路层：

- 物理层只负责传输比特流，无法区分数据边界
- 无法检测传输过程中的错误
- 多台设备共享网络时会产生冲突
- 就像**公路上没有交通规则**，车辆会乱撞

### 解决方案

数据链路层负责**在相邻节点间可靠地传输数据帧**。

打个比方：

> 数据链路层就像**快递分拣中心**，把比特流打包成一个个"包裹"（帧），贴上地址标签（MAC 地址），确保包裹能准确送到下一个节点。

### 数据链路层的核心功能

| 功能 | 说明 | 生活例子 |
|------|------|----------|
| 成帧 | 把比特流分成帧 | 把散货装进集装箱 |
| 物理寻址 | 使用 MAC 地址标识设备 | 快递单上的地址 |
| 差错检测 | 检测传输错误 | 检查包裹是否损坏 |
| 流量控制 | 控制发送速率 | 控制水龙头出水量 |
| 介质访问控制 | 协调多设备共享介质 | 红绿灯控制交通 |

## 2 成帧与封装

### 什么是帧？

**定义**：数据链路层的数据单元，包含头部、数据和尾部

### 以太网帧结构

```
┌─────────────┬─────────────┬──────────┬──────────────┬─────────┬──────────┐
│ 前导码(8B)  │ 目的MAC(6B) │ 源MAC(6B)│ 类型/长度(2B)│ 数据    │ FCS(4B) │
│ 同步时钟    │ 接收方地址   │ 发送方地址│ 标识上层协议 │ 46-1500B│ 校验和  │
└─────────────┴─────────────┴──────────┴──────────────┴─────────┴──────────┘
```

**各字段说明**：

| 字段 | 长度 | 作用 |
|------|------|------|
| 前导码 | 8 字节 | 同步时钟，提醒接收方准备接收 |
| 目的 MAC | 6 字节 | 接收方的物理地址 |
| 源 MAC | 6 字节 | 发送方的物理地址 |
| 类型 | 2 字节 | 标识上层协议（0x0800=IP，0x0806=ARP） |
| 数据 | 46-1500 字节 | 上层传来的数据 |
| FCS | 4 字节 | CRC 校验，检测传输错误 |

**生活类比**：

> 帧就像**快递包裹**：前导码是"请注意"，目的 MAC 是收件地址，源 MAC 是寄件地址，类型是"里面装的是什么"，数据是实际物品，FCS 是"包裹完好无损"的封条。

### 最小帧长

**为什么有最小帧长**：确保发送方在发送完帧之前能检测到冲突

**以太网最小帧长**：64 字节（不含前导码）

## 3 MAC 地址

### 什么是 MAC 地址？

**定义**：媒体访问控制地址，是网卡的物理地址

**长度**：48 位（6 字节）

**表示方式**：十六进制，如 `00:1A:2B:3C:4D:5E`

### MAC 地址结构

```
┌──────────────────┬──────────────────┐
│ 前24位（OUI）    │ 后24位（序列号） │
│ 厂商标识         │ 厂商分配         │
└──────────────────┴──────────────────┘
```

**生活类比**：

> MAC 地址就像**身份证号**，前 24 位是"出生地"（厂商），后 24 位是"个人编号"（序列号），全球唯一。

### MAC 地址分类

| 类型 | 说明 | 例子 |
|------|------|------|
| 单播地址 | 标识单个设备 | 00:1A:2B:3C:4D:5E |
| 组播地址 | 标识一组设备 | 01:00:5E:00:00:01 |
| 广播地址 | 标识所有设备 | FF:FF:FF:FF:FF:FF |

### MAC 地址 vs IP 地址

| 对比项 | MAC 地址 | IP 地址 |
|--------|----------|---------|
| 层级 | 数据链路层 | 网络层 |
| 长度 | 48 位 | 32 位（IPv4）或 128 位（IPv6） |
| 可变性 | 固化在网卡，不可变 | 可动态分配，可变 |
| 作用范围 | 局域网内 | 全球互联网 |
| 类比 | 身份证号 | 邮寄地址 |

## 4 以太网技术

### 什么是以太网？

**定义**：最常见的局域网（LAN）技术标准

**标准**：IEEE 802.3

**速率**：10 Mbps → 100 Mbps → 1 Gbps → 10 Gbps

### 以太网工作原理

```
设备 A 要发送数据给设备 B：
1. 设备 A 监听信道是否空闲
2. 空闲则发送数据帧
3. 所有设备都能收到帧
4. 只有目的地址匹配的设备 B 接收并处理
5. 其他设备丢弃该帧
```

### 集线器（Hub）

**工作层级**：物理层

**工作原理**：把收到的信号广播到所有端口

**缺点**：
- 所有设备共享带宽
- 容易产生冲突
- 安全性差

**生活类比**：像**大喇叭广播**，一个人说话，所有人都能听到。

### 交换机（Switch）

**工作层级**：数据链路层

**工作原理**：
1. 学习：记录 MAC 地址与端口的对应关系
2. 转发：根据目的 MAC 地址转发到对应端口
3. 过滤：如果目的 MAC 在同一端口，不转发
4. 泛洪：如果目的 MAC 未知，广播到所有端口

**优势**：
- 每个端口独享带宽
- 减少冲突
- 提高安全性

**生活类比**：像**快递分拣员**，知道每个包裹该送到哪个房间，不会到处乱发。

### 交换机 vs 集线器

| 对比项 | 集线器 | 交换机 |
|--------|--------|--------|
| 工作层级 | 物理层 | 数据链路层 |
| 转发方式 | 广播 | 点对点 |
| 带宽 | 共享 | 独享 |
| 冲突 | 有 | 无 |
| 安全性 | 低 | 高 |
| 价格 | 便宜 | 较贵 |

## 5 差错检测

### 为什么需要差错检测？

物理层传输比特流时，可能因为干扰导致比特翻转（0 变 1，1 变 0）。数据链路层需要检测这些错误。

### CRC 循环冗余校验

**原理**：
1. 发送方：用生成多项式对数据进行除法运算，得到余数
2. 把余数附加在数据后面
3. 接收方：用同样的生成多项式对接收数据做除法
4. 如果余数为 0，说明传输正确；否则有错误

**生活类比**：像**银行校验码**，转账时会根据账号生成一个校验码，确保账号没输错。

### 校验和

**原理**：把数据分成若干段，求和后取反

**应用**：IP、TCP、UDP 头部

**缺点**：检测能力不如 CRC

## 6 流量控制

### 为什么需要流量控制？

如果发送方发得太快，接收方来不及处理，会导致数据丢失。

### 停止-等待协议

**原理**：
1. 发送方发送一帧后停止，等待确认
2. 接收方收到帧后发送 ACK
3. 发送方收到 ACK 后发送下一帧

**缺点**：效率低，信道利用率差

**生活类比**：像**打电话**，你说一句，等对方回应，再说下一句。

### 滑动窗口协议

**原理**：
1. 发送方可以连续发送多个帧，不需要等待确认
2. 窗口大小决定了一次能发多少帧
3. 收到确认后，窗口向前滑动

**优势**：大幅提高信道利用率

**生活类比**：像**发微信**，你可以连续发好几条消息，不用等对方回复每一条。

## 7 核心知识点总结

| 知识点 | 说明 |
|--------|------|
| 成帧 | 把比特流分成帧，添加头部和尾部 |
| MAC 地址 | 48 位物理地址，全球唯一 |
| 以太网帧 | 目的 MAC + 源 MAC + 类型 + 数据 + FCS |
| 交换机 | 根据 MAC 地址转发帧，独享带宽 |
| CRC | 循环冗余校验，检测传输错误 |
| 滑动窗口 | 允许连续发送多帧，提高利用率 |

## 8 新手常见误区

### 误区 1："MAC 地址可以随意修改"

**错！** MAC 地址固化在网卡的 ROM 中，虽然可以通过软件修改（MAC 地址伪装），但硬件地址是唯一的。

### 误区 2："交换机和集线器是一样的"

不是的。交换机工作在数据链路层，能识别 MAC 地址，点对点转发；集线器工作在物理层，只是简单广播，所有设备共享带宽。

### 误区 3："MAC 地址可以跨网络传输"

不对。MAC 地址只在局域网内有效，跨网络传输时需要路由器，路由器会重新封装帧，MAC 地址会改变。

### 误区 4："数据链路层保证可靠传输"

不准确。数据链路层只负责相邻节点间的传输，不保证端到端的可靠性。可靠传输由传输层（TCP）负责。

## 9 动手练习

### 练习 1：基础概念

请说明 MAC 地址的结构，并解释为什么 MAC 地址是全球唯一的。

<details>
<summary>点击查看答案</summary>

```
MAC 地址结构：
- 总长度：48 位（6 字节）
- 前 24 位（OUI）：厂商标识，由 IEEE 统一分配
- 后 24 位：厂商分配的序列号

为什么全球唯一：
- IEEE 负责分配 OUI，确保不同厂商的 OUI 不同
- 厂商保证自己生产的网卡序列号不重复
- 因此，全球任何两块网卡的 MAC 地址都不同
```

</details>

### 练习 2：交换机工作原理

假设交换机连接了 4 台设备（A、B、C、D），分别连接在端口 1、2、3、4。当 A 发送数据帧给 B 时，交换机会如何处理？

<details>
<summary>点击查看答案</summary>

```
处理过程：
1. 交换机从端口 1 收到数据帧
2. 读取帧的目的 MAC 地址
3. 查找 MAC 地址表，发现 B 的 MAC 地址对应端口 2
4. 将帧从端口 2 转发给 B
5. 端口 3、4 的设备不会收到该帧

如果 MAC 地址表中没有 B 的记录：
- 交换机会将帧泛洪（广播）到所有端口（除了端口 1）
- B 收到后会响应，交换机学习到 B 的 MAC 地址与端口 2 的对应关系
```

</details>

### 练习 3（挑战）：帧结构分析

<details>
<summary>点击查看答案</summary>

```
封装过程：
1. 应用层：生成 HTTP 请求报文
2. 传输层：添加 TCP 头部（源端口、目的端口 80、序列号等）
3. 网络层：添加 IP 头部（源 IP、目的 IP、TTL 等）
4. 数据链路层：添加以太网头部和尾部

最终帧结构：
┌─────────┬─────────┬─────────┬──────┬──────────────────────────┬─────┐
│ 前导码  │ 目的MAC │ 源MAC   │ 类型 │ IP头部+TCP头部+HTTP数据  │ FCS │

```

</details>
