# 第15章：网络故障排查

## 本章导读

在学这一章之前，你可能会有这些疑问：

- 网络出问题了，应该从哪里开始排查？
- 常见的网络故障有哪些？
- 如何快速定位问题所在？
- 有什么工具可以帮助排查？

这一章就是为了解答这些问题。我们会先建立**系统化的排查思路**，再学习**常见故障的诊断方法**，最后掌握**实用的排查工具和技巧**。

---

## 1 为什么需要故障排查？

### 痛点分析

网络故障的常见表现：

- 网页打不开，但能 ping 通
- 网络时断时续，不稳定
- 某些应用无法连接
- 网速突然变慢
- 就像**人生病了**，需要找病因、对症治疗

### 解决方案

故障排查的核心思路：

| 步骤 | 说明 | 目标 |
|------|------|------|
| 收集信息 | 了解故障现象和影响范围 | 明确问题 |
| 分析问题 | 根据现象推测可能原因 | 缩小范围 |
| 验证假设 | 通过测试验证推测 | 确认原因 |
| 解决问题 | 修复故障 | 恢复服务 |
| 总结经验 | 记录问题和解决方案 | 避免重复 |

## 2 系统化排查方法

### 分层排查法

从底层到高层逐步排查：

```
第1层：物理层
  - 网线是否插好？
  - 网卡指示灯是否亮？
  - 交换机/路由器是否通电？

第2层：数据链路层
  - MAC 地址是否正常？
  - 是否有 ARP 冲突？
  - 交换机端口是否正常？

第3层：网络层
  - IP 配置是否正确？
  - 路由是否正常？
  - 防火墙是否阻止？

第4层：传输层
  - 端口是否监听？
  - 连接是否建立？
  - 是否有丢包？

第5-7层：应用层
  - DNS 解析是否正常？
  - 服务是否运行？
  - 应用配置是否正确？
```

### 分段排查法

将网络分成多个段，逐段排查：

```
客户端 → [本地网络] → [接入网络] → [骨干网络] → [目标网络] → 服务器

排查步骤：
1. 测试本地网络：ping 网关
2. 测试接入网络：ping 运营商 DNS
3. 测试骨干网络：ping 公网 IP
4. 测试目标网络：ping 目标服务器
5. 测试应用层：访问目标服务
```

### 对比排查法

对比正常和异常情况：

```
正常情况：
- 能访问 A 网站
- 不能访问 B 网站

对比分析：
- A 和 B 的 IP 不同
- A 和 B 的 DNS 解析不同
- A 和 B 的路由路径不同

通过对比找出差异点
```

## 3 常见故障诊断

### 故障 1：无法上网

**现象**：所有网站都打不开

**排查步骤**：

```bash
# 1. 检查物理连接
# 查看网卡状态
ifconfig eth0  # Linux
ipconfig       # Windows

# 2. 检查 IP 配置
# 是否有 IP 地址
ifconfig eth0
# 是否有默认网关
route -n

# 3. 测试本地网络
ping 192.168.1.1  # 网关

# 4. 测试 DNS
ping 8.8.8.8      # 公网 DNS
nslookup www.baidu.com

# 5. 测试路由
traceroute www.baidu.com

# 6. 检查防火墙
sudo iptables -L -n
```

**可能原因及解决**：

| 原因 | 现象 | 解决方法 |
|------|------|----------|
| 网线未插 | 网卡灯不亮 | 插好网线 |
| IP 配置错误 | 无 IP 或 169.254.x.x | 重新获取 IP |
| 网关不可达 | ping 网关不通 | 检查路由器 |
| DNS 故障 | ping 通 IP 但打不开网页 | 更换 DNS |
| 防火墙阻止 | 特定端口不通 | 调整规则 |

### 故障 2：网速慢

**现象**：网页加载慢，视频卡顿

**排查步骤**：

```bash
# 1. 测试延迟和丢包
ping -c 100 www.baidu.com

# 2. 测试带宽
iperf3 -c server_ip

# 3. 查看连接数
netstat -s | grep -i "connection"

# 4. 查看流量
iftop -i eth0  # 实时流量监控
nload -i eth0  # 带宽监控

# 5. 抓包分析
sudo tcpdump -i eth0 -w slow.pcap
# 用 Wireshark 分析
```

**可能原因及解决**：

| 原因 | 现象 | 解决方法 |
|------|------|----------|
| 带宽不足 | 高峰期慢 | 升级带宽 |
| 网络拥塞 | 丢包率高 | 避开高峰或 QoS |
| 设备性能 | CPU/内存高 | 升级设备 |
| 病毒/木马 | 异常流量 | 杀毒 |
| 服务器问题 | 特定网站慢 | 联系服务商 |

### 故障 3：特定服务无法访问

**现象**：能上网，但某个应用无法使用

**排查步骤**：

```bash
# 1. 确认服务地址
nslookup service.example.com

# 2. 测试端口连通性
telnet service.example.com 80
# 或
nc -zv service.example.com 80

# 3. 测试协议
curl -I http://service.example.com

# 4. 抓包分析
sudo tcpdump -i any host service.example.com

# 5. 检查本地配置
# hosts 文件
cat /etc/hosts
# 代理设置
env | grep -i proxy
```

**可能原因及解决**：

| 原因 | 现象 | 解决方法 |
|------|------|----------|
| DNS 解析失败 | 域名无法解析 | 检查 DNS |
| 端口被封 | telnet 不通 | 联系网络管理员 |
| 协议不匹配 | curl 报错 | 检查协议版本 |
| 认证失败 | 401/403 错误 | 检查账号密码 |
| 服务宕机 | 连接超时 | 联系服务商 |

### 故障 4：网络时断时续

**现象**：网络不稳定，时好时坏

**排查步骤**：

```bash
# 1. 持续 ping 测试
ping -i 0.2 www.baidu.com > ping.log &

# 2. 监控网络接口
watch -n 1 ifconfig eth0

# 3. 查看系统日志
tail -f /var/log/syslog | grep -i network

# 4. 检查硬件
# 网线是否松动
# 交换机端口是否正常
# 无线信号强度

# 5. 抓包分析
sudo tcpdump -i eth0 -w unstable.pcap
```

**可能原因及解决**：

| 原因 | 现象 | 解决方法 |
|------|------|----------|
| 网线接触不良 | 时断时续 | 更换网线 |
| 交换机故障 | 多设备受影响 | 更换交换机 |
| 无线干扰 | WiFi 不稳定 | 更换信道 |
| IP 冲突 | 偶尔断网 | 检查 IP 分配 |
| 驱动问题 | 系统日志报错 | 更新驱动 |

## 4 高级排查工具

### mtr 命令

**作用**：结合 ping 和 traceroute，持续监控路由

**用法**：

```bash
# 基本用法
mtr www.baidu.com

# 报告模式
mtr -r www.baidu.com

# 指定次数
mtr -c 100 www.baidu.com

# 显示详细信息
mtr -b www.baidu.com
```

**输出分析**：

```
Host              Loss%  Snt  Last  Avg  Best  Wrst StDev
1. 192.168.1.1     0.0%   10    1.2   1.3   1.1   1.5   0.1
2. 10.0.0.1        0.0%   10    5.6   5.8   5.5   6.2   0.2
3. 222.186.15.1    2.0%   10   10.5  10.8  10.3  12.5   0.5
```

**关键指标**：
- **Loss%**：丢包率
- **StDev**：延迟标准差，越小越稳定

### hping3 命令

**作用**：高级网络测试工具，支持多种协议

**用法**：

```bash
# TCP SYN 扫描
hping3 -S -p 80 www.baidu.com

# TCP ACK 扫描（测试防火墙）
hping3 -A -p 80 www.baidu.com

# UDP 测试
hping3 --udp -p 53 www.baidu.com

# 洪水测试（压力测试）
hping3 -S -p 80 --flood www.baidu.com

# 指定速率
hping3 -S -p 80 -i u10000 www.baidu.com  # 每 10ms 一个包
```

### nmap 命令

**作用**：网络扫描和探测工具

**用法**：

```bash
# 主机发现
nmap -sn 192.168.1.0/24

# 端口扫描
nmap 192.168.1.100

# 服务版本探测
nmap -sV 192.168.1.100

# 操作系统探测
nmap -O 192.168.1.100

# 综合扫描
nmap -A 192.168.1.100

# 快速扫描
nmap -F 192.168.1.100
```

**输出示例**：

```
PORT     STATE SERVICE VERSION
22/tcp   open  ssh     OpenSSH 7.6
80/tcp   open  http    Apache 2.4.29
443/tcp  open  ssl     OpenSSL 1.1.1
3306/tcp open  mysql   MySQL 5.7.32
```

## 5 故障排查实战案例

### 案例 1：网站访问慢

**问题描述**：用户反馈访问公司网站很慢

**排查过程**：

```bash
# 1. 测试延迟
ping www.company.com
# 结果：延迟 200ms，丢包率 5%

# 2. 追踪路由
traceroute www.company.com
# 结果：在第 8 跳延迟突然增加

# 3. 分析
# 第 8 跳是运营商骨干网
# 可能存在拥塞

# 4. 解决方案
# - 联系运营商优化路由
# - 使用 CDN 加速
# - 部署多线路接入
```

### 案例 2：VPN 连接失败

**问题描述**：远程员工无法连接 VPN

**排查过程**：

```bash
# 1. 测试基础网络
ping vpn.company.com
# 结果：能 ping 通

# 2. 测试端口
nc -zv vpn.company.com 1194
# 结果：连接超时

# 3. 检查防火墙
# 发现 UDP 1194 端口被阻止

# 4. 解决方案
# - 在防火墙上开放 UDP 1194
# - 或改用 TCP 443 端口
```

### 案例 3：DNS 解析异常

**问题描述**：某些域名无法解析

**排查过程**：

```bash
# 1. 测试 DNS
nslookup www.problem.com
# 结果：解析失败

# 2. 使用其他 DNS
nslookup www.problem.com 8.8.8.8
# 结果：能解析

# 3. 分析
# 本地 DNS 服务器有问题

# 4. 解决方案
# - 更换 DNS 服务器为 8.8.8.8
# - 或联系 ISP 修复 DNS
```

## 7 新手常见误区

### 误区 1："重启能解决所有问题"

**错！** 重启只是临时措施，不能解决根本问题。应该先找到原因，再针对性解决。

### 误区 2："网络问题都是运营商的错"

不对。网络问题可能出在本地设备、配置、应用等多个环节。应该先排查本地，再联系运营商。

### 误区 3："抓包太复杂，学不会"

其实抓包工具都有图形界面，入门并不难。从简单的 ping、traceroute 开始，逐步深入。

### 误区 4："故障排查靠运气"

不对。故障排查是有方法论的，按照分层、分段、对比的思路，系统性地排查，成功率会大大提高。
