# 第五章：垃圾回收基础

## 本章导读

在学这一章之前，你可能会有这些疑问：

- 什么是垃圾回收（GC）？为什么需要自动内存管理？
- JVM 如何判断哪些对象是"垃圾"？
- 有哪些常见的垃圾回收算法？
- 什么是 GC Roots？它们有什么作用？

这一章就是为了解答这些问题。我们会先搞清楚 **垃圾回收的核心概念**，再深入理解可达性分析和 GC 算法，最后掌握 GC Roots 的作用。

---

## 5.1 为什么需要垃圾回收？

### 痛点分析

想象一下这个场景：

你用 C++ 写程序，每次创建对象后都要手动释放内存。如果忘记释放，就会出现内存泄漏；如果释放两次，程序会崩溃。

这就是**手动内存管理的痛点**——容易出错，开发效率低。

### Java 的解决方案

Java 采用**自动内存管理**，JVM 会自动回收不再使用的对象。

打个比方：

> 就像餐厅的服务员会自动清理空桌子，你不需要自己收拾餐具。JVM 就是那个服务员，自动清理不再使用的对象。

### 垃圾回收的优势

| 优势 | 说明 |
| --- | --- |
| 开发效率高 | 不需要手动管理内存 |
| 避免内存泄漏 | 自动回收不再使用的对象 |
| 避免悬空指针 | 不会出现访问已释放内存的问题 |
| 降低开发难度 | 新手也能写出安全的代码 |

---

## 5.2 如何判断对象是"垃圾"？

### 引用计数法

引用计数法是最直观的垃圾回收算法。每个对象都有一个引用计数器，记录有多少引用指向它。

```java
// 示例：引用计数
public class ReferenceCountingDemo {
    public static void main(String[] args) {
        Object obj1 = new Object(); // obj1 引用计数为 1
        Object obj2 = obj1;         // obj1 引用计数为 2
        
        obj1 = null;                // obj1 引用计数为 1
        obj2 = null;                // obj1 引用计数为 0，可以被回收
    }
}
```

### 引用计数法的问题

引用计数法有一个致命缺陷：**无法处理循环引用**。

```java
// 示例：循环引用问题
public class CircularReferenceDemo {
    public static void main(String[] args) {
        Object obj1 = new Object();
        Object obj2 = new Object();
        
        obj1.ref = obj2; // obj1 引用 obj2
        obj2.ref = obj1; // obj2 引用 obj1
        
        obj1 = null;
        obj2 = null;
        
        // 虽然 obj1 和 obj2 已经不可达
        // 但它们的引用计数不为 0
        // 导致无法被回收
    }
}

class MyObject {
    Object ref;
}
```

### 可达性分析算法

为了解决循环引用问题，JVM 采用**可达性分析算法**。

算法思路：从一组称为 **GC Roots** 的对象开始，沿着引用链向下搜索。如果一个对象到 GC Roots 没有任何引用链，说明该对象不可达，可以被回收。

```
GC Roots
    ↓
可达对象（存活）
    ↓
不可达对象（垃圾）
```

打个比方：

> 就像从公司总部（GC Roots）出发，沿着组织架构图往下找。如果某个员工和总部没有任何联系，说明他已经离职，可以被清理。

## 5.3 GC Roots

### 什么是 GC Roots

GC Roots 是 JVM 中的一组特殊对象，它们是垃圾回收的起点。所有可达对象都必须从 GC Roots 可达。

### GC Roots 的类型

| GC Root 类型 | 说明 |
| --- | --- |
| 虚拟机栈中的引用 | 方法中的局部变量、参数 |
| 方法区中的静态变量 | 类的静态字段 |
| 方法区中的常量 | 常量池中的引用 |
| 本地方法栈中的引用 | JNI（本地方法）中的引用 |
| 同步监视器 | 被 synchronized 锁定的对象 |
| JVM 内部引用 | 系统类加载器、异常对象等 |

### GC Roots 示例

```java
// 示例：GC Roots
public class GCRootsDemo {
    // 静态变量是 GC Root
    public static Object staticObj = new Object();
    
    // 常量是 GC Root
    public static final String CONSTANT = "Hello";
    
    public static void main(String[] args) {
        // 局部变量是 GC Root
        Object localObj = new Object();
        
        // 参数是 GC Root
        process(localObj);
    }
    
    public static void process(Object obj) {
        // obj 是局部变量，也是 GC Root
        System.out.println(obj);
    }
}
```

## 5.4 垃圾回收算法

### 标记-清除算法

标记-清除算法是最基础的垃圾回收算法。它分为两个阶段：

1. **标记阶段**：标记所有可达对象
2. **清除阶段**：清除所有未标记对象

```
回收前：
[存活][垃圾][存活][垃圾][存活]

标记后：
[存活][  ][存活][  ][存活]

清除后：
[存活][  ][存活][  ][存活]
```

**优点**：简单直观

**缺点**：
- 效率低：需要扫描整个内存空间
- 内存碎片：产生大量不连续的内存空间

### 复制算法

复制算法将内存分为两块，每次只使用一块。当这块内存用完时，将存活对象复制到另一块，然后清空当前块。

```
回收前：
To 区：[空]
From 区：[存活][垃圾][存活][垃圾]

复制后：
To 区：[存活][存活]
From 区：[空]
```

**优点**：
- 无内存碎片
- 分配效率高

**缺点**：
- 内存利用率低：需要两块内存
- 复制开销大：需要复制大量对象

### 标记-整理算法

标记-整理算法结合了标记-清除和复制算法的优点。它先标记所有存活对象，然后将它们移动到内存的一端，最后清理边界外的空间。

```
回收前：
[存活][垃圾][存活][垃圾][存活]

标记后：
[存活][  ][存活][  ][存活]

整理后：
[存活][存活][存活][  ][  ]
```

**优点**：
- 无内存碎片
- 内存利用率高

**缺点**：
- 移动对象开销大
- 需要更新引用

### 分代收集算法

分代收集算法是现代 JVM 采用的算法。它将堆分为**新生代**和**老年代**，针对不同代采用不同的回收算法。

```
┌─────────────────────────────┐
│  新生代（Young Generation）  │
│  ├─ Eden 区                  │
│  ├─ Survivor 0 区            │
│  └─ Survivor 1 区            │
│  采用复制算法                │
├─────────────────────────────┤
│  老年代（Old Generation）    │
│  └─ 长期存活的对象           │
│  采用标记-清除或标记-整理    │
└─────────────────────────────┘
```

**新生代特点**：
- 对象朝生夕死
- 采用复制算法
- 回收频繁

**老年代特点**：
- 对象长期存活
- 采用标记-清除或标记-整理
- 回收较少

## 5.5 垃圾回收过程

### 新生代回收过程

```
1. 对象在 Eden 区分配
2. Eden 区满，触发 Minor GC
3. 将 Eden 和 Survivor 0 中的存活对象复制到 Survivor 1
4. 清空 Eden 和 Survivor 0
5. 交换 Survivor 0 和 Survivor 1 的角色
6. 对象年龄增加，超过阈值进入老年代
```

### 老年代回收过程

```
1. 老年代空间不足，触发 Major GC / Full GC
2. 标记所有存活对象
3. 清除或整理未标记对象
4. 回收内存空间
```

### GC 类型

| GC 类型 | 说明 | 触发条件 |
| --- | --- | --- |
| Minor GC | 新生代回收 | Eden 区满 |
| Major GC | 老年代回收 | 老年代空间不足 |
| Full GC | 整个堆回收 | 老年代或方法区空间不足 |

## 5.6 核心知识点总结

| 知识点 | 说明 |
| --- | --- |
| 引用计数法 | 记录引用数量，无法处理循环引用 |
| 可达性分析 | 从 GC Roots 出发，判断对象是否可达 |
| GC Roots | 垃圾回收的起点，包括局部变量、静态变量等 |
| 标记-清除 | 标记存活对象，清除未标记对象，产生碎片 |
| 复制算法 | 将存活对象复制到另一块内存，无碎片 |
| 标记-整理 | 标记后将存活对象移动到一端，无碎片 |
| 分代收集 | 新生代用复制算法，老年代用标记-清除/整理 |

## 5.7 新手常见误区

### 误区 1："Java 没有内存泄漏"

**错！** 虽然 Java 有自动垃圾回收，但如果持有对象的引用不释放，仍然会导致内存泄漏。

正确做法：及时释放不再使用的对象引用，特别是静态集合类。

### 误区 2："垃圾回收会立即执行"

不是的。垃圾回收是**异步执行**的，JVM 会根据内存使用情况决定何时执行 GC。调用 `System.gc()` 只是建议 JVM 执行 GC，不保证立即执行。

### 误区 3："对象被 GC 回收后，finalize 方法一定会执行"

不对。finalize 方法的执行是不确定的，JVM 不保证它会立即执行，甚至可能不执行。不建议使用 finalize 方法。

### 误区 4："Minor GC 比 Major GC 快"

通常情况下是的，因为新生代对象存活率低，回收效率高。但如果新生代对象存活率高，Minor GC 也可能很慢。

### 练习 3（挑战）：综合题

请解释分代收集算法的原理，为什么新生代采用复制算法，老年代采用标记-清除或标记-整理算法？

<details>
<summary>点击查看答案</summary>

**分代收集算法原理**：

分代收集算法将堆分为新生代和老年代，针对不同代采用不同的回收算法。

**新生代采用复制算法的原因**：

1. **对象朝生夕死**：新生代中大部分对象都是临时对象，存活率低
2. **复制效率高**：只需要复制少量存活对象，复制开销小
3. **无内存碎片**：复制后的内存是连续的，分配效率高

**老年代采用标记-清除或标记-整理的原因**：

1. **对象长期存活**：老年代中对象存活率高，复制开销大
2. **内存利用率高**：标记-清除或标记-整理不需要额外的内存空间
3. **回收频率低**：老年代回收不频繁，可以承受较高的回收成本

**总结**：

分代收集算法根据对象的生命周期特点，选择合适的回收算法，既保证了回收效率，又保证了内存利用率。

</details>
