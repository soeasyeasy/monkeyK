# 第六章：垃圾收集器详解

## 本章导读

在学这一章之前，你可能会有这些疑问：

- JVM 有哪些垃圾收集器？它们有什么区别？
- 什么是串行收集器？什么是并行收集器？
- CMS 和 G1 有什么区别？哪个更好？
- ZGC 是什么？它能解决什么问题？

这一章就是为了解答这些问题。我们会先搞清楚 **各种垃圾收集器的特点**，再深入理解它们的工作原理和适用场景。学完这章，你就能根据应用特点选择合适的垃圾收集器。

---

## 1 为什么需要多种垃圾收集器？

### 痛点分析

想象一下这个场景：

你的应用是一个 Web 服务，需要低延迟；另一个应用是批处理程序，需要高吞吐量。如果用同一种垃圾收集器，很难同时满足这两个需求。

这就是**不同场景需要不同垃圾收集器**的原因。

### 垃圾收集器的分类

垃圾收集器可以从多个维度分类：

| 分类维度 | 类型 | 说明 |
| --- | --- | --- |
| 线程数量 | 串行收集器 | 单线程执行 GC |
| 线程数量 | 并行收集器 | 多线程执行 GC |
| 回收区域 | 新生代收集器 | 只回收新生代 |
| 回收区域 | 老年代收集器 | 只回收老年代 |
| 回收区域 | 整堆收集器 | 回收整个堆 |
| 停顿时间 | 非低延迟收集器 | 停顿时间较长 |
| 停顿时间 | 低延迟收集器 | 停顿时间极短 |

## 2 Serial 收集器

### 什么是 Serial 收集器

Serial 收集器是**最古老**的垃圾收集器，它使用**单线程**执行垃圾回收。

### Serial 收集器的特点

| 特点 | 说明 |
| --- | --- |
| 单线程 | 只有一个 GC 线程 |
| 串行执行 | GC 时暂停所有用户线程 |
| 简单高效 | 没有线程交互开销 |

### Serial 收集器的适用场景

| 场景 | 说明 |
| --- | --- |
| 客户端应用 | 对延迟不敏感 |
| 小内存应用 | 堆内存较小 |
| 单核处理器 | 没有多核优势 |

### Serial 收集器的配置

```bash
# 启用 Serial 收集器
-XX:+UseSerialGC

# 新生代使用 Serial
-XX:+UseSerialGC
```

---

## 3 Parallel 收集器

### 什么是 Parallel 收集器

Parallel 收集器是**吞吐量优先**的垃圾收集器，它使用**多线程**并行执行垃圾回收。

### Parallel 收集器的特点

| 特点 | 说明 |
| --- | --- |
| 多线程并行 | 多个 GC 线程同时工作 |
| 吞吐量高 | 减少 GC 总时间 |
| 停顿时间长 | GC 时暂停所有用户线程 |

### Parallel 收集器的适用场景

| 场景 | 说明 |
| --- | --- |
| 批处理应用 | 对吞吐量要求高 |
| 后台任务 | 对延迟不敏感 |
| 多核处理器 | 能充分利用多核优势 |

### Parallel 收集器的配置

```bash
# 启用 Parallel 收集器（JDK 8 默认）
-XX:+UseParallelGC

# 设置 GC 线程数
-XX:ParallelGCThreads=4

# 启用自适应调节
-XX:+UseAdaptiveSizePolicy
```

## 4 CMS 收集器

### 什么是 CMS 收集器

CMS（Concurrent Mark Sweep）收集器是**低延迟优先**的垃圾收集器，它采用**并发标记-清除**算法。

### CMS 收集器的特点

| 特点 | 说明 |
| --- | --- |
| 并发执行 | GC 线程与用户线程并发执行 |
| 低延迟 | 减少 GC 停顿时间 |
| 标记-清除 | 不移动对象，产生内存碎片 |

### CMS 收集器的工作过程

```
1. 初始标记（STW）
   - 标记 GC Roots 直接关联的对象
   - 停顿时间短

2. 并发标记
   - 遍历对象图，标记所有存活对象
   - 与用户线程并发执行

3. 重新标记（STW）
   - 修正并发标记期间的变化
   - 停顿时间稍长

4. 并发清除
   - 清除未标记对象
   - 与用户线程并发执行
```

### CMS 收集器的缺点

| 缺点 | 说明 |
| --- | --- |
| 内存碎片 | 标记-清除算法产生碎片 |
| CPU 敏感 | 并发执行占用 CPU 资源 |
| 浮动垃圾 | 并发期间产生新垃圾 |
| 并发失败 | 内存不足时退化为 Serial Old |

### CMS 收集器的配置

```bash
# 启用 CMS 收集器
-XX:+UseConcMarkSweepGC

# 设置并发 GC 线程数
-XX:ConcGCThreads=4

# 设置老年代触发 CMS 的阈值
-XX:CMSInitiatingOccupancyFraction=75

# 启用 CMS 类卸载
-XX:+CMSClassUnloadingEnabled
```

## 5 G1 收集器

### 什么是 G1 收集器

G1（Garbage-First）收集器是**面向服务端**的垃圾收集器，它采用**分区算法**，将堆划分为多个大小相等的独立区域（Region）。

### G1 收集器的特点

| 特点 | 说明 |
| --- | --- |
| 分区管理 | 堆被划分为多个 Region |
| 可预测停顿 | 可以设置期望的停顿时间 |
| 并行并发 | 结合并行和并发执行 |
| 空间整合 | 采用复制算法，无内存碎片 |

### G1 收集器的 Region 结构

```
┌─────────────────────────────┐
│  G1 堆（Heap）               │
├─────────────────────────────┤
│  Eden 区                     │
│  ├─ Region 1                 │
│  ├─ Region 2                 │
│  └─ Region 3                 │
├─────────────────────────────┤
│  Survivor 区                 │
│  ├─ Region 4                 │
│  └─ Region 5                 │
├─────────────────────────────┤
│  Old 区                      │
│  ├─ Region 6                 │
│  ├─ Region 7                 │
│  └─ Region 8                 │
├─────────────────────────────┤
│  Humongous 区                │
│  └─ Region 9（大对象）       │
└─────────────────────────────┘
```

### G1 收集器的工作过程

```
1. 初始标记（STW）
   - 标记 GC Roots 直接关联的对象
   - 停顿时间短

2. 并发标记
   - 遍历对象图，标记所有存活对象
   - 与用户线程并发执行

3. 最终标记（STW）
   - 处理 SATB（Snapshot-At-The-Beginning）队列
   - 停顿时间稍长

4. 筛选回收（STW）
   - 选择回收价值最高的 Region
   - 复制存活对象，清除垃圾对象
```

### G1 收集器的配置

```bash
# 启用 G1 收集器（JDK 9+ 默认）
-XX:+UseG1GC

# 设置最大停顿时间目标
-XX:MaxGCPauseMillis=200

# 设置 Region 大小
-XX:G1HeapRegionSize=4M

# 设置老年代触发 G1 的阈值
-XX:InitiatingHeapOccupancyPercent=45
```

## 6 ZGC 收集器

### 什么是 ZGC 收集器

ZGC（Z Garbage Collector）是**超低延迟**的垃圾收集器，它的停顿时间**不超过 10ms**，且不会随堆大小增加。

### ZGC 收集器的特点

| 特点 | 说明 |
| --- | --- |
| 超低延迟 | 停顿时间 < 10ms |
| 可扩展 | 支持 TB 级堆内存 |
| 并发执行 | 所有阶段都并发执行 |
| 着色指针 | 使用指针标记对象状态 |

### ZGC 收集器的工作过程

```
1. 并发标记
   - 遍历对象图，标记存活对象
   - 与用户线程并发执行

2. 并发重定位
   - 移动存活对象到新位置
   - 更新所有引用
   - 使用染色指针技术

3. 并发重映射
   - 更新对象引用
   - 与用户线程并发执行
```

### ZGC 收集器的配置

```bash
# 启用 ZGC 收集器（JDK 15+ 生产可用）
-XX:+UseZGC

# 设置堆大小
-Xmx4G
-Xms4G

# 启用并发类卸载
-XX:+ZUncommit
```

## 7 Shenandoah 收集器

### 什么是 Shenandoah 收集器

Shenandoah 是另一个**低延迟**垃圾收集器，它采用**转发指针**技术，与 ZGC 类似。

### Shenandoah 收集器的特点

| 特点 | 说明 |
| --- | --- |
| 低延迟 | 停顿时间短 |
| 并发执行 | 大部分阶段并发执行 |
| 转发指针 | 使用转发指针更新引用 |

### Shenandoah 与 ZGC 的对比

| 特性 | Shenandoah | ZGC |
| --- | --- | --- |
| 停顿时间 | 低 | 极低 |
| 堆大小支持 | 中等 | 超大（TB 级） |
| 实现方式 | 转发指针 | 染色指针 |
| 成熟度 | 较新 | 成熟 |

## 8 垃圾收集器选择指南

### 选择建议

| 场景 | 推荐收集器 | 原因 |
| --- | --- | --- |
| 小型应用 | Serial | 简单高效 |
| 批处理应用 | Parallel | 高吞吐量 |
| Web 服务 | G1 | 平衡延迟和吞吐 |
| 低延迟应用 | ZGC | 超低延迟 |
| 大内存应用 | ZGC | 支持 TB 级堆 |

| 收集器 | 吞吐量 | 延迟 | 内存占用 | 适用堆大小 |
| --- | --- | --- | --- | --- |
| Serial | 中 | 高 | 低 | 小 |
| Parallel | 高 | 高 | 中 | 中 |
| CMS | 中 | 低 | 中 | 中 |
| G1 | 中高 | 中低 | 中 | 中大 |
| ZGC | 中高 | 极低 | 高 | 超大 |

## 9 核心知识点总结

| 知识点 | 说明 |
| --- | --- |
| Serial | 单线程，简单高效，适合小应用 |
| Parallel | 多线程并行，高吞吐量，适合批处理 |
| CMS | 并发标记-清除，低延迟，有内存碎片 |
| G1 | 分区管理，可预测停顿，适合服务端 |
| ZGC | 超低延迟，支持 TB 级堆，适合大内存应用 |
| Shenandoah | 低延迟，转发指针，与 ZGC 类似 |

## 10 新手常见误区

### 误区 1："G1 是最好的垃圾收集器"

**错！** 没有最好的垃圾收集器，只有最适合的。不同的应用场景需要不同的收集器。G1 适合大多数服务端应用，但不一定适合所有场景。

正确做法：根据应用特点选择合适的收集器。

### 误区 2："ZGC 可以完全消除 GC 停顿"

不是的。ZGC 只是将停顿时间降到极低（< 10ms），但不能完全消除。对于实时性要求极高的应用，仍需要考虑其他方案。

### 误区 3："CMS 已经过时，不应该使用"

虽然 CMS 在 JDK 9 被标记为废弃，JDK 14 被移除，但在 JDK 8 等老版本中仍然广泛使用。对于已有应用，不建议盲目迁移。

### 误区 4："垃圾收集器不需要调优"

实际上，垃圾收集器的参数调优对性能影响很大。默认参数可能不适合所有场景，需要根据应用特点进行调整。

### 练习 2：进阶题

请解释 ZGC 收集器的工作原理，为什么它能实现超低延迟？

<details>
<summary>点击查看答案</summary>

**ZGC 工作原理**：

ZGC 采用**染色指针**（Colored Pointers）技术，将所有 GC 阶段都改为并发执行。

**为什么能实现超低延迟**：

1. **并发标记**：标记阶段与用户线程并发执行，不需要暂停
2. **并发重定位**：移动对象时，使用染色指针技术，不需要暂停用户线程
3. **并发重映射**：更新引用时，与用户线程并发执行

**染色指针技术**：

ZGC 使用指针的高位存储元数据（如标记信息），这样可以在不访问对象的情况下判断对象状态，从而避免暂停用户线程。

**总结**：

ZGC 通过并发执行和染色指针技术，将 GC 停顿时间降到极低（< 10ms），且不会随堆大小增加。

</details>

### 练习 3（挑战）：综合题

请为一个 Web 服务应用选择合适的垃圾收集器，并说明理由。

<details>
<summary>点击查看答案</summary>

**推荐选择 G1 收集器**

**理由**：

1. **Web 服务特点**：
   - 需要平衡吞吐量和延迟
   - 堆内存通常较大（几 GB 到几十 GB）
   - 需要可预测的停顿时间

2. **G1 收集器优势**：
   - **可预测停顿**：可以设置最大停顿时间目标（如 200ms）
   - **分区管理**：堆被划分为多个 Region，灵活管理
   - **空间整合**：采用复制算法，无内存碎片
   - **并行并发**：结合并行和并发执行，平衡吞吐和延迟

3. **配置建议**：
   ```bash
   -XX:+UseG1GC
   -XX:MaxGCPauseMillis=200
   -XX:G1HeapRegionSize=4M
   -XX:InitiatingHeapOccupancyPercent=45
   ```

**其他选择**：

- 如果对延迟要求极高（< 10ms），可以选择 ZGC
- 如果对吞吐量要求高，可以选择 Parallel 收集器

</details>
