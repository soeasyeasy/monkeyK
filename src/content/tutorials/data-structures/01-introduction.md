# 第一章：数据结构概述

## 本章导读

在学这一章之前，你可能会有这些疑问：

- 数据结构到底是什么？听起来很抽象，学它有什么用？
- 数组、链表、栈、队列这些名词到底在说什么？它们之间有什么区别？
- 为什么面试总问数据结构？写业务代码真的用得到吗？
- 时间复杂度 O(n) 这些符号到底怎么看？

这一章就是为了解答这些问题。我们会先搞清楚 **数据结构是什么、为什么重要**，再了解它的分类体系，最后学会用时间复杂度来评估算法的好坏。学完之后，你会对数据结构有一个完整的认识框架，为后面深入学习每种具体结构打好基础。

---

## 1.1 为什么需要数据结构？

### 痛点分析

想象一下这个场景：

你是一个图书管理员，手里有 10000 本书。读者来借书，你要找到对应的书。如果你把所有书随便堆在仓库里，每次找一本书都要翻遍整个仓库，可能要花几个小时。

但如果你给书分类摆放——按编号排列、按类别分区、建一套索引卡片——找一本书可能只需要几分钟。

这就是**数据结构的核心价值**：**同样的数据，组织方式不同，效率天差地别。**

### 生活化类比

> 数据结构就像整理房间的方式。
>
> - 你的衣服可以随便扔在床上（没有数据结构），也可以按季节挂在衣柜里（有序结构）。
> - 你的书可以堆成一堆，也可以按类别放在书架上。
> - 你的手机通讯录可以存在一个文本文件里，也可以存在数据库里。
>
> 整理方式不同，找东西的速度就不同。数据结构就是"数据的整理方式"。

### 数据结构在编程中的位置

```
程序 = 数据结构 + 算法

数据结构：数据在计算机中的组织方式（怎么存）
算法：对数据进行操作的方法（怎么算）
```

打个比方：

> 数据结构就像仓库的货架布局——决定货物怎么摆放。
> 算法就像取货的路线——决定怎么最快拿到货物。
> 两者配合，才能让仓库高效运转。

## 1.2 数据结构的核心概念

### 什么是数据结构

**数据结构（Data Structure）** 是计算机中组织、管理、存储数据的方式。它的设计目标是：

- 让数据能够被高效地**访问**
- 让数据能够被高效地**修改**
- 让数据之间的关系能够被清晰地**表达**

### 数据的逻辑结构分类

数据结构按照逻辑关系，可以分为以下几类：

| 分类 | 说明 | 常见结构 | 生活化类比 |
| --- | --- | --- | --- |
| 线性结构 | 数据元素之间是一对一的线性关系 | 数组、链表、栈、队列 | 排队买票，一个接一个 |
| 树形结构 | 数据元素之间是一对多的层次关系 | 二叉树、B 树、红黑树 | 公司的组织架构图，老板下面有经理，经理下面有员工 |
| 图状结构 | 数据元素之间是多对多的关系 | 有向图、无向图 | 社交网络，每个人可以认识多个人 |
| 集合结构 | 数据元素之间除了"同属一个集合"外没有其他关系 | 集合（Set） | 一个袋子里装了各种东西，彼此没有关联 |

### 数据的存储结构

数据在计算机内存中有两种基本的存储方式：

| 存储方式 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 顺序存储 | 数据元素在内存中连续存放 | 访问速度快，可以通过下标直接定位 | 插入和删除需要移动大量元素 |
| 链式存储 | 数据元素在内存中不连续存放，通过指针连接 | 插入和删除方便，不需要移动元素 | 访问速度慢，必须从头遍历 |

打个比方：

> **顺序存储**就像电影院连号座位，第 5 排第 3 号直接就能找到，但中间要加一个座位就得让后面所有人都挪一下。
>
> **链式存储**就像寻宝游戏，每个宝箱里写着下一个宝箱的位置，你可以随时在中间插入一个新宝箱，但想找第 10 个宝箱就得从第 1 个开始一个一个找。

## 1.3 算法与时间复杂度

### 什么是算法

**算法（Algorithm）** 是解决特定问题的一系列明确指令。

好的算法应该满足：

- **正确性**：能正确解决问题
- **可读性**：人能看懂
- **高效性**：消耗的时间和内存尽量少

### 为什么需要时间复杂度

衡量一个算法的好坏，最直观的方法是"跑一下看要多久"。但这种方法有问题：

- 不同电脑性能不同，同一算法在不同电脑上运行时间不同
- 数据量不同，同一算法对不同规模数据运行时间不同
- 测试环境有干扰，结果不稳定

所以我们需要一个**与硬件无关、与数据规模相关**的衡量标准——**时间复杂度**。

### 大 O 表示法

时间复杂度用**大 O 表示法**来描述，它表示的是：**当数据规模 n 增大时，算法执行时间的增长趋势**。

注意：它不是精确的执行时间，而是**增长趋势**。

#### 常见的时间复杂度（从快到慢）

| 时间复杂度 | 名称 | 说明 | 生活化类比 |
| --- | --- | --- | --- |
| O(1) | 常数时间 | 不管数据量多大，执行时间不变 | 从书柜里随便拿一本书 |
| O(log n) | 对数时间 | 每次操作数据量减半 | 查字典，每次翻到中间看，范围缩小一半 |
| O(n) | 线性时间 | 数据量翻倍，时间翻倍 | 在一排书中从左到右一本一本找 |
| O(n log n) | 线性对数时间 | 比线性稍慢 | 高效的排序算法（如归并排序） |
| O(n^2) | 平方时间 | 数据量翻倍，时间变 4 倍 | 两两比较每对书是否重复 |
| O(2^n) | 指数时间 | 数据量增加 1，时间翻倍 | 穷举所有可能的密码组合 |

#### 用图来感受增长趋势

```
执行次数
|
|                                          / O(2^n)
|                                        /
|                                      /
|                                   /
|                               /
|                          __-- O(n^2)
|                     __--
|                __--
|           ___--_______________________ O(n)
|      _--___
|  _--___  . . . . . . . . . . . . . . O(log n)
|--___ . . . . . . . . . . . . . . . . O(1)
+------------------------------------------ 数据量 n
```

### 如何计算时间复杂度

**核心原则：只看最高次项，忽略常数。**

```javascript
// 示例 1：O(1) - 常数时间
// 不管数组多大，直接通过下标访问元素，只需要 1 步
const arr = [10, 20, 30, 40, 50];
const first = arr[0]; // 无论数组有 5 个还是 500 万个元素，都是 1 步

// 示例 2：O(n) - 线性时间
// 遍历一次数组，数组有 n 个元素就执行 n 次
function findElement(arr, target) {
  for (let i = 0; i < arr.length; i++) { // 循环 n 次
    if (arr[i] === target) { // 每次比较 1 次
      return i;
    }
  }
  return -1;
}

// 示例 3：O(n^2) - 平方时间
// 两层嵌套循环，外层 n 次，内层 n 次，总共 n * n = n^2 次
function printAllPairs(arr) {
  for (let i = 0; i < arr.length; i++) { // 外层循环 n 次
    for (let j = 0; j < arr.length; j++) { // 内层循环 n 次
      console.log(arr[i], arr[j]); // 打印每一对组合
    }
  }
}

// 示例 4：O(log n) - 对数时间
// 每次把搜索范围缩小一半
function binarySearch(arr, target) {
  let left = 0; // 左边界
  let right = arr.length - 1; // 右边界
  while (left <= right) { // 当左右边界还没交叉时继续
    const mid = Math.floor((left + right) / 2); // 取中间位置
    if (arr[mid] === target) return mid; // 找到了
    if (arr[mid] < target) left = mid + 1; // 目标在右半部分
    else right = mid - 1; // 目标在左半部分
  }
  return -1;
}
```

::: tip 快速判断技巧

- **没有循环** → O(1)
- **一层循环** → O(n)
- **两层嵌套循环** → O(n^2)
- **每次减半** → O(log n)
- **排序算法** → 通常是 O(n log n)

:::

## 1.4 空间复杂度

### 什么是空间复杂度

空间复杂度衡量的是：**算法在运行过程中额外占用的内存空间随数据规模增长的趋势**。

和时间复杂度类似，也用大 O 表示法。

```javascript
// O(1) 空间复杂度 - 只用了固定几个变量，不随数据量增长
function sum(arr) {
  let total = 0; // 1 个变量
  for (let i = 0; i < arr.length; i++) {
    total += arr[i]; // 没有创建新的数据结构
  }
  return total;
}

// O(n) 空间复杂度 - 创建了一个和原数组一样大的新数组
function doubleArray(arr) {
  const result = []; // 新建了一个数组
  for (let i = 0; i < arr.length; i++) {
    result.push(arr[i] * 2); // 新数组大小和原数组一样
  }
  return result;
}
```

::: tip 权衡原则

在实际开发中，我们经常需要在**时间**和**空间**之间做权衡。有时候多占一点内存，可以换来更快的执行速度（这叫"空间换时间"）。比如缓存就是一种典型的空间换时间策略。

:::

## 1.5 核心知识点总结

| 知识点 | 要点 |
| --- | --- |
| 数据结构的定义 | 数据在计算机中的组织方式，决定了访问和修改的效率 |
| 逻辑结构分类 | 线性结构、树形结构、图状结构、集合结构 |
| 存储结构分类 | 顺序存储（连续）、链式存储（不连续，靠指针连接） |
| 程序的本质 | 程序 = 数据结构 + 算法 |
| 时间复杂度 | 描述算法执行时间随数据规模增长的趋势，用大 O 表示 |
| 常见复杂度排序 | O(1) < O(log n) < O(n) < O(n log n) < O(n^2) < O(2^n) |
| 空间复杂度 | 描述算法额外占用内存随数据规模增长的趋势 |
| 时空权衡 | 有时可以用更多内存换取更快的速度 |

## 1.6 新手常见误区

### 误区 1：时间复杂度 = 精确的执行时间

**错误理解**：O(n) 就是执行 n 毫秒。

**正确理解**：O(n) 表示的是**增长趋势**，不是精确时间。它告诉你"数据量翻倍时，时间大约翻倍"，但不告诉你具体是多少毫秒。

### 误区 2：O(n) 一定比 O(n^2) 快

**错误理解**：O(n) 的算法在任何情况下都比 O(n^2) 快。

**正确理解**：时间复杂度描述的是**数据量很大时**的趋势。当数据量很小时，O(n^2) 的算法可能因为常数项更小而更快。但数据量足够大时，O(n) 一定优于 O(n^2)。

### 误区 3：学数据结构就是为了面试

**错误理解**：做业务开发用不到数据结构，学它只是为了应付面试。

**正确理解**：数据结构无处不在。你用数据库索引（B 树）、用前端路由（树）、用缓存（哈希表）、用消息队列（队列）。理解数据结构能帮你写出更高效的代码，做出更好的技术选型。

### 误区 4：最佳数据结构是万能的

**错误理解**：存在一种"最好的"数据结构，什么场景都能用。

**正确理解**：没有最好的数据结构，只有最适合当前场景的数据结构。数组适合随机访问，链表适合频繁插入删除，哈希表适合快速查找。选择取决于你的具体需求。

## 1.7 动手练习

### 练习 1：分析时间复杂度

请分析以下代码的时间复杂度：

```javascript
function mystery(arr) {
  let count = 0;
  for (let i = 0; i < arr.length; i++) {
    for (let j = i; j < arr.length; j++) {
      count++;
    }
  }
  return count;
}
```

::: details 点击查看答案

时间复杂度是 **O(n^2)**。

虽然内层循环从 i 开始而不是从 0 开始，实际执行次数是 n + (n-1) + (n-2) + ... + 1 = n*(n+1)/2，但根据大 O 表示法规则，忽略常数和低次项，结果仍然是 O(n^2)。

:::

### 练习 2：选择合适的数据结构

场景：你需要实现一个"最近浏览记录"功能，最多保存 20 条记录。新记录加在最前面，超过 20 条就删掉最旧的。你会选择什么数据结构？

::: details 点击查看答案

适合用**数组**或**双端队列（Deque）**。

- 需要按顺序保存记录 → 线性结构
- 需要在两端操作（头部插入、尾部删除） → 数组或双端队列都可以
- 数据量固定且很小（最多 20 条） → 数组的缺点（中间插入慢）不会暴露

如果用 JavaScript，可以直接用数组的 `unshift()` 和 `pop()` 方法。

:::

### 练习 3：空间复杂度分析

分析以下代码的空间复杂度：

```javascript
function fibonacci(n) {
  const dp = [0, 1];
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i - 1] + dp[i - 2];
  }
  return dp[n];
}
```

::: details 点击查看答案

空间复杂度是 **O(n)**。

创建了一个长度为 n+1 的数组 `dp`，随着 n 的增大，数组占用的内存线性增长。

如果想优化到 O(1)，可以只保存前两个值，不需要整个数组：

```javascript
function fibonacciOptimized(n) {
  if (n <= 1) return n; // 边界情况
  let prev2 = 0; // 前第二个值
  let prev1 = 1; // 前一个值
  for (let i = 2; i <= n; i++) {
    const current = prev1 + prev2; // 当前值 = 前两个值之和
    prev2 = prev1; // 更新前第二个值
    prev1 = current; // 更新前一个值
  }
  return prev1; // 返回第 n 个斐波那契数
}
```

优化后空间复杂度降为 O(1)，只用了 3 个变量。

:::
