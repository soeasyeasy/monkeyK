# 第九章：内存管理基础

## 本章导读

在开始学习之前，你可能会有这些疑问：

1. **程序里的地址就是内存的真实地址吗？** -- 其实程序看到的地址和硬件看到的地址是两回事，本章会讲清楚它们之间的关系。
2. **内存是怎么分配给各个程序的？** -- 从最简单的连续分配到复杂的分页分段，我们会一步步了解内存分配的演进过程。
3. **为什么需要分页和分段？** -- 连续分配有什么问题？分页和分段又是如何解决这些问题的？
4. **现代操作系统到底是怎么管理内存的？** -- 段页式管理是最终答案，也是 Linux 等系统实际使用的方案。

本章我们就来解决这些问题，帮你建立起内存管理的完整知识体系。

## 为什么需要内存管理

### 没有内存管理会怎样

想象一下，你住在一个没有物业管理的小区里：

- 没有门牌号（没有地址管理），快递找不到你家
- 没有停车位规划（没有空间分配），车子乱停乱放
- 没有保安巡逻（没有内存保护），谁都可以进你家翻东西

内存管理就是操作系统这个"物业管家"，它负责：

| 功能 | 说明 | 类比 |
| --- | --- | --- |
| 内存分配 | 为进程分配所需的内存空间 | 给住户分配停车位 |
| 内存保护 | 防止进程访问未授权的内存区域 | 保安不让陌生人进你家 |
| 地址映射 | 将逻辑地址转换为物理地址 | 把门牌号映射到实际位置 |
| 内存共享 | 允许多个进程共享同一内存区域 | 小区公共设施大家共用 |
| 内存扩充 | 通过虚拟内存技术扩展可用内存 | 车位不够时建地下车库 |

### 内存管理的演进

就像城市从村庄发展到大都市一样，内存管理也经历了从简单到复杂的演进：

```
单一连续分配 --> 固定分区 --> 动态分区 --> 分页 --> 分段 --> 段页式
（小村庄）      （规划小区）  （智能小区）  （公寓楼） （别墅区） （综合社区）
```

## 核心原理讲解

### 一、逻辑地址与物理地址

这是内存管理最基础的概念，你必须搞清楚。

**逻辑地址**：程序编译后产生的地址，也叫相对地址。你可以理解为"程序以为自己住在哪"。

**物理地址**：内存单元的真实地址，也叫绝对地址。这是"程序实际住在哪"。

**生活类比**：逻辑地址就像你简历上写的"通讯地址"，物理地址就像你的"实际住址"。你搬家了（程序被重定位），实际住址变了，但简历上的地址可以不变，只要有个" forwarding address"（地址映射机制）帮你转寄邮件就行。

```
┌─────────────┐         ┌─────────────┐
│   程序代码   │         │   内存单元   │
│  逻辑地址    │  ──>   │  物理地址    │
│  0x0000     │  映射   │  0x1000     │
│  0x0001     │         │  0x1001     │
│  0x0002     │         │  0x1002     │
└─────────────┘         └─────────────┘
```

#### 地址转换的两种方式

| 方式 | 时机 | 特点 | 类比 |
| --- | --- | --- | --- |
| 静态重定位 | 程序装入时一次性转换 | 程序不能移动，简单但不灵活 | 搬家前就把所有地址改好 |
| 动态重定位 | 程序执行时每次访问都转换 | 程序可以移动，需要 MMU 硬件支持 | 每次寄信都查 forwarding address |

```
CPU ──逻辑地址──> MMU ──物理地址──> 内存
       ↑
   基址寄存器
```

::: tip
现代操作系统几乎都采用动态重定位方式，因为它允许程序在内存中移动，提高了内存利用率。MMU（Memory Management Unit）是 CPU 里的一块专用硬件，专门干地址转换的活。
:::

### 二、连续分配方式

连续分配是最早的内存管理方式，每个进程占用一段连续的内存空间。

#### 1. 单一连续分配

最早期的方式，内存分为系统区和用户区，同一时间只能跑一个用户程序。

```
┌─────────────────┐ 0KB
│   操作系统       │
├─────────────────┤ 128KB
│                 │
│   用户进程      │
│                 │
└─────────────────┘ 1MB
```

::: info
这种方式的缺点很明显：同一时间只能运行一个用户程序，内存利用率极低。就像一个大教室只让一个学生用，太浪费了。
:::

#### 2. 固定分区分配

把用户空间切成若干固定大小的分区，每个分区可以装一个作业。

```
┌─────────────────┐
│   操作系统       │
├─────────────────┤
│  分区 1 (64KB)  │ <-- 进程 A
├─────────────────┤
│  分区 2 (128KB) │ <-- 进程 B
├─────────────────┤
│  分区 3 (256KB) │ <-- 进程 C
├─────────────────┤
│  分区 4 (512KB) │ <-- 空闲
└─────────────────┘
```

**生活类比**：就像停车场划了固定大小的车位。大车停大车位没问题，但小车停大车位就浪费了（内部碎片）。而且如果车比最大的车位还大，那就停不下了。

**优点**：实现简单，支持多道程序设计

**缺点**：
- 内部碎片：进程小于分区时，剩余空间浪费
- 分区大小不灵活：可能无法装入大进程

#### 3. 动态分区分配

根据进程的实际大小来分配，不再预先划分固定分区。

```
初始状态：
┌─────────────────┐
│   操作系统       │
├─────────────────┤
│                 │
│   空闲区       │
│   (800KB)       │
│                 │
└─────────────────┘

分配 100KB 给进程 A 后：
┌─────────────────┐
│   操作系统       │
├─────────────────┤
│  进程 A (100KB) │
├─────────────────┤
│                 │
│   空闲区       │
│   (700KB)       │
│                 │
└─────────────────┘
```

**生活类比**：不再划固定车位了，来多大的车就给多大的位置。但问题是车开走后留下的空位可能不大不小，后来的车停不进去（外部碎片）。

### 三、动态分区分配算法

当有多个进程需要分配内存时，该选哪个空闲区？这就是分配算法要解决的问题。

| 算法 | 策略 | 优点 | 缺点 | 类比 |
| --- | --- | --- | --- | --- |
| 首次适应（FF） | 从低地址开始找第一个够大的空闲区 | 简单，保留高地址大空闲区 | 低地址碎片多 | 找餐厅：去最近的那家 |
| 最佳适应（BF） | 找最小的够大的空闲区 | 保留大空闲区 | 产生大量小碎片 | 找餐厅：找刚好够用的最小那家 |
| 最坏适应（WF） | 找最大的空闲区 | 减少小碎片 | 破坏大空闲区 | 找餐厅：去最大的那家 |
| 循环首次适应（NFF） | 从上次分配位置继续查找 | 分配均匀 | 难以利用大空闲区 | 找餐厅：轮流去不同的 |

::: tip
首次适应算法在实际应用中效果最好，因为它既简单又能保留高地址的大空闲区。这也是为什么很多实际系统选择它的原因。
:::

### 四、分页存储管理

分页管理是解决外部碎片问题的关键方案。

**核心思想**：把内存切成固定大小的块（页框），把程序也切成同样大小的块（页）。这样就不需要连续的空间了。

**生活类比**：就像把一本书拆成固定大小的章节，这些章节不需要按顺序放在书架上，只要有个目录（页表）记录每章放在哪就行。

#### 基本概念

- **页（Page）**：用户程序的逻辑单位，大小固定（通常 4KB）
- **页框（Page Frame）**：物理内存的单位，大小与页相同
- **页表（Page Table）**：记录页与页框的对应关系

```
逻辑地址空间              物理内存空间
┌─────────────┐          ┌─────────────┐
│  页 0       │ ───────> │  页框 2     │
├─────────────┤          ├─────────────┤
│  页 1       │ ───────> │  页框 0     │
├─────────────┤          ├─────────────┤
│  页 2       │ ───────> │  页框 3     │
├─────────────┤          ├─────────────┤
│  页 3       │ ───────> │  页框 1     │
└─────────────┘          └─────────────┘
```

#### 地址转换过程

逻辑地址被拆成两部分：

```
逻辑地址（32位）：
┌──────────────┬──────────────┐
│   页号 (20)  │  偏移 (12)   │
└──────────────┴──────────────┘
         ↓              ↓
    查页表得到       直接拼接
    页框号
         ↓              ↓
物理地址（32位）：
┌──────────────┬──────────────┐
│  页框号 (20) │  偏移 (12)   │
└──────────────┴──────────────┘
```

#### 计算示例

假设页大小为 4KB（2^12 = 4096 字节），页内偏移占 12 位。

| 页号 | 页框号 |
| --- | --- |
| 0 | 2 |
| 1 | 0 |
| 2 | 3 |
| 3 | 1 |

逻辑地址 0x1234 的转换：
- 页号 = 0x1234 >> 12 = 1
- 偏移 = 0x1234 & 0xFFF = 0x234
- 查页表：页 1 --> 页框 0
- 物理地址 = (0 << 12) | 0x234 = 0x0234

::: info
分页管理消除了外部碎片，但可能存在内部碎片（最后一页没装满就浪费了）。不过平均每个进程只浪费半个页框，通常不到 2KB，可以接受。
:::

#### 快表（TLB）

页表存在内存里，每次访问内存都要先查页表，等于多了一次内存访问。**快表（TLB）** 就是一块高速缓存，把最近用过的页表项存在里面。

```
CPU ──逻辑地址──> TLB ──命中──> 物理地址
                    │
                    └──未命中──> 查页表 ──> 物理地址
                                      ↓
                                   更新 TLB
```

**生活类比**：TLB 就像你手机里的常用联系人。打电话时先翻常用联系人（TLB），找到了就直接拨号；找不到再翻完整通讯录（页表），找到后加到常用联系人里。

### 五、分段存储管理

分页是按"大小"切分程序，分段是按"逻辑功能"切分程序。

**生活类比**：分页像是把一栋大楼按楼层编号（每层一样大），分段像是按功能分区（办公区、仓储区、休息区，每个区大小不同）。

#### 基本概念

- **段（Segment）**：具有完整逻辑意义的信息单元（如代码段、数据段、栈段）
- **段表（Segment Table）**：记录每个段的起始地址和长度

```
逻辑地址（32位）：
┌──────────────┬──────────────┐
│   段号 (16)  │  段内偏移 (16)│
└──────────────┴──────────────┘
         ↓              ↓
    查段表得到       检查是否
    段起始地址       越界
         ↓              ↓
物理地址 = 段起始地址 + 段内偏移
```

#### 计算示例

| 段号 | 段名 | 起始地址 | 长度 |
| --- | --- | --- | --- |
| 0 | 代码段 | 0x1000 | 2048 |
| 1 | 数据段 | 0x3000 | 1024 |
| 2 | 栈段 | 0x5000 | 512 |

访问逻辑地址 (1, 500)：
- 段号 = 1，查段表：起始地址 0x3000，长度 1024
- 偏移 500 < 1024，未越界
- 物理地址 = 0x3000 + 500 = 0x31F4

### 六、段页式存储管理

段页式结合了两者的优点：先分段，再在段内分页。

```
逻辑地址：
┌──────────┬──────────┬──────────┐
│  段号    │   页号   │  页内偏移 │
└──────────┴──────────┴──────────┘
    ↓           ↓           ↓
  查段表     查页表      直接拼接
    ↓           ↓           ↓
  得到页表   得到页框号   物理地址
  起始地址
```

::: tip
段页式管理既保留了分段的逻辑组织优点（按功能分块，方便共享和保护），又避免了分段的外部碎片问题（段内分页，不需要连续空间）。这是现代操作系统常用的方案。
:::

## 基础用法：地址转换计算

### 分页地址转换示例

```
// 已知条件：
// 页大小 = 4KB = 2^12 = 4096 字节
// 页内偏移占 12 位
// 页表如下：

// 页号  -->  页框号
//   0   -->    5
//   1   -->    3
//   2   -->    7
//   3   -->    1

// 题目：求逻辑地址 0x1A5C 对应的物理地址

// 第一步：拆分逻辑地址
// 0x1A5C = 0001 1010 0101 1100 (二进制)
// 页号 = 高 4 位 = 0001 = 1     -- 正确写法：用右移运算
// 偏移 = 低 12 位 = 1010 0101 1100 = 0xA5C  -- 正确写法：用掩码运算

// 第二步：查页表
// 页号 1 --> 页框号 3

// 第三步：拼接物理地址
// 物理地址 = (页框号 << 12) | 偏移
//          = (3 << 12) | 0xA5C
//          = 0x3000 | 0xA5C
//          = 0x3A5C

// 错误写法：直接把逻辑地址当物理地址用
// 物理地址 != 0x1A5C  -- 错误！逻辑地址不等于物理地址

// 错误写法：页号和偏移搞反了
// 页号 != 0xA5C，偏移 != 1  -- 错误！高位是页号，低位是偏移
```

### 分段地址转换示例

```
// 已知段表：
// 段号  段名    起始地址   长度
//  0   代码段   0x1000    2048
//  1   数据段   0x3000    1024
//  2   栈段    0x5000     512

// 题目：求逻辑地址 (段号=1, 偏移=800) 的物理地址

// 第一步：查段表
// 段号 1 --> 起始地址 0x3000，长度 1024

// 第二步：越界检查
// 偏移 800 < 长度 1024，合法     -- 正确：必须先检查越界
// 物理地址 = 0x3000 + 800 = 0x3320

// 错误写法：不做越界检查直接相加
// 如果偏移 = 2000 > 1024，直接相加会访问到其他段的数据  -- 错误！

// 错误写法：用段号当页号去查页表
// 段表和页表是两个不同的东西  -- 错误！不能混用
```

## 新手常见误区

### 误区一：逻辑地址就是物理地址

**错误理解**：程序里用的地址就是内存条上的真实地址。

**为什么错**：逻辑地址是程序"以为"的地址，物理地址是"实际"的地址。两者通过地址转换机制映射，通常不相等。

**正确做法**：理解 CPU 发出的是逻辑地址，经过 MMU 转换后才变成物理地址去访问内存。

### 误区二：分页和分段是一样的

**错误理解**：分页和分段都是把程序切块，没什么区别。

**为什么错**：分页是按固定大小切分，对用户透明，目的是消除外部碎片；分段是按逻辑功能切分，大小可变，用户可见，目的是方便共享和保护。

**正确做法**：记住分页是"系统视角"的切分（为了高效管理），分段是"用户视角"的切分（为了逻辑清晰）。

### 误区三：分页会产生外部碎片

**错误理解**：分页管理会产生外部碎片。

**为什么错**：分页管理产生的是内部碎片（最后一页没装满），不是外部碎片。因为每个页框大小固定，不存在"太小而无法利用"的空闲块。

**正确做法**：分页消除外部碎片，产生内部碎片；分段产生外部碎片，不产生内部碎片。

### 误区四：最佳适应算法是最好的

**错误理解**：最佳适应（BF）每次选最合适的，应该是最好的算法。

**为什么错**：BF 虽然保留了大空闲区，但每次都会切出很小的碎片，这些碎片几乎无法利用，反而浪费了。

**正确做法**：首次适应（FF）在实际中效果最好，因为它简单且能保留高地址的大空闲区。

### 误区五：TLB 可以替代页表

**错误理解**：有了 TLB 就不需要页表了。

**为什么错**：TLB 容量很小（通常只有几十到几百项），只能缓存最近用过的页表项。TLB 未命中时还是得查内存中的页表。

**正确做法**：TLB 是页表的加速器，不是替代品。两者配合工作：TLB 命中直接返回，未命中查页表并更新 TLB。

**解题过程**：

1. 页大小为 1KB = 2^10，页内偏移占 10 位
2. 逻辑地址 0x08AB = 0000 1000 1010 1011
3. 页号 = 0x08AB >> 10 = 2
4. 偏移 = 0x08AB & 0x3FF = 0x0AB
5. 查页表：页号 2 --> 页框号 2
6. 物理地址 = (2 << 10) | 0x0AB = 0x800 | 0x0AB = 0x8AB

**答案：物理地址为 0x8AB**

### 练习三（挑战）：段页式地址转换

已知系统参数：
- 段表如下：

| 段号 | 页表起始地址 | 页表长度 |
| --- | --- | --- |
| 0 | 0x2000 | 4 |
| 1 | 0x3000 | 3 |
| 2 | 0x4000 | 2 |

- 段 1 的页表如下（页大小 4KB）：

| 页号 | 页框号 |
| --- | --- |
| 0 | 6 |
| 1 | 10 |
| 2 | 3 |

求逻辑地址 (段号=1, 页号=2, 偏移=0x500) 的物理地址。

<details>
<summary>点击查看答案</summary>

**解题过程**：

1. 根据段号 1，查段表：页表起始地址 = 0x3000，页表长度 = 3
2. 检查页号 2 < 页表长度 3，合法
3. 查段 1 的页表：页号 2 --> 页框号 3
4. 物理地址 = (页框号 << 12) | 偏移 = (3 << 12) | 0x500 = 0x3000 | 0x500 = 0x3500

**答案：物理地址为 0x3500**

注意：段页式的地址转换需要三次查表（段表 --> 页表 --> 物理地址），所以实际系统中会用 TLB 来加速。

</details>
