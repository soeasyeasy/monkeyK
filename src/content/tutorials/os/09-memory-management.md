# 第九章：内存管理基础

## 什么是内存管理

内存管理是操作系统最重要的功能之一。它负责跟踪内存使用情况，决定哪些进程可以获得内存，以及何时分配和回收内存。

| 功能 | 说明 |
| --- | --- |
| 内存分配 | 为进程分配所需的内存空间 |
| 内存保护 | 防止进程访问未授权的内存区域 |
| 地址映射 | 将逻辑地址转换为物理地址 |
| 内存共享 | 允许多个进程共享同一内存区域 |
| 内存扩充 | 通过虚拟内存技术扩展可用内存 |

## 逻辑地址与物理地址

### 基本概念

**逻辑地址（Logical Address）**：程序编译后产生的地址，也称为相对地址或虚拟地址。程序员看到的是逻辑地址。

**物理地址（Physical Address）**：内存单元的实际地址，也称为绝对地址。硬件看到的是物理地址。

```
┌─────────────┐         ┌─────────────┐
│   程序代码   │         │   内存单元   │
│  逻辑地址    │  ──>   │  物理地址    │
│  0x0000     │  映射   │  0x1000     │
│  0x0001     │         │  0x1001     │
│  0x0002     │         │  0x1002     │
└─────────────┘         └─────────────┘
```

### 地址转换方式

**静态重定位**：在程序装入内存时一次性完成地址转换。程序一旦装入，就不能移动。

**动态重定位**：在程序执行期间进行地址转换。每次访问内存时都需要转换地址，通常由硬件（MMU）完成。

```
CPU ──逻辑地址──> MMU ──物理地址──> 内存
       ↑
   基址寄存器
```

::: tip
现代操作系统几乎都采用动态重定位方式，因为它允许程序在内存中移动，提高了内存利用率。
:::

## 连续分配方式

连续分配是最简单的内存管理方式，每个进程占用连续的内存空间。

### 单一连续分配

最早期的内存管理方式，内存分为两部分：
- **系统区**：供操作系统使用，通常位于低地址部分
- **用户区**：供用户进程使用

```
┌─────────────────┐ 0KB
│   操作系统       │
├─────────────────┤ 128KB
│                 │
│   用户进程      │
│                 │
└─────────────────┘ 1MB
```

::: info
单一连续分配的缺点是同一时间只能运行一个用户程序，内存利用率极低。
:::

### 固定分区分配

将用户空间划分为若干个固定大小的分区，每个分区可以装入一个作业。

```
┌─────────────────┐
│   操作系统       │
├─────────────────┤
│  分区 1 (64KB)  │ ← 进程 A
├─────────────────┤
│  分区 2 (128KB) │ ← 进程 B
├─────────────────┤
│  分区 3 (256KB) │ ← 进程 C
├─────────────────┤
│  分区 4 (512KB) │ ← 空闲
└─────────────────┘
```

**优点**：实现简单，支持多道程序设计

**缺点**：
- 内部碎片：进程小于分区时，剩余空间浪费
- 分区大小不灵活：可能无法装入大进程

### 动态分区分配

根据进程的实际需要，动态地分配内存空间。分区大小与进程大小相匹配。

```
初始状态：
┌─────────────────┐
│   操作系统       │
├─────────────────┤
│                 │
│   空闲区       │
│   (800KB)       │
│                 │
└─────────────────┘

分配 100KB 给进程 A 后：
┌─────────────────┐
│   操作系统       │
├─────────────────┤
│  进程 A (100KB) │
├─────────────────┤
│                 │
│   空闲区       │
│   (700KB)       │
│                 │
└─────────────────┘
```

### 动态分区分配算法

| 算法 | 策略 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 首次适应（FF） | 从低地址开始找第一个够大的空闲区 | 简单，保留高地址大空闲区 | 低地址碎片多 |
| 最佳适应（BF） | 找最小的够大的空闲区 | 保留大空闲区 | 产生大量小碎片 |
| 最坏适应（WF） | 找最大的空闲区 | 减少小碎片 | 破坏大空闲区 |
| 循环首次适应（NFF） | 从上次分配位置继续查找 | 分配均匀 | 难以利用大空闲区 |

::: tip
首次适应算法在实际应用中效果最好，因为它既简单又能保留高地址的大空闲区。
:::

## 分页存储管理

分页存储管理将内存划分为固定大小的块（页框），将程序划分为同样大小的块（页）。

### 基本概念

- **页（Page）**：用户程序的逻辑单位，大小固定（通常 4KB）
- **页框（Page Frame）**：物理内存的单位，大小与页相同
- **页表（Page Table）**：记录页与页框的对应关系

```
逻辑地址空间              物理内存空间
┌─────────────┐          ┌─────────────┐
│  页 0       │ ───────> │  页框 2     │
├─────────────┤          ├─────────────┤
│  页 1       │ ───────> │  页框 0     │
├─────────────┤          ├─────────────┤
│  页 2       │ ───────> │  页框 3     │
├─────────────┤          ├─────────────┤
│  页 3       │ ───────> │  页框 1     │
└─────────────┘          └─────────────┘
```

### 地址转换

逻辑地址由两部分组成：
- **页号（Page Number）**：高 n 位
- **页内偏移（Offset）**：低 m 位

```
逻辑地址（32位）：
┌──────────────┬──────────────┐
│   页号 (20)  │  偏移 (12)   │
└──────────────┴──────────────┘
         ↓              ↓
    查页表得到       直接拼接
    页框号
         ↓              ↓
物理地址（32位）：
┌──────────────┬──────────────┐
│  页框号 (20) │  偏移 (12)   │
└──────────────┴──────────────┘
```

### 页表示例

假设页大小为 4KB（2^12 = 4096 字节），页内偏移占 12 位。

| 页号 | 页框号 |
| --- | --- |
| 0 | 2 |
| 1 | 0 |
| 2 | 3 |
| 3 | 1 |

逻辑地址 0x1234 的转换：
- 页号 = 0x1234 >> 12 = 1
- 偏移 = 0x1234 & 0xFFF = 0x234
- 查页表：页 1 → 页框 0
- 物理地址 = (0 << 12) | 0x234 = 0x0234

::: info
分页管理消除了外部碎片，但可能存在内部碎片（最后一页未用满）。
:::

### 快表（TLB）

页表存储在内存中，每次访问内存都需要先查页表，效率较低。**快表（Translation Lookaside Buffer, TLB）** 是一种高速缓存，用于加速地址转换。

```
CPU ──逻辑地址──> TLB ──命中──> 物理地址
                    │
                    └──未命中──> 查页表 ──> 物理地址
                                      ↓
                                   更新 TLB
```

## 分段存储管理

分段存储管理将程序按照逻辑结构划分为若干个段，每个段有独立的名称和长度。

### 基本概念

- **段（Segment）**：具有完整逻辑意义的信息单元（如代码段、数据段、栈段）
- **段表（Segment Table）**：记录每个段的起始地址和长度

```
逻辑地址（32位）：
┌──────────────┬──────────────┐
│   段号 (16)  │  段内偏移 (16)│
└──────────────┴──────────────┘
         ↓              ↓
    查段表得到       检查是否
    段起始地址       越界
         ↓              ↓
物理地址 = 段起始地址 + 段内偏移
```

### 段表示例

| 段号 | 段名 | 起始地址 | 长度 |
| --- | --- | --- | --- |
| 0 | 代码段 | 0x1000 | 2048 |
| 1 | 数据段 | 0x3000 | 1024 |
| 2 | 栈段 | 0x5000 | 512 |

访问逻辑地址 (1, 500)：
- 段号 = 1，查段表：起始地址 0x3000，长度 1024
- 偏移 500 < 1024，未越界
- 物理地址 = 0x3000 + 500 = 0x31F4

### 分段与分页的比较

| 特性 | 分页 | 分段 |
| --- | --- | --- |
| 单位大小 | 固定 | 可变 |
| 用户可见性 | 对用户透明 | 用户可见 |
| 目的 | 减少外部碎片 | 逻辑组织、共享保护 |
| 地址空间 | 一维 | 二维 |
| 碎片 | 内部碎片 | 外部碎片 |

## 段页式存储管理

段页式结合了两者的优点：先分段，再在段内分页。

```
逻辑地址：
┌──────────┬──────────┬──────────┐
│  段号    │   页号   │  页内偏移 │
└──────────┴──────────┴──────────┘
    ↓           ↓           ↓
  查段表     查页表      直接拼接
    ↓           ↓           ↓
  得到页表   得到页框号   物理地址
  起始地址
```

::: tip
段页式管理既保留了分段的逻辑组织优点，又避免了分段的外部碎片问题，是现代操作系统常用的方案。
:::

## 本章小结

- 逻辑地址是程序看到的地址，物理地址是内存实际地址，需要通过地址转换机制映射
- 连续分配方式包括单一连续、固定分区和动态分区，存在碎片问题
- 分页管理将内存划分为固定大小的页框，消除了外部碎片
- 分段管理按逻辑结构划分程序，便于共享和保护
- 段页式结合两者优点，是现代操作系统的常用方案
