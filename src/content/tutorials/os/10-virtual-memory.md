# 第十章：虚拟内存

## 虚拟内存的概念

虚拟内存是操作系统提供的一种内存管理技术，它让程序认为拥有连续的可用内存（虚拟地址空间），实际上物理内存可能远小于虚拟地址空间。

### 核心思想

- **局部性原理**：程序在一段时间内只访问部分内存区域
  - 时间局部性：刚被访问的内存很快会被再次访问
  - 空间局部性：刚被访问的内存附近区域很可能被访问
- **按需调页**：只将当前需要的页面调入内存，其他页面留在磁盘

```
虚拟地址空间（4GB）        物理内存（2GB）
┌─────────────┐           ┌─────────────┐
│  代码段      │           │  当前需要的  │
│  0x0000     │           │  页面        │
├─────────────┤           │             │
│  数据段      │  ──映射─> ├─────────────┤
│  0x4000     │           │  未使用的    │
├─────────────┤           │  页框        │
│  堆         │           │             │
│  0x8000     │           └─────────────┘
├─────────────┤
│  栈         │           磁盘（交换空间）
│  0xC000     │           ┌─────────────┐
└─────────────┘           │  未使用的    │
                          │  页面        │
                          └─────────────┘
```

### 虚拟内存的优点

| 优点 | 说明 |
| --- | --- |
| 程序更大 | 程序可以超过物理内存大小 |
| 多道编程 | 更多进程可以同时驻留内存 |
| 减少 I/O | 减少换入换出次数 |
| 共享内存 | 进程间可以共享虚拟页面 |
| 简化编程 | 程序员无需关心物理内存限制 |

::: tip
虚拟内存并不是真正的内存，而是一种抽象概念。它让每个进程都认为自己独占整个地址空间。
:::

## 请求分页

请求分页是在分页系统基础上，增加了请求调页和页面置换功能。

### 工作原理

1. **页面调入**：当访问的页面不在内存时，触发缺页中断，从磁盘调入
2. **页面调出**：当内存满时，选择某些页面换出到磁盘
3. **页面置换**：决定哪个页面被换出的算法

```
CPU 访问内存 ──> 页表检查 ──> 在内存？
                              │
                    ┌─────────┴─────────┐
                    ↓                   ↓
                   是                  否
                    │                   │
                    ↓                   ↓
              直接访问            缺页中断
                                    │
                                    ↓
                              从磁盘调入
                                    │
                                    ↓
                              更新页表
                                    │
                                    ↓
                              访问内存
```

### 页表项结构

请求分页的页表项包含以下信息：

| 字段 | 说明 |
| --- | --- |
| 页号 | 逻辑页号 |
| 页框号 | 对应的物理页框号 |
| 存在位（P） | 页面是否在内存中 |
| 访问位（A） | 页面是否被访问过 |
| 修改位（M） | 页面是否被修改过 |
| 外存地址 | 页面在磁盘上的位置 |

```
页表项（32位）：
┌────────┬────────┬────────┬────────┬────────┐
│ 页号   │ 页框号 │ 存在位 │ 访问位 │ 修改位 │
│ (20)   │ (10)   │ (1)    │ (1)    │ (1)    │
└────────┴────────┴────────┴────────┴────────┘
```

### 缺页中断处理

当访问的页面不在内存时，硬件会触发缺页中断，操作系统执行以下步骤：

1. 保存 CPU 现场
2. 分析中断原因，确定缺失页面
3. 检查磁盘上是否有该页面
4. 检查内存是否有空闲页框
   - 有：直接调入
   - 无：执行页面置换算法，选择一个页面换出
5. 从磁盘读取页面到内存
6. 更新页表
7. 恢复 CPU 现场，重新执行被中断的指令

::: info
缺页中断是操作系统中处理最频繁的中断之一，其处理效率直接影响系统性能。
:::

## 页面置换算法

当内存已满且需要调入新页面时，需要选择一个页面换出。不同的算法有不同的策略。

### 最佳置换算法（OPT）

**策略**：换出将来最长时间不会被访问的页面

**特点**：
- 理论上的最优算法
- 无法在实际中实现（需要预测未来）
- 用于评估其他算法的性能

```
访问序列：7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2
内存容量：3 个页框

初始状态：[_, _, _]
访问 7：[7, _, _]
访问 0：[7, 0, _]
访问 1：[7, 0, 1]
访问 2：[2, 0, 1]  ← 换出 7（将来最晚使用）
访问 0：[2, 0, 1]  ← 命中
访问 3：[2, 0, 3]  ← 换出 1（将来最晚使用）
...
```

### 先进先出算法（FIFO）

**策略**：换出最早进入内存的页面

**特点**：
- 实现简单
- 性能较差
- 可能出现 Belady 异常（增加内存反而缺页率上升）

```
访问序列：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
内存容量：3 个页框

初始：[_, _, _]
1：[1, _, _]
2：[1, 2, _]
3：[1, 2, 3]
4：[4, 2, 3]  ← 换出 1（最先进入）
1：[4, 1, 3]  ← 换出 2
2：[4, 1, 2]  ← 换出 3
5：[5, 1, 2]  ← 换出 4
...
```

::: warning
FIFO 算法可能出现 Belady 异常：当分配给进程的物理块数增加时，缺页次数反而增加。这是该算法的主要缺陷。
:::

### 最近最久未使用算法（LRU）

**策略**：换出最近最长时间没有被访问的页面

**特点**：
- 性能接近 OPT
- 实现成本较高
- 是实际应用中最常用的算法之一

```
访问序列：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
内存容量：3 个页框

初始：[_, _, _]
1：[1, _, _]
2：[1, 2, _]
3：[1, 2, 3]
4：[4, 2, 3]  ← 换出 1（最久未使用）
1：[4, 1, 3]  ← 换出 2
2：[4, 1, 2]  ← 换出 3
5：[5, 1, 2]  ← 换出 4
...
```

**实现方式**：
- **计数器**：为每个页表项添加访问计数器，每次访问时更新。需要搜索所有页表项，效率低。
- **栈**：使用栈保存页面访问顺序，栈顶是最近访问的。需要维护栈结构，开销大。

### 时钟算法（Clock）

时钟算法是 LRU 的近似实现，也称为二次机会算法。

**策略**：
1. 为每个页面设置一个访问位
2. 页面按环形链表组织，指针指向最老的页面
3. 需要置换时，检查指针指向的页面
   - 访问位为 0：换出该页面
   - 访问位为 1：将访问位置 0，指针移动到下一个页面

```
页面链表（环形）：
    ┌───┐   ┌───┐   ┌───┐   ┌───┐
    │ A │──>│ B │──>│ C │──>│ D │──┐
    │1  │   │0  │   │1  │   │1  │  │
    └───┘   └───┘   └───┘   └───┘  │
      ↑                             │
      └─────────────────────────────┘
      指针指向 A

需要置换时：
1. 检查 A：访问位为 1，置为 0，指针移到 B
2. 检查 B：访问位为 0，换出 B
```

**改进的时钟算法**：
同时考虑访问位和修改位，优先换出未修改的页面（减少写回磁盘的开销）。

| 访问位 | 修改位 | 优先级 |
| --- | --- | --- |
| 0 | 0 | 最高（直接换出） |
| 0 | 1 | 次高（需要写回） |
| 1 | 0 | 次低（给一次机会） |
| 1 | 1 | 最低（给一次机会） |

### 页面置换算法比较

| 算法 | 缺页率 | 实现复杂度 | 是否 Belady 异常 |
| --- | --- | --- | --- |
| OPT | 最低 | 无法实现 | 否 |
| FIFO | 较高 | 简单 | 是 |
| LRU | 接近 OPT | 中等 | 否 |
| Clock | 接近 LRU | 简单 | 否 |

::: tip
Linux 系统使用的是改进的时钟算法（二次机会算法的变体），它在性能和实现复杂度之间取得了良好的平衡。
:::

## 抖动与工作集

### 抖动（Thrashing）

当系统频繁地进行页面置换，导致 CPU 利用率急剧下降的现象称为抖动。

**原因**：
- 分配给进程的物理块数太少
- 页面置换算法不合理
- 多道程序度过高

```
CPU 利用率
    ↑
    │        ╱╲
    │       ╱  ╲
    │      ╱    ╲
    │     ╱      ╲
    │    ╱        ╲
    │   ╱          ╲
    │  ╱            ╲
    │ ╱              ╲
    │╱________________╲___→ 多道程序度
         最佳点
```

### 工作集模型

**工作集**：在某段时间间隔内，进程实际访问的页面集合。

**工作集模型**：根据进程的工作集大小动态调整分配给进程的物理块数。

```
时间窗口：Δt
工作集：WSS(t) = 在 [t-Δt, t] 时间内访问的页面集合

如果 WSS > 可用内存：
  - 挂起某些进程
  - 减少多道程序度

如果 WSS < 可用内存：
  - 可以加载更多进程
  - 增加多道程序度
```

::: info
工作集模型的核心思想是：为每个进程分配足够的物理块，使其工作集能够驻留在内存中，从而避免抖动。
:::

## 本章小结

- 虚拟内存通过局部性原理和按需调页，让程序可以使用比物理内存更大的地址空间
- 请求分页在分页系统基础上增加了请求调页和页面置换功能
- 缺页中断是虚拟内存的核心机制，处理效率影响系统性能
- 页面置换算法包括 OPT、FIFO、LRU、Clock 等，各有优缺点
- 抖动是系统频繁置换导致性能下降的现象，工作集模型可以预防抖动
