# 第十章：虚拟内存

## 本章导读

在开始学习之前，你可能会有这些疑问：

1. **物理内存不够用了怎么办？** -- 程序比内存大也能运行？这到底是怎么做到的？
2. **操作系统是怎么"变"出更多内存的？** -- 虚拟内存并不是真正的内存，那它是什么？
3. **页面置换算法那么多，到底该用哪个？** -- OPT、FIFO、LRU、Clock 各自适合什么场景？
4. **为什么电脑有时候会突然变卡？** -- 这很可能和"抖动"有关，本章会解释清楚。

本章我们就来解决这些问题，帮你理解虚拟内存这个操作系统中最精妙的设计之一。

## 为什么需要虚拟内存

### 没有虚拟内存会怎样

想象一下，你搬进了一间只有 20 平米的小房间（物理内存），但你的家当有一整个仓库那么多（程序需要的内存）。没有虚拟内存的话，你只能：

- 把所有家当都塞进 20 平米，塞不下就扔掉（程序无法运行）
- 每次只拿一部分进来，用完再换（手动管理，极其麻烦）

有了虚拟内存，就像给你配了一个"智能管家"：

- 管家告诉你"你的房间有 4GB 大"（虚拟地址空间），你随便放
- 实际上管家在背后帮你把暂时不用的东西放到地下室（磁盘）
- 需要的时候再帮你取回来（页面置换）

### 虚拟内存的核心思想

虚拟内存建立在两个关键原理之上：

**局部性原理**：程序在一段时间内只访问一小部分内存区域。

- 时间局部性：刚被访问的数据很快会被再次访问（比如循环里的变量）
- 空间局部性：刚被访问的数据附近的数据很可能被访问（比如数组遍历）

**生活类比**：你在图书馆写论文，桌上只放当前在看的几本书（内存），其他书放在书架上（磁盘）。因为你知道接下来大概率还是看这几本书（局部性），所以不需要把所有书都搬上桌。

**按需调页**：只把当前需要的页面放进内存，其他页面留在磁盘上。

```
虚拟地址空间（4GB）        物理内存（2GB）
┌─────────────┐           ┌─────────────┐
│  代码段      │           │  当前需要的  │
│  0x0000     │           │  页面        │
├─────────────┤           │             │
│  数据段      │  ──映射─> ├─────────────┤
│  0x4000     │           │  未使用的    │
├─────────────┤           │  页框        │
│  堆         │           │             │
│  0x8000     │           └─────────────┘
├─────────────┤
│  栈         │           磁盘（交换空间）
│  0xC000     │           ┌─────────────┐
└─────────────┘           │  未使用的    │
                          │  页面        │
                          └─────────────┘
```

### 虚拟内存的优点

| 优点 | 说明 | 类比 |
| --- | --- | --- |
| 程序更大 | 程序可以超过物理内存大小 | 小房间通过地下室扩容 |
| 多道编程 | 更多进程可以同时驻留内存 | 更多人共用图书馆 |
| 减少 I/O | 减少换入换出次数 | 减少跑地下室的次数 |
| 共享内存 | 进程间可以共享虚拟页面 | 多人共用同一本参考书 |
| 简化编程 | 程序员无需关心物理内存限制 | 你不用管管家怎么搬东西 |

::: tip
虚拟内存并不是真正的内存，而是一种抽象概念。它让每个进程都认为自己独占了整个地址空间，实际上操作系统在背后做了大量的调度和管理工作。
:::

## 核心原理讲解

### 一、请求分页

请求分页是在普通分页系统的基础上，增加了"请求调页"和"页面置换"两个功能。

**生活类比**：普通分页就像把所有书都搬到桌上（内存），不管你看没看到。请求分页则是"看到哪本搬哪本"，桌上放不下了就把暂时不看的放回书架。

#### 工作原理

```
CPU 访问内存 ──> 页表检查 ──> 在内存？
                              │
                    ┌─────────┴─────────┐
                    ↓                   ↓
                   是                  否
                    │                   │
                    ↓                   ↓
              直接访问            缺页中断
                                    │
                                    ↓
                              从磁盘调入
                                    │
                                    ↓
                              更新页表
                                    │
                                    ↓
                              访问内存
```

#### 页表项结构

请求分页的页表项比普通分页多了几个关键字段：

| 字段 | 说明 | 作用 |
| --- | --- | --- |
| 页号 | 逻辑页号 | 标识页面 |
| 页框号 | 对应的物理页框号 | 定位物理地址 |
| 存在位（P） | 页面是否在内存中 | 判断是否缺页 |
| 访问位（A） | 页面是否被访问过 | 用于置换算法 |
| 修改位（M） | 页面是否被修改过 | 决定是否需要写回磁盘 |
| 外存地址 | 页面在磁盘上的位置 | 缺页时从磁盘调入 |

```
页表项（32位）：
┌────────┬────────┬────────┬────────┬────────┐
│ 页号   │ 页框号 │ 存在位 │ 访问位 │ 修改位 │
│ (20)   │ (10)   │ (1)    │ (1)    │ (1)    │
└────────┴────────┴────────┴────────┴────────┘
```

#### 缺页中断处理

当访问的页面不在内存时，硬件触发缺页中断，操作系统执行以下步骤：

1. 保存 CPU 现场
2. 分析中断原因，确定缺失页面
3. 检查磁盘上是否有该页面
4. 检查内存是否有空闲页框
   - 有：直接调入
   - 无：执行页面置换算法，选择一个页面换出
5. 从磁盘读取页面到内存
6. 更新页表
7. 恢复 CPU 现场，重新执行被中断的指令

::: info
缺页中断是操作系统中处理最频繁的中断之一，其处理效率直接影响系统性能。一次缺页中断可能需要几毫秒（磁盘访问），而正常内存访问只需要几十纳秒，差距达到十万倍。
:::

### 二、页面置换算法

当内存已满且需要调入新页面时，必须选择一个"牺牲者"换出。不同的算法有不同的选择策略。

#### 1. 最佳置换算法（OPT）

**策略**：换出将来最长时间不会被访问的页面。

**生活类比**：你要清理书架空间，最优策略是把接下来最长时间不会看的书放回地下室。但问题是，你怎么知道未来不会看哪本书？

**特点**：
- 理论上的最优算法
- 无法在实际中实现（需要预测未来）
- 用于评估其他算法的性能

```
访问序列：7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2
内存容量：3 个页框

初始状态：[_, _, _]
访问 7：[7, _, _]         -- 缺页
访问 0：[7, 0, _]         -- 缺页
访问 1：[7, 0, 1]         -- 缺页
访问 2：[2, 0, 1]         -- 换出 7（7 将来最晚使用：7在第13步才出现，0在第6步，1在第14步...等等，看后面序列）
访问 0：[2, 0, 1]         -- 命中
访问 3：[2, 0, 3]         -- 换出 1（1 在将来第14步才出现，0在第7步，2在第9步）
...
```

#### 2. 先进先出算法（FIFO）

**策略**：换出最早进入内存的页面（谁先来谁先走）。

**生活类比**：书架满了，把最早放上去的书拿走，不管你还看不看。

```
访问序列：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
内存容量：3 个页框

初始：[_, _, _]
1：[1, _, _]              -- 缺页
2：[1, 2, _]              -- 缺页
3：[1, 2, 3]              -- 缺页
4：[4, 2, 3]              -- 换出 1（最先进入）  -- 缺页
1：[4, 1, 3]              -- 换出 2              -- 缺页
2：[4, 1, 2]              -- 换出 3              -- 缺页
5：[5, 1, 2]              -- 换出 4              -- 缺页
...
```

::: warning
FIFO 算法可能出现 **Belady 异常**：当分配给进程的物理块数增加时，缺页次数反而增加。比如上面这个序列，3 个页框时缺页 9 次，4 个页框时反而缺页 10 次。这是该算法的主要缺陷。
:::

#### 3. 最近最久未使用算法（LRU）

**策略**：换出最近最长时间没有被访问的页面（谁最久没被碰过就换谁）。

**生活类比**：书架满了，把最长时间没翻过的书拿走。这比 FIFO 合理，因为"最近经常看的书大概率接下来还会看"。

```
访问序列：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
内存容量：3 个页框

初始：[_, _, _]
1：[1, _, _]              -- 缺页
2：[1, 2, _]              -- 缺页
3：[1, 2, 3]              -- 缺页
4：[4, 2, 3]              -- 换出 1（最久未使用）  -- 缺页
1：[4, 1, 3]              -- 换出 2（此时2最久未用） -- 缺页
2：[4, 1, 2]              -- 换出 3                -- 缺页
5：[5, 1, 2]              -- 换出 4                -- 缺页
...
```

**实现方式**：
- **计数器**：为每个页面记录访问时间戳，每次访问时更新。需要搜索所有页表项找最小值，效率低。
- **栈**：使用栈保存页面访问顺序，栈顶是最近访问的。需要维护栈结构，开销大。

#### 4. 时钟算法（Clock）

时钟算法是 LRU 的近似实现，也叫二次机会算法。它不需要记录精确的访问时间，实现成本低得多。

**策略**：
1. 为每个页面设置一个访问位（0 或 1）
2. 页面按环形链表组织，指针指向最老的页面
3. 需要置换时，检查指针指向的页面
   - 访问位为 0：换出该页面
   - 访问位为 1：将访问位置 0，给一次"二次机会"，指针移动到下一个页面

```
页面链表（环形）：
    ┌───┐   ┌───┐   ┌───┐   ┌───┐
    │ A │──>│ B │──>│ C │──>│ D │──┐
    │1  │   │0  │   │1  │   │1  │  │
    └───┘   └───┘   └───┘   └───┘  │
      ↑                             │
      └─────────────────────────────┘
      指针指向 A

需要置换时：
1. 检查 A：访问位为 1，置为 0，指针移到 B   -- 给 A 一次机会
2. 检查 B：访问位为 0，换出 B                -- B 没有机会了，换出
```

**改进的时钟算法**：同时考虑访问位和修改位，优先换出未修改的页面（减少写回磁盘的开销）。

| 访问位 | 修改位 | 优先级 | 说明 |
| --- | --- | --- | --- |
| 0 | 0 | 最高（直接换出） | 没访问过也没修改，直接扔掉 |
| 0 | 1 | 次高（需要写回） | 没访问过但修改了，要写回磁盘 |
| 1 | 0 | 次低（给一次机会） | 访问过但没修改，给一次机会 |
| 1 | 1 | 最低（给一次机会） | 访问过也修改过，最后考虑 |

#### 页面置换算法比较

| 算法 | 缺页率 | 实现复杂度 | 是否 Belady 异常 | 实际使用 |
| --- | --- | --- | --- | --- |
| OPT | 最低 | 无法实现 | 否 | 仅用于理论对比 |
| FIFO | 较高 | 简单 | 是 | 很少使用 |
| LRU | 接近 OPT | 中等 | 否 | 数据库等场景 |
| Clock | 接近 LRU | 简单 | 否 | Linux 等操作系统 |

::: tip
Linux 系统使用的是改进的时钟算法（二次机会算法的变体），它在性能和实现复杂度之间取得了良好的平衡。这也是大多数现代操作系统的选择。
:::

### 三、抖动与工作集

#### 抖动（Thrashing）

当系统频繁地进行页面置换，导致 CPU 利用率急剧下降的现象称为抖动。

**生活类比**：你在图书馆写论文，但桌上只能放 2 本书。你需要看 5 本书的内容，于是你不停地跑地下室换书，大部分时间都花在路上了，真正看书的时间反而很少。这就是"抖动"。

**原因**：
- 分配给进程的物理块数太少
- 页面置换算法不合理
- 多道程序度过高（同时运行的进程太多）

```
CPU 利用率
    ↑
    │        /\
    │       /  \
    │      /    \
    │     /      \
    │    /        \
    │   /          \
    │  /            \
    │ /              \
    │/________________\___→ 多道程序度
         最佳点
```

当多道程序度超过某个临界点时，每个进程分到的物理块太少，频繁缺页，CPU 利用率反而急剧下降。

#### 工作集模型

**工作集**：在某段时间间隔内，进程实际访问的页面集合。

**工作集模型**：根据进程的工作集大小动态调整分配给进程的物理块数，确保每个进程的工作集都能驻留在内存中。

```
时间窗口：Δt
工作集：WSS(t) = 在 [t-Δt, t] 时间内访问的页面集合

如果所有进程的 WSS 之和 > 可用内存：
  - 挂起某些进程
  - 减少多道程序度

如果所有进程的 WSS 之和 < 可用内存：
  - 可以加载更多进程
  - 增加多道程序度
```

::: info
工作集模型的核心思想是：为每个进程分配足够的物理块，使其工作集能够驻留在内存中，从而避免抖动。这就像确保你桌上至少能放下你当前需要的所有书，这样就不用频繁跑地下室了。
:::

## 对比表格

### 页面置换算法全面对比

| 算法 | 策略 | 缺页率 | 实现复杂度 | Belady 异常 | 适用场景 |
| --- | --- | --- | --- | --- | --- |
| OPT | 换出将来最久不用的 | 最低（理论值） | 无法实现 | 否 | 理论基准 |
| FIFO | 换出最早进入的 | 较高 | 简单（队列） | 是 | 几乎不用 |
| LRU | 换出最近最久未用的 | 接近 OPT | 中等（栈/计数器） | 否 | 数据库、缓存 |
| Clock | 用访问位近似 LRU | 接近 LRU | 简单（环形链表） | 否 | 操作系统主流 |

### 虚拟内存 vs 物理内存

| 特性 | 物理内存 | 虚拟内存 |
| --- | --- | --- |
| 大小 | 受硬件限制 | 可以远大于物理内存 |
| 速度 | 快（纳秒级） | 慢（涉及磁盘访问） |
| 地址空间 | 实际地址 | 每个进程独立的地址空间 |
| 用户可见 | 操作系统管理 | 对进程透明 |
| 持久性 | 断电丢失 | 页面存在磁盘上，持久 |

## 基础用法：页面置换算法模拟

### FIFO 算法完整模拟

```
// 已知条件：
// 访问序列：7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2, 1, 2
// 物理块数：3

// 初始状态：三个空页框
// 页框：[_, _, _]
// 队列：（空）

// 访问 7：页框未满，直接装入
// 页框：[7, _, _]              -- 缺页 1
// 队列：[7]

// 访问 0：页框未满，直接装入
// 页框：[7, 0, _]              -- 缺页 2
// 队列：[7, 0]

// 访问 1：页框未满，直接装入
// 页框：[7, 0, 1]              -- 缺页 3
// 队列：[7, 0, 1]

// 访问 2：页框已满，换出队首 7
// 页框：[2, 0, 1]              -- 缺页 4
// 队列：[0, 1, 2]

// 访问 0：命中！不需要置换
// 页框：[2, 0, 1]              -- 命中
// 队列：[0, 1, 2]              -- 不变

// 访问 3：换出队首 0
// 页框：[2, 3, 1]              -- 缺页 5
// 队列：[1, 2, 3]

// 访问 0：换出队首 1
// 页框：[2, 3, 0]              -- 缺页 6
// 队列：[2, 3, 0]

// 访问 4：换出队首 2
// 页框：[4, 3, 0]              -- 缺页 7
// 队列：[3, 0, 4]

// 访问 2：换出队首 3
// 页框：[4, 2, 0]              -- 缺页 8
// 队列：[0, 4, 2]

// 访问 3：换出队首 0
// 页框：[4, 2, 3]              -- 缺页 9
// 队列：[4, 2, 3]

// 访问 0：换出队首 4
// 页框：[0, 2, 3]              -- 缺页 10
// 队列：[2, 3, 0]

// 访问 3：命中！
// 页框：[0, 2, 3]              -- 命中

// 访问 2：命中！
// 页框：[0, 2, 3]              -- 命中

// 访问 1：换出队首 2
// 页框：[0, 1, 3]              -- 缺页 11
// 队列：[3, 0, 1]

// 访问 2：换出队首 3
// 页框：[0, 1, 2]              -- 缺页 12
// 队列：[0, 1, 2]

// 错误写法：FIFO 在命中时还移动队列位置
// 命中时队列不变！只有换入新页面时才更新队列  -- 错误！

// 错误写法：FIFO 根据"最近最少使用"来换出
// FIFO 只看进入时间，不看使用频率  -- 错误！那是 LRU
```

### LRU 算法完整模拟

```
// 已知条件：
// 访问序列：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
// 物理块数：3

// 初始状态：三个空页框
// 页框：[_, _, _]
// 使用时间线：（空）

// 访问 1：装入
// 页框：[1, _, _]              -- 缺页 1
// 最近使用：1

// 访问 2：装入
// 页框：[1, 2, _]              -- 缺页 2
// 最近使用：1, 2

// 访问 3：装入
// 页框：[1, 2, 3]              -- 缺页 3
// 最近使用：1, 2, 3

// 访问 4：换出最久未用的 1
// 页框：[4, 2, 3]              -- 缺页 4
// 最近使用：2, 3, 4            -- 1 最久没用

// 访问 1：换出最久未用的 2
// 页框：[4, 1, 3]              -- 缺页 5
// 最近使用：3, 4, 1            -- 2 最久没用

// 访问 2：换出最久未用的 3
// 页框：[4, 1, 2]              -- 缺页 6
// 最近使用：4, 1, 2            -- 3 最久没用

// 访问 5：换出最久未用的 4
// 页框：[5, 1, 2]              -- 缺页 7
// 最近使用：1, 2, 5            -- 4 最久没用

// 错误写法：LRU 换出"最早进入"的页面
// LRU 看的是"最后一次使用"的时间，不是"进入"的时间  -- 错误！那是 FIFO

// 错误写法：LRU 在命中时不更新使用顺序
// 命中时必须更新为"最近使用"  -- 错误！否则和 FIFO 没区别
```

## 新手常见误区

### 误区一：虚拟内存就是"把硬盘当内存用"

**错误理解**：虚拟内存就是把磁盘空间变成内存，让内存变大。

**为什么错**：虚拟内存的本质是一个地址空间抽象，它让每个进程认为自己独占了一大块连续的地址空间。磁盘只是用来存放暂时不在内存中的页面，是虚拟内存的实现手段，不是虚拟内存本身。

**正确做法**：理解虚拟内存是一个"抽象概念"，它通过按需调页和页面置换来实现，磁盘只是其中存放不活跃页面的地方。

### 误区二：物理内存越大，虚拟内存越没用

**错误理解**：如果物理内存足够大，就不需要虚拟内存了。

**为什么错**：即使物理内存很大，虚拟内存仍然有用：(1) 它为每个进程提供独立的地址空间，实现进程间隔离；(2) 它简化了编程，程序员不需要关心物理内存布局；(3) 它支持内存共享和写时复制等高级功能。

**正确做法**：物理内存大只是减少了缺页中断的频率，但虚拟内存的隔离、保护和共享功能是不可替代的。

### 误区三：OPT 算法可以在实际中使用

**错误理解**：OPT 算法效果最好，应该在实际系统中使用。

**为什么错**：OPT 需要知道未来的页面访问序列，这在现实中是不可能的。程序未来的行为无法精确预测。

**正确做法**：OPT 只用于理论分析和性能对比基准。实际系统使用 LRU 的近似算法（如 Clock），它们在实现简单的前提下能接近 OPT 的性能。

### 误区四：FIFO 和 LRU 结果一样

**错误理解**：FIFO 和 LRU 都是换出一个页面，结果应该差不多。

**为什么错**：FIFO 只看进入时间，LRU 看最后使用时间。在很多场景下两者差异很大。例如，一个很早进入但一直在用的页面，FIFO 会换出它，LRU 不会。

**正确做法**：记住 FIFO 是"谁先来谁先走"，LRU 是"谁最久没动谁走"。LRU 利用了局部性原理，性能通常远好于 FIFO。

### 误区五：多道程序度越高越好

**错误理解**：同时运行的进程越多，CPU 利用率越高。

**为什么错**：多道程序度超过某个临界点后，每个进程分到的物理块太少，频繁发生缺页中断，CPU 大部分时间在处理缺页而不是执行指令，这就是"抖动"。CPU 利用率反而急剧下降。

**正确做法**：使用工作集模型，根据进程的实际内存需求动态调整多道程序度，确保每个进程的工作集都能驻留在内存中。

已知页面访问序列为：1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5，物理块数为 3。

使用 Clock 算法（二次机会算法）模拟，计算缺页次数。假设所有页面初始访问位为 0。

<details>
<summary>点击查看答案</summary>

**Clock 算法规则**：
- 页面按环形链表组织，指针初始指向第一个页面
- 访问页面时，将其访问位置 1
- 需要置换时：检查指针指向的页面
  - 访问位 = 0：换出该页面
  - 访问位 = 1：置为 0，指针移到下一个

```
访问 1：页框 [1, _, _]  访问位 [0, -, -]  指针→0       -- 缺页 1
访问 2：页框 [1, 2, _]  访问位 [0, 0, -]  指针→0       -- 缺页 2
访问 3：页框 [1, 2, 3]  访问位 [0, 0, 0]  指针→0       -- 缺页 3
访问 4：需要置换
  检查位置 0（页面1）：访问位=0，换出！
  页框 [4, 2, 3]  访问位 [0, 0, 0]  指针→1             -- 缺页 4
访问 1：需要置换（1不在内存中）
  检查位置 1（页面2）：访问位=0，换出！
  页框 [4, 1, 3]  访问位 [0, 0, 0]  指针→2             -- 缺页 5
访问 2：需要置换
  检查位置 2（页面3）：访问位=0，换出！
  页框 [4, 1, 2]  访问位 [0, 0, 0]  指针→0             -- 缺页 6
访问 5：需要置换
  检查位置 0（页面4）：访问位=0，换出！
  页框 [5, 1, 2]  访问位 [0, 0, 0]  指针→1             -- 缺页 7
访问 1：命中！访问位置 1
  页框 [5, 1, 2]  访问位 [0, 1, 0]  指针→1             -- 命中
访问 2：命中！访问位置 1
  页框 [5, 1, 2]  访问位 [0, 1, 1]  指针→1             -- 命中
访问 3：需要置换
  检查位置 1（页面1）：访问位=1，置0，指针→2           -- 给一次机会
  检查位置 2（页面2）：访问位=1，置0，指针→0           -- 给一次机会
  检查位置 0（页面5）：访问位=0，换出！
  页框 [3, 1, 2]  访问位 [0, 0, 0]  指针→1             -- 缺页 8
访问 4：需要置换
  检查位置 1（页面1）：访问位=0，换出！
  页框 [3, 4, 2]  访问位 [0, 0, 0]  指针→2             -- 缺页 9
访问 5：需要置换
  检查位置 2（页面2）：访问位=0，换出！
  页框 [3, 4, 5]  访问位 [0, 0, 0]  指针→0             -- 缺页 10

Clock 算法缺页次数：10 次，缺页率：10/12 = 83.3%
```

注意：在这个例子中 Clock 和 FIFO 的结果相同（都是 10 次），因为所有页面在置换时访问位都是 0（没有被二次命中的页面在置换时刻）。当访问模式更复杂时，Clock 的"二次机会"机制才会体现出与 FIFO 的差异。

</details>
