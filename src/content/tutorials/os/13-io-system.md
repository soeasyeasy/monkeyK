# 第十三章：I/O 系统

## I/O 系统概述

I/O（输入/输出）系统是操作系统中负责管理外部设备的部分。它提供了统一的接口，让应用程序可以方便地访问各种设备。

| 功能 | 说明 |
| --- | --- |
| 设备管理 | 管理所有 I/O 设备 |
| 设备驱动 | 提供设备驱动程序 |
| 缓冲区管理 | 管理 I/O 缓冲区 |
| 设备分配 | 分配和回收设备 |
| 设备保护 | 控制设备的访问权限 |

### I/O 系统的层次结构

```
┌─────────────────────────────────┐
│        用户应用程序              │
├─────────────────────────────────┤
│        设备独立性软件            │  ← 统一接口、设备命名
├─────────────────────────────────┤
│        设备驱动程序              │  ← 设备相关操作
├─────────────────────────────────┤
│        中断处理程序              │  ← 处理 I/O 中断
├─────────────────────────────────┤
│        I/O 控制硬件              │  ← 设备控制器
├─────────────────────────────────┤
│        物理设备                  │  ← 磁盘、打印机等
└─────────────────────────────────┘
```

## I/O 硬件

### I/O 设备分类

**字符设备**：
- 以字符为单位进行 I/O 操作
- 顺序访问
- 例如：键盘、鼠标、打印机

**块设备**：
- 以块为单位进行 I/O 操作
- 支持随机访问
- 例如：磁盘、SSD、光盘

**网络设备**：
- 通过网络协议进行通信
- 例如：网卡、路由器

### I/O 设备组成

典型的 I/O 设备由以下部分组成：

```
┌─────────────────────────────────┐
│           设备                  │
│  ┌─────────────────────────┐   │
│  │      设备控制器          │   │  ← 控制设备操作
│  │  ┌─────────────────┐   │   │
│  │  │   寄存器         │   │   │  ← 数据、状态、控制
│  │  │  - 数据寄存器    │   │   │
│  │  │  - 状态寄存器    │   │   │
│  │  │  - 控制寄存器    │   │   │
│  │  └─────────────────┘   │   │
│  └─────────────────────────┘   │
│              ↓                  │
│  ┌─────────────────────────┐   │
│  │      机械部件            │   │  ← 执行实际操作
│  │  （磁头、电机等）        │   │
│  └─────────────────────────┘   │
└─────────────────────────────────┘
```

### 设备控制器

设备控制器是 CPU 和物理设备之间的桥梁，负责：
- 接收 CPU 的命令
- 向 CPU 报告设备状态
- 控制设备的实际操作

**寄存器类型**：
| 寄存器 | 功能 |
| --- | --- |
| 数据寄存器 | 存储要发送或接收的数据 |
| 状态寄存器 | 存储设备状态（忙、闲、错误） |
| 控制寄存器 | 存储 CPU 发给设备的命令 |

### 直接内存访问（DMA）

DMA 允许设备直接与内存交换数据，无需 CPU 干预。

```
传统 I/O（程序控制 I/O）：
CPU ──读取数据──> 设备控制器 ──> 设备
CPU ──写入数据──> 内存

DMA I/O：
设备控制器 ──DMA 通道──> 内存
CPU 只在开始和结束时参与
```

**DMA 的工作过程**：
1. CPU 向 DMA 控制器发送命令（传输方向、内存地址、数据量）
2. DMA 控制器接管总线控制权
3. DMA 控制器在设备和内存之间传输数据
4. 传输完成，DMA 控制器向 CPU 发送中断
5. CPU 处理中断，继续执行

**优点**：
- 减少 CPU 干预
- 提高传输效率
- 适合大数据量传输

::: tip
现代磁盘、网卡等设备都使用 DMA 技术，大大减轻了 CPU 的负担。
:::

## I/O 控制方式

### 程序直接控制方式

CPU 通过不断轮询设备状态来控制 I/O 操作。

```
程序流程：
1. CPU 向设备发送读命令
2. CPU 循环检查设备状态寄存器
3. 设备准备好数据后，CPU 读取数据
4. 重复步骤 2-3，直到数据传输完成

代码示例（伪代码）：
while (设备忙) {
    // 等待
}
读取数据到寄存器
while (还有数据) {
    while (设备未准备好) {
        // 等待
    }
    将数据从寄存器传到内存
}
```

**优点**：实现简单

**缺点**：
- CPU 利用率低（忙等待）
- 不适合多道程序环境

### 中断驱动方式

设备准备好数据后，向 CPU 发送中断信号。

```
程序流程：
1. CPU 向设备发送读命令
2. CPU 继续执行其他程序
3. 设备准备好数据后，发送中断
4. CPU 响应中断，读取数据
5. 中断处理完成，返回原程序

中断处理过程：
┌─────────────┐
│ 保存现场    │
├─────────────┤
│ 识别中断源  │
├─────────────┤
│ 读取数据    │
├─────────────┤
│ 恢复现场    │
└─────────────┘
```

**优点**：
- CPU 可以执行其他程序
- 提高 CPU 利用率

**缺点**：
- 中断处理开销大
- 数据量小时效率低

### DMA 方式

使用 DMA 控制器在设备和内存之间直接传输数据。

```
程序流程：
1. CPU 初始化 DMA 控制器（设置内存地址、数据量等）
2. CPU 继续执行其他程序
3. DMA 控制器在设备和内存之间传输数据
4. 传输完成，DMA 控制器发送中断
5. CPU 响应中断，处理后续操作

数据传输：
设备 ──DMA 控制器──> 内存
（无需 CPU 参与）
```

**优点**：
- 大幅减少 CPU 干预
- 适合大数据量传输
- 传输速度快

**缺点**：
- 需要额外的 DMA 控制器硬件
- 实现复杂

### 通道控制方式

通道是一种更高级的 I/O 处理机，可以执行通道程序。

```
通道程序：
┌─────────────────────────────┐
│ 通道指令 1：读取块 100      │
├─────────────────────────────┤
│ 通道指令 2：读取块 101      │
├─────────────────────────────┤
│ 通道指令 3：读取块 102      │
├─────────────────────────────┤
│ ...                         │
└─────────────────────────────┘

执行过程：
1. CPU 向通道发送通道程序起始地址
2. 通道从内存中取出通道指令并执行
3. 通道控制设备完成 I/O 操作
4. 通道程序执行完毕，向 CPU 发送中断
```

**通道类型**：
| 类型 | 特点 | 适用设备 |
| --- | --- | --- |
| 字节多路通道 | 多个子通道，字节交叉 | 低速设备（打印机） |
| 数组选择通道 | 独占通道，块传输 | 高速设备（磁盘） |
| 字节数组多路通道 | 结合两者优点 | 各种设备 |

::: info
现代计算机通常使用 DMA 方式，通道控制方式主要用于大型计算机系统。
:::

## I/O 控制方式比较

| 控制方式 | CPU 利用率 | 实现复杂度 | 适用场景 |
| --- | --- | --- | --- |
| 程序直接控制 | 最低 | 最简单 | 简单系统 |
| 中断驱动 | 中等 | 中等 | 低速设备 |
| DMA | 高 | 较复杂 | 高速块设备 |
| 通道控制 | 最高 | 最复杂 | 大型系统 |

## 缓冲技术

### 为什么需要缓冲

**问题**：
- 设备速度与 CPU 速度不匹配
- 设备之间速度差异大
- 数据粒度不匹配

**缓冲的作用**：
- 缓和速度矛盾
- 提高 CPU 和设备利用率
- 支持批量处理

### 单缓冲

在内存中设置一个缓冲区。

```
生产者（设备）──> 缓冲区 ──> 消费者（CPU）

时间线：
T0: 设备开始写入缓冲区
T1: 缓冲区满，设备等待
T2: CPU 从缓冲区读取数据
T3: 缓冲区空，CPU 等待
T4: 设备继续写入
...

优点：实现简单
缺点：设备和 CPU 不能并行工作
```

### 双缓冲

在内存中设置两个缓冲区，实现生产者-消费者并行。

```
生产者 ──> 缓冲区 1 ──> 消费者
         缓冲区 2

时间线：
T0: 设备写入缓冲区 1
T1: 缓冲区 1 满，设备切换到缓冲区 2
T2: CPU 读取缓冲区 1，同时设备写入缓冲区 2
T3: 缓冲区 1 空，CPU 切换到缓冲区 2
T4: 设备写入缓冲区 1，同时 CPU 读取缓冲区 2
...

优点：设备和 CPU 可以并行工作
缺点：需要两个缓冲区空间
```

### 循环缓冲

使用多个缓冲区组成环形结构。

```
缓冲区环：
    ┌───┐
    │ 0 │ ← 生产者写入
    ├───┤
    │ 1 │
    ├───┤
    │ 2 │
    ├───┤
    │ 3 │ ← 消费者读取
    └───┘

指针：
- in：指向下一个可写入的缓冲区
- out：指向下一个可读取的缓冲区

条件：
- 缓冲区满：(in + 1) % N == out
- 缓冲区空：in == out
```

**优点**：
- 支持多个生产者和消费者
- 缓冲区利用率高

### 缓冲池

由多个缓冲区组成，可以灵活分配。

```
缓冲池结构：
┌─────────────────────────────┐
│  空闲缓冲区队列              │
│  [空][空][空][空][空]        │
├─────────────────────────────┤
│  输入缓冲区队列              │
│  [输入1][输入2][输入3]       │
├─────────────────────────────┤
│  输出缓冲区队列              │
│  [输出1][输出2][输出3]       │
└─────────────────────────────┘

操作：
1. 输入操作：从空闲队列取缓冲区 → 填入数据 → 放入输入队列
2. 输出操作：从输出队列取缓冲区 → 发送数据 → 放回空闲队列
```

**优点**：
- 灵活分配
- 支持多种 I/O 操作

::: tip
Linux 系统使用缓冲池（buffer cache）来管理磁盘 I/O，大大提高了系统性能。
:::

## 设备分配

### 设备分配策略

设备分配需要考虑以下因素：
- 设备的固有特性（字符设备、块设备）
- 设备的分配方式（独占、共享、虚拟）
- 进程的优先级
- 系统的 I/O 调度策略

### 设备分配方式

**独占设备**：
- 进程独占使用，直到释放
- 例如：打印机、磁带机
- 缺点：设备利用率低

**共享设备**：
- 多个进程可以交替使用
- 例如：磁盘
- 优点：设备利用率高

**虚拟设备**：
- 通过 SPOOLing 技术将独占设备虚拟为共享设备
- 例如：打印机虚拟化为打印队列

### SPOOLing 技术

SPOOLing（Simultaneous Peripheral Operations On Line）是一种虚拟设备技术。

```
SPOOLing 系统结构：
┌─────────────────────────────────┐
│           输入井                │  ← 磁盘上的输入缓冲区
├─────────────────────────────────┤
│           输出井                │  ← 磁盘上的输出缓冲区
├─────────────────────────────────┤
│        输入进程                 │  ← 从设备读取到输入井
├─────────────────────────────────┤
│        输出进程                 │  ← 从输出井写入设备
├─────────────────────────────────┤
│        请求队列                 │  ← 进程的 I/O 请求
└─────────────────────────────────┘

打印机的 SPOOLing 实现：
1. 进程请求打印，将数据写入输出井
2. 打印守护进程从输出井读取数据
3. 实际执行打印操作
4. 打印完成，通知进程

优点：
- 将独占设备虚拟为共享设备
- 提高设备利用率
- 支持假脱机操作
```

### 设备分配算法

**先来先服务（FCFS）**：
- 按请求到达顺序分配
- 公平，但可能效率低

**优先级调度**：
- 高优先级进程优先获得设备
- 可能导致低优先级进程饥饿

**最短作业优先**：
- I/O 时间短的进程优先
- 提高系统吞吐量

### 设备分配过程

```
设备分配流程：
1. 进程发出 I/O 请求
2. 检查设备状态
   - 设备忙：加入等待队列
   - 设备闲：继续
3. 分配设备
4. 启动设备
5. 设备完成操作，发送中断
6. 释放设备
7. 唤醒等待队列中的下一个进程
```

## I/O 软件层次

### 中断处理程序

处理 I/O 中断，是 I/O 软件的最底层。

```
中断处理过程：
1. 保存 CPU 现场
2. 识别中断源（哪个设备）
3. 读取设备状态
4. 如果是输入：将数据从设备寄存器读到内存
5. 如果是输出：将下一个数据写入设备寄存器
6. 唤醒等待该 I/O 的进程
7. 恢复 CPU 现场
```

### 设备驱动程序

与硬件直接交互的软件，提供设备相关的操作。

```
设备驱动程序功能：
1. 初始化设备
2. 发送命令到设备
3. 处理中断
4. 错误处理
5. 提供统一接口给上层

示例（Linux 设备驱动）：
struct file_operations {
    struct module *owner;
    ssize_t (*read) (struct file *, char *, size_t, loff_t *);
    ssize_t (*write) (struct file *, const char *, size_t, loff_t *);
    int (*open) (struct inode *, struct file *);
    int (*release) (struct inode *, struct file *);
    ...
};
```

### 设备独立性软件

提供与设备无关的统一接口。

```
设备独立性软件功能：
1. 设备命名：使用逻辑设备名（如 /dev/sda）
2. 设备保护：权限检查
3. 缓冲区管理：分配和释放缓冲区
4. 设备分配：分配和释放设备
5. 错误处理：处理设备错误

系统调用接口：
open("/dev/sda", O_RDONLY);
read(fd, buffer, size);
write(fd, buffer, size);
close(fd);
```

::: info
设备独立性软件使得应用程序可以独立于具体设备，提高了系统的可扩展性和可移植性。
:::

## I/O 性能

### I/O 性能指标

| 指标 | 说明 |
| --- | --- |
| 带宽 | 单位时间内传输的数据量（MB/s） |
| 延迟 | 完成一次 I/O 操作的时间（ms） |
| IOPS | 每秒 I/O 操作次数 |
| 响应时间 | 从请求到完成的时间 |

### 影响 I/O 性能的因素

**硬件因素**：
- 设备类型（HDD vs SSD）
- 接口类型（SATA vs NVMe）
- 缓存大小

**软件因素**：
- I/O 调度算法
- 缓冲策略
- 文件系统实现

### I/O 性能优化

**硬件优化**：
- 使用 SSD 替代 HDD
- 使用 RAID 技术
- 增加缓存

**软件优化**：
- 使用异步 I/O
- 优化 I/O 调度
- 减少 I/O 操作次数

```
异步 I/O 示例（Linux）：
// 提交异步 I/O 请求
io_submit(ctx, 1, &iocb);

// 等待 I/O 完成
io_getevents(ctx, 1, 1, &events, NULL);

// 处理结果
if (events[0].res > 0) {
    // I/O 成功
}
```

## 本章小结

- I/O 硬件包括设备控制器、寄存器和 DMA 控制器
- I/O 控制方式包括程序直接控制、中断驱动、DMA 和通道控制
- 缓冲技术包括单缓冲、双缓冲、循环缓冲和缓冲池
- 设备分配需要考虑设备类型、分配方式和调度算法
- SPOOLing 技术可以将独占设备虚拟为共享设备
- I/O 软件分为中断处理、设备驱动和设备独立性软件三个层次
