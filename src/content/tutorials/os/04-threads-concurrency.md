# 第四章：线程与并发

## 线程的概念

**线程（Thread）** 是 CPU 调度的基本单位，是进程中的一个执行流。一个进程可以包含多个线程，它们共享进程的地址空间和资源。

### 线程与进程的比较

| 对比项 | 进程 | 线程 |
| --- | --- | --- |
| 调度单位 | 资源分配的基本单位 | CPU 调度的基本单位 |
| 地址空间 | 独立的地址空间 | 共享所属进程的地址空间 |
| 资源拥有 | 拥有独立的资源 | 共享进程的资源 |
| 切换开销 | 大（需要切换地址空间） | 小（不需要切换地址空间） |
| 通信方式 | 需要 IPC 机制 | 可直接读写共享内存 |
| 创建/销毁开销 | 大 | 小 |

::: info
可以将进程想象成一个工厂，线程就是工厂里的工人。工厂提供场地和设备（资源），工人使用这些设备进行生产（执行任务）。多个工人共享同一个工厂的资源。
:::

### 线程的组成

每个线程拥有自己的：

- **线程 ID**
- **程序计数器（PC）**
- **寄存器集合**
- **栈（Stack）**

与同进程内的其他线程共享：

- **代码段**
- **数据段**
- **打开的文件**
- **信号处理函数**
- **当前工作目录**
- **进程 ID 和组 ID**

```
进程 A
├── 线程 1（主线程）
│   ├── PC、寄存器、栈
│   └── 共享：代码段、数据段、打开文件...
├── 线程 2
│   ├── PC、寄存器、栈
│   └── 共享：代码段、数据段、打开文件...
└── 线程 3
    ├── PC、寄存器、栈
    └── 共享：代码段、数据段、打开文件...
```

## 用户级线程与内核级线程

### 用户级线程（User-Level Threads, ULT）

用户级线程的管理完全在用户空间进行，内核不感知。

```
┌─────────────────────────────────┐
│  线程1  │  线程2  │  线程3       │  ← 用户空间
├─────────────────────────────────┤
│         线程库（管理线程）        │  ← 用户空间
├─────────────────────────────────┤
│           操作系统内核           │  ← 内核空间
│         （只看到一个进程）        │
└─────────────────────────────────┘
```

| 优点 | 缺点 |
| --- | --- |
| 线程切换不需要内核参与，速度快 | 一个线程阻塞会导致整个进程阻塞 |
| 调度算法可以由应用程序自定义 | 多线程无法在多核 CPU 上并行执行 |
| 实现与 OS 无关 | 系统调用会阻塞整个进程 |

代表实现：POSIX Pthreads（M:1 模型）、GNU Portable Threads

### 内核级线程（Kernel-Level Threads, KLT）

内核级线程由操作系统内核直接管理。

```
┌─────────────────────────────────┐
│  线程1  │  线程2  │  线程3       │  ← 用户空间
├─────────────────────────────────┤
│           操作系统内核           │  ← 内核空间
│  线程1  │  线程2  │  线程3       │
│  （内核直接管理和调度每个线程）    │
└─────────────────────────────────┘
```

| 优点 | 缺点 |
| --- | --- |
| 一个线程阻塞不影响其他线程 | 线程切换需要陷入内核，开销较大 |
| 多线程可以在多核 CPU 上并行 | 线程的创建和管理需要内核支持 |
| 内核可以进行优化调度 | 实现与 OS 相关 |

代表实现：Windows 线程、Linux 的 NPTL（1:1 模型）

### 对比总结

| 对比项 | 用户级线程 | 内核级线程 |
| --- | --- | --- |
| 管理位置 | 用户空间 | 内核空间 |
| 切换速度 | 快 | 较慢 |
| 阻塞影响 | 阻塞整个进程 | 只阻塞当前线程 |
| 多核并行 | 不支持 | 支持 |
| 内核感知 | 不感知 | 感知 |

## 多线程模型

### 多对一模型（Many-to-One）

多个用户级线程映射到一个内核级线程。

```
用户线程：T1  T2  T3  T4
           │   │   │   │
           └───┴───┴───┘
               │
           内核线程：K1
```

- 优点：线程管理开销小
- 缺点：一个线程阻塞，所有线程都阻塞；不能利用多核

### 一对一模型（One-to-One）

每个用户级线程对应一个内核级线程。

```
用户线程：T1  T2  T3
           │   │   │
           │   │   │
内核线程：K1  K2  K3
```

- 优点：一个线程阻塞不影响其他线程；支持多核并行
- 缺点：创建内核线程开销大

代表：Linux（NPTL）、Windows

### 多对多模型（Many-to-Many）

多个用户级线程映射到多个内核级线程（M:N）。

```
用户线程：T1  T2  T3  T4  T5
           │   │   │   │   │
           └───┴───┴───┴───┘
               │   │   │
           内核线程：K1  K2  K3
```

- 优点：结合了两种模型的优点
- 缺点：实现复杂

### 两级模型（Two-Level Model）

多对多模型的变体，允许将用户线程绑定到特定的内核线程。

```
用户线程：T1  T2  T3  T4  T5
           │   │   │   │   │
           │   ├───┘   │   │
           │   │       │   │
内核线程：K1  K2      K3
```

## 线程实现示例

### POSIX 线程（pthreads）

```c
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>

// 线程函数
void* thread_func(void* arg) {
    int id = *(int*)arg;
    printf("线程 %d 正在运行\n", id);
    return NULL;
}

int main() {
    pthread_t threads[3];
    int ids[3] = {1, 2, 3};

    // 创建线程
    for (int i = 0; i < 3; i++) {
        pthread_create(&threads[i], NULL, thread_func, &ids[i]);
    }

    // 等待线程结束
    for (int i = 0; i < 3; i++) {
        pthread_join(threads[i], NULL);
    }

    printf("所有线程已完成\n");
    return 0;
}
```

编译和运行：

```bash
gcc -o thread_example thread_example.c -pthread
./thread_example
```

### Windows 线程

```c
#include <windows.h>
#include <stdio.h>

// 线程函数
DWORD WINAPI ThreadFunc(LPVOID arg) {
    int id = *(int*)arg;
    printf("线程 %d 正在运行\n", id);
    return 0;
}

int main() {
    HANDLE threads[3];
    int ids[3] = {1, 2, 3};

    for (int i = 0; i < 3; i++) {
        threads[i] = CreateThread(
            NULL,           // 安全属性
            0,              // 栈大小
            ThreadFunc,     // 线程函数
            &ids[i],        // 参数
            0,              // 创建标志
            NULL            // 线程 ID
        );
    }

    WaitForMultipleObjects(3, threads, TRUE, INFINITE);

    for (int i = 0; i < 3; i++) {
        CloseHandle(threads[i]);
    }

    printf("所有线程已完成\n");
    return 0;
}
```

## 并发带来的问题

多线程共享资源带来了效率，但也引入了问题：

### 数据竞争（Data Race）

```c
int counter = 0;

void* increment(void* arg) {
    for (int i = 0; i < 100000; i++) {
        counter++;  // 非原子操作！
    }
    return NULL;
}

// 两个线程同时执行 increment
// 最终 counter 可能小于 200000
```

::: tip
数据竞争是多线程编程中最常见的问题。解决方案包括使用**互斥锁（Mutex）**、**信号量（Semaphore）** 等同步机制，确保对共享数据的互斥访问。
:::

### 死锁（Deadlock）

两个或多个线程相互等待对方释放资源，导致所有线程都无法继续执行。

```
线程 A 持有锁 1，等待锁 2
线程 B 持有锁 2，等待锁 1
→ 两个线程永远等待
```

## 本章小结

- 线程是 CPU 调度的基本单位，进程是资源分配的基本单位
- 线程共享所属进程的地址空间和资源，但拥有独立的栈和寄存器
- **用户级线程**在用户空间管理，切换快但无法利用多核
- **内核级线程**由内核管理，支持多核但切换开销大
- 多线程模型包括：多对一、一对一、多对多和两级模型
- 并发编程需要注意数据竞争和死锁等问题
