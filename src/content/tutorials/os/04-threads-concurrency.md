# 第四章：线程与并发

## 本章导读

在学这一章之前，你可能会有这些疑问：

- 进程已经够用了，为什么还要引入线程？线程到底解决了什么问题？
- 线程和进程有什么区别？为什么说线程更"轻量"？
- 用户级线程和内核级线程有什么不同？为什么要有两种实现方式？
- 多线程会带来什么问题？为什么并发编程这么难？

这一章就是为了解答这些问题。我们会先搞清楚为什么需要线程，再学习线程和进程的区别，然后了解用户级线程和内核级线程的实现方式，最后看看多线程会带来哪些并发问题。学完之后，你会理解现代操作系统为什么要用线程，以及怎么写好多线程程序。

---

## 4.1 为什么需要线程？

### 痛点分析

在第三章我们学了进程，进程是资源分配的基本单位。但是进程有两个很大的问题：

1. **创建和切换开销大**：创建一个进程需要分配独立的内存空间、文件描述表等资源。切换进程时需要保存整个进程的状态，包括内存映射、寄存器等，非常耗时。

2. **进程间通信麻烦**：因为每个进程都有独立的地址空间，进程之间不能直接访问对方的数据，必须通过管道、消息队列、共享内存等复杂的 IPC 机制来通信。

打个比方：

> 进程就像一个个独立的工厂。每个工厂都有自己的场地、设备、工人。如果要把一个工厂的产品搬到另一个工厂，需要专门的运输车（IPC 机制）。而且建新工厂需要很大的投入（创建开销大），工厂之间切换也很麻烦（切换开销大）。

### 线程的价值

线程就是为了解决进程的两个痛点而引入的。线程是 CPU 调度的基本单位，同一个进程内的多个线程共享进程的资源（内存、文件等），但每个线程有自己的栈和寄存器。

打个比方：

> 线程就像工厂里的工人。同一个工厂（进程）里的工人共享工厂的场地和设备（内存、文件），但每个工人有自己的工具箱（栈）和工作记录（寄存器）。工人之间可以直接交流（共享内存），不需要专门的运输车。而且招一个新工人（创建线程）比建一个新工厂（创建进程）便宜得多，工人之间切换也比工厂之间切换快得多。

```
没有线程：每个任务都是一个独立的进程
  任务A（进程1）→ 独立的内存空间 → 创建开销大
  任务B（进程2）→ 独立的内存空间 → 切换开销大
  任务C（进程3）→ 独立的内存空间 → 通信需要 IPC

有了线程：一个进程内可以有多个线程
  进程1
    ├─ 线程A → 共享进程的内存空间
    ├─ 线程B → 共享进程的内存空间 → 创建快、切换快、直接通信
    └─ 线程C → 共享进程的内存空间
```

> 一句话总结：线程是轻量级的进程，创建快、切换快、通信方便，解决了进程的两个痛点。

## 4.2 线程的概念

### 什么是线程

**线程（Thread）** 是 CPU 调度的基本单位，是进程中的一个执行流。一个进程可以包含多个线程，它们共享进程的地址空间和资源。

打个比方：

> 进程就像一个工厂，线程就像工厂里的工人。工厂提供场地和设备（资源），工人使用这些设备进行生产（执行任务）。多个工人共享同一个工厂的资源，但每个工人有自己的工具箱和工作记录。

### 线程与进程的比较

| 对比项 | 进程 | 线程 | 生活化类比 |
| --- | --- | --- | --- |
| 调度单位 | 资源分配的基本单位 | CPU 调度的基本单位 | 像工厂 vs 工人 |
| 地址空间 | 独立的地址空间 | 共享所属进程的地址空间 | 像独立的工厂 vs 共享工厂的工人 |
| 资源拥有 | 拥有独立的资源 | 共享进程的资源 | 像工厂拥有设备 vs 工人使用设备 |
| 切换开销 | 大（需要切换地址空间） | 小（不需要切换地址空间） | 像换工厂 vs 换工人 |
| 通信方式 | 需要 IPC 机制 | 可直接读写共享内存 | 像运输车 vs 直接交流 |
| 创建/销毁开销 | 大 | 小 | 像建工厂 vs 招工人 |

### 线程的组成

每个线程拥有自己的（独享资源）：

- **线程 ID**：唯一标识一个线程
- **程序计数器（PC）**：记录下一条要执行的指令地址
- **寄存器集合**：保存线程的当前状态
- **栈（Stack）**：存储局部变量、函数调用信息

与同进程内的其他线程共享（共享资源）：

- **代码段**：程序的指令
- **数据段**：全局变量、静态变量
- **打开的文件**：文件描述符
- **信号处理函数**：信号的处理方式
- **当前工作目录**：进程的当前目录
- **进程 ID 和组 ID**：进程的身份标识

```
进程 A（共享资源：代码段、数据段、打开的文件...）
├── 线程 1（主线程）
│   ├── 独享：PC、寄存器、栈
│   └── 共享：代码段、数据段、打开文件...
├── 线程 2
│   ├── 独享：PC、寄存器、栈
│   └── 共享：代码段、数据段、打开文件...
└── 线程 3
    ├── 独享：PC、寄存器、栈
    └── 共享：代码段、数据段、打开文件...
```

## 4.3 用户级线程与内核级线程

线程的实现方式有两种：用户级线程和内核级线程。这两种方式的区别在于"谁来管理线程"。

### 用户级线程（User-Level Threads, ULT）

用户级线程的管理完全在用户空间进行，内核不感知。也就是说，操作系统只看到进程，看不到线程。

打个比方：

> 用户级线程就像工厂内部自己管理的工人。工厂老板（用户空间的线程库）自己决定招多少工人、怎么分配工作。政府部门（操作系统内核）只知道有这个工厂，不知道里面有多少工人。

```
┌─────────────────────────────────┐
│  线程1  │  线程2  │  线程3       │  ← 用户空间（工厂内部）
├─────────────────────────────────┤
│         线程库（管理线程）        │  ← 用户空间（工厂老板）
├─────────────────────────────────┤
│           操作系统内核           │  ← 内核空间（政府部门）
│         （只看到一个进程）        │
└─────────────────────────────────┘
```

| 优点 | 说明 | 生活化类比 |
| --- | --- | --- |
| 线程切换不需要内核参与，速度快 | 切换线程不需要陷入内核，直接在用户空间完成 | 像工厂老板自己调配工人，不需要政府审批 |
| 调度算法可以由应用程序自定义 | 应用程序可以选择最适合自己的调度算法 | 像工厂老板可以根据生产需要灵活安排 |
| 实现与 OS 无关 | 用户级线程库可以在任何操作系统上运行 | 像工厂的管理制度不依赖于政府的政策 |

| 缺点 | 说明 | 生活化类比 |
| --- | --- | --- |
| 一个线程阻塞会导致整个进程阻塞 | 因为内核不知道线程的存在，一个线程等待 I/O 时，整个进程都会被挂起 | 像一个工人请假，整个工厂都停工 |
| 多线程无法在多核 CPU 上并行执行 | 因为内核只看到一个进程，不会把多个核分配给同一个进程的不同线程 | 像政府只给工厂分配一台机器，多个工人只能轮流用 |
| 系统调用会阻塞整个进程 | 系统调用会陷入内核，导致整个进程阻塞 | 像工厂需要政府审批时，整个工厂都要等 |

代表实现：POSIX Pthreads（M:1 模型）、GNU Portable Threads

### 内核级线程（Kernel-Level Threads, KLT）

内核级线程由操作系统内核直接管理。内核知道每个线程的存在，可以为每个线程分配 CPU。

打个比方：

> 内核级线程就像政府登记的工人。政府部门（操作系统内核）知道每个工人的存在，可以直接给工人分配任务（CPU）。工厂老板（应用程序）也可以自己管理工人，但政府也有管理权。

```
┌─────────────────────────────────┐
│  线程1  │  线程2  │  线程3       │  ← 用户空间（工厂）
├─────────────────────────────────┤
│           操作系统内核           │  ← 内核空间（政府部门）
│  线程1  │  线程2  │  线程3       │
│  （内核直接管理和调度每个线程）    │
└─────────────────────────────────┘
```

| 优点 | 说明 | 生活化类比 |
| --- | --- | --- |
| 一个线程阻塞不影响其他线程 | 内核可以调度其他线程继续执行 | 像一个工人请假，其他工人继续工作 |
| 多线程可以在多核 CPU 上并行 | 内核可以把不同的线程分配到不同的核上 | 像政府可以给工厂分配多台机器 |
| 内核可以进行优化调度 | 内核可以根据系统负载动态调整线程的调度 | 像政府可以根据整体经济情况调整政策 |

| 缺点 | 说明 | 生活化类比 |
| --- | --- | --- |
| 线程切换需要陷入内核，开销较大 | 切换线程需要从用户态切换到内核态 | 像调配工人需要政府审批，流程较长 |
| 线程的创建和管理需要内核支持 | 创建线程需要调用系统调用 | 像招工人需要到政府登记 |
| 实现与 OS 相关 | 不同的操作系统可能有不同的线程实现 | 像不同国家的政策不同 |

代表实现：Windows 线程、Linux 的 NPTL（1:1 模型）

### 对比总结

| 对比项 | 用户级线程 | 内核级线程 | 生活化类比 |
| --- | --- | --- | --- |
| 管理位置 | 用户空间 | 内核空间 | 像工厂自己管理 vs 政府管理 |
| 切换速度 | 快 | 较慢 | 像内部调配 vs 政府审批 |
| 阻塞影响 | 阻塞整个进程 | 只阻塞当前线程 | 像一个请假全停工 vs 只影响个人 |
| 多核并行 | 不支持 | 支持 | 像只用一台机器 vs 可以用多台机器 |
| 内核感知 | 不感知 | 感知 | 像政府不知道 vs 政府知道 |
| 实现复杂度 | 简单 | 复杂 | 像自己定规矩 vs 要符合政府规定 |

## 4.4 多线程模型

根据用户级线程和内核级线程的对应关系，有三种经典的多线程模型。

### 多对一模型（Many-to-One）

多个用户级线程映射到一个内核级线程。

打个比方：

> 就像一个工厂有多个工人，但只有一台机器。工人只能轮流使用这台机器，一个工人用机器时，其他工人只能等待。

```
用户线程：T1  T2  T3  T4
           │   │   │   │
           └───┴───┴───┘
               │
           内核线程：K1
```

| 优点 | 缺点 |
| --- | --- |
| 线程管理开销小 | 一个线程阻塞，所有线程都阻塞 |
| 实现简单 | 不能利用多核 |

### 一对一模型（One-to-One）

每个用户级线程对应一个内核级线程。

打个比方：

> 就像一个工厂有多个工人，每个工人都有自己的机器。一个工人机器坏了，不影响其他工人继续工作。

```
用户线程：T1  T2  T3
           │   │   │
           │   │   │
内核线程：K1  K2  K3
```

| 优点 | 缺点 |
| --- | --- |
| 一个线程阻塞不影响其他线程 | 创建内核线程开销大 |
| 支持多核并行 | 线程数量受内核限制 |

代表：Linux（NPTL）、Windows

### 多对多模型（Many-to-Many）

多个用户级线程映射到多个内核级线程（M:N）。

打个比方：

> 就像一个工厂有多个工人，也有多台机器。工人可以灵活使用机器，一个工人用一台机器时，其他工人可以用其他机器。

```
用户线程：T1  T2  T3  T4  T5
           │   │   │   │   │
           └───┴───┴───┴───┘
               │   │   │
           内核线程：K1  K2  K3
```

| 优点 | 缺点 |
| --- | --- |
| 结合了两种模型的优点 | 实现复杂 |
| 既可以灵活调度，又支持多核 | 需要内核支持 |

### 两级模型（Two-Level Model）

多对多模型的变体，允许将用户线程绑定到特定的内核线程。

打个比方：

> 就像一个工厂有多个工人和多台机器，但有些工人固定使用某台机器，有些工人可以灵活使用任何机器。

```
用户线程：T1  T2  T3  T4  T5
           │   │   │   │   │
           │   ├───┘   │   │
           │   │       │   │
内核线程：K1  K2      K3
```

## 4.5 线程实现示例

### POSIX 线程（pthreads）

POSIX 线程是 UNIX/Linux 系统上的标准线程库，使用 `pthread` 库。

```c
#include <pthread.h>  // 包含 POSIX 线程库的函数声明
#include <stdio.h>    // 包含 printf() 函数声明
#include <stdlib.h>   // 包含 exit() 函数声明

// 线程函数：每个线程执行的代码
// 参数 arg 是传递给线程的参数
// 返回值是线程结束时返回的值
void* thread_func(void* arg) {
    // 将参数转换为整数
    int id = *(int*)arg;
    
    // 打印线程 ID
    printf("线程 %d 正在运行\n", id);
    
    // 线程结束时返回 NULL
    return NULL;
}

int main() {
    // 定义线程数组，存储 3 个线程的句柄
    pthread_t threads[3];
    
    // 定义传递给线程的参数数组
    int ids[3] = {1, 2, 3};
    
    // 创建 3 个线程
    for (int i = 0; i < 3; i++) {
        // pthread_create() 创建新线程
        // 参数1：线程句柄，用于后续操作
        // 参数2：线程属性，NULL 表示使用默认属性
        // 参数3：线程函数，线程要执行的代码
        // 参数4：传递给线程函数的参数
        pthread_create(&threads[i], NULL, thread_func, &ids[i]);
    }
    
    // 等待所有线程结束
    for (int i = 0; i < 3; i++) {
        // pthread_join() 等待线程结束
        // 参数1：线程句柄
        // 参数2：接收线程返回值的指针，NULL 表示不关心返回值
        pthread_join(threads[i], NULL);
    }
    
    // 打印主线程结束信息
    printf("所有线程已完成\n");
    
    return 0;
}
```

编译和运行：

```bash
# 编译时需要链接 pthread 库
gcc -o thread_example thread_example.c -pthread

# 运行程序
./thread_example
```

### Windows 线程

Windows 系统使用 `CreateThread()` 函数创建线程。

```c
#include <windows.h>  // 包含 Windows API 的函数声明
#include <stdio.h>    // 包含 printf() 函数声明

// 线程函数：每个线程执行的代码
// 参数 arg 是传递给线程的参数
// 返回值是线程结束时返回的值
DWORD WINAPI ThreadFunc(LPVOID arg) {
    // 将参数转换为整数
    int id = *(int*)arg;
    
    // 打印线程 ID
    printf("线程 %d 正在运行\n", id);
    
    // 线程结束时返回 0
    return 0;
}

int main() {
    // 定义线程句柄数组，存储 3 个线程的句柄
    HANDLE threads[3];
    
    // 定义传递给线程的参数数组
    int ids[3] = {1, 2, 3};
    
    // 创建 3 个线程
    for (int i = 0; i < 3; i++) {
        // CreateThread() 创建新线程
        // 参数1：安全属性，NULL 表示默认
        // 参数2：栈大小，0 表示使用默认大小
        // 参数3：线程函数，线程要执行的代码
        // 参数4：传递给线程函数的参数
        // 参数5：创建标志，0 表示立即运行
        // 参数6：接收线程 ID 的指针，NULL 表示不关心
        threads[i] = CreateThread(
            NULL,           // 安全属性
            0,              // 栈大小
            ThreadFunc,     // 线程函数
            &ids[i],        // 参数
            0,              // 创建标志
            NULL            // 线程 ID
        );
    }
    
    // 等待所有线程结束
    // WaitForMultipleObjects() 等待多个对象（线程）
    // 参数1：对象数量
    // 参数2：对象句柄数组
    // 参数3：是否等待所有对象，TRUE 表示等待所有
    // 参数4：超时时间，INFINITE 表示无限等待
    WaitForMultipleObjects(3, threads, TRUE, INFINITE);
    
    // 关闭线程句柄，释放资源
    for (int i = 0; i < 3; i++) {
        CloseHandle(threads[i]);
    }
    
    // 打印主线程结束信息
    printf("所有线程已完成\n");
    
    return 0;
}
```

## 4.6 并发带来的问题

多线程共享资源带来了效率，但也引入了严重的问题。最主要的问题有两个：数据竞争和死锁。

### 数据竞争（Data Race）

数据竞争是指多个线程同时访问同一个数据，且至少有一个线程在修改数据，导致最终结果不确定。

打个比方：

> 数据竞争就像两个人同时编辑同一个文档。A 写了一句话，B 也写了一句话，最后文档里可能只有 A 的话或 B 的话，或者两人的话混在一起变得乱七八糟。

```c
#include <stdio.h>
#include <pthread.h>

// 全局变量，被多个线程共享
int counter = 0;

// 线程函数：对 counter 进行 100000 次加 1 操作
void* increment(void* arg) {
    // 循环 100000 次
    for (int i = 0; i < 100000; i++) {
        // 错误：counter++ 不是原子操作！
        // 它实际上包含三个步骤：
        // 1. 从内存读取 counter 的值
        // 2. 将值加 1
        // 3. 将新值写回内存
        // 如果两个线程同时执行这三步，就会出现问题
        counter++;  // 非原子操作！
    }
    return NULL;
}

int main() {
    // 创建两个线程
    pthread_t t1, t2;
    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);
    
    // 等待两个线程结束
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    
    // 期望结果：200000
    // 实际结果：可能小于 200000，因为发生了数据竞争
    printf("counter = %d\n", counter);
    
    return 0;
}
```

```
数据竞争的发生过程：

线程 A                          线程 B
─────────────────────────────────────────────
读取 counter = 0
                                读取 counter = 0
counter = 0 + 1 = 1
                                counter = 0 + 1 = 1
写入 counter = 1
                                写入 counter = 1
─────────────────────────────────────────────
结果：counter = 1（期望是 2）
```

解决方案：使用互斥锁（Mutex）保证同一时刻只有一个线程可以访问共享数据。

```c
#include <stdio.h>
#include <pthread.h>

// 全局变量
int counter = 0;

// 互斥锁，用于保护共享数据
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

// 线程函数
void* increment(void* arg) {
    for (int i = 0; i < 100000; i++) {
        // 加锁：获取互斥锁
        // 如果锁已被其他线程持有，当前线程会阻塞等待
        pthread_mutex_lock(&lock);
        
        // 临界区：同一时刻只有一个线程可以执行这段代码
        counter++;
        
        // 解锁：释放互斥锁，允许其他线程进入临界区
        pthread_mutex_unlock(&lock);
    }
    return NULL;
}

int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, increment, NULL);
    pthread_create(&t2, NULL, increment, NULL);
    
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    
    // 现在结果一定是 200000
    printf("counter = %d\n", counter);
    
    // 销毁互斥锁，释放资源
    pthread_mutex_destroy(&lock);
    
    return 0;
}
```

### 死锁（Deadlock）

死锁是指两个或多个线程相互等待对方释放资源，导致所有线程都无法继续执行。

打个比方：

> 死锁就像两个人在窄路上相遇，都不肯让路，结果两个人都过不去。或者像四个人围着一张桌子吃饭，每个人都需要左右两只筷子，但每个人都只拿了一只筷子，结果谁都吃不了。

```c
#include <stdio.h>
#include <pthread.h>
#include <unistd.h>

// 定义两把锁
pthread_mutex_t lock1 = PTHREAD_MUTEX_INITIALIZER;
pthread_mutex_t lock2 = PTHREAD_MUTEX_INITIALIZER;

// 线程 A 的函数
void* thread_a(void* arg) {
    // 线程 A 先获取锁 1
    pthread_mutex_lock(&lock1);
    printf("线程 A：已获取锁 1\n");
    
    // 模拟一些工作
    sleep(1);
    
    // 线程 A 尝试获取锁 2
    // 如果锁 2 已被线程 B 持有，线程 A 会阻塞等待
    pthread_mutex_lock(&lock2);
    printf("线程 A：已获取锁 2\n");
    
    // 释放锁
    pthread_mutex_unlock(&lock2);
    pthread_mutex_unlock(&lock1);
    
    return NULL;
}

// 线程 B 的函数
void* thread_b(void* arg) {
    // 线程 B 先获取锁 2
    pthread_mutex_lock(&lock2);
    printf("线程 B：已获取锁 2\n");
    
    // 模拟一些工作
    sleep(1);
    
    // 线程 B 尝试获取锁 1
    // 如果锁 1 已被线程 A 持有，线程 B 会阻塞等待
    pthread_mutex_lock(&lock1);
    printf("线程 B：已获取锁 1\n");
    
    // 释放锁
    pthread_mutex_unlock(&lock1);
    pthread_mutex_unlock(&lock2);
    
    return NULL;
}

int main() {
    pthread_t t1, t2;
    
    // 创建两个线程
    pthread_create(&t1, NULL, thread_a, NULL);
    pthread_create(&t2, NULL, thread_b, NULL);
    
    // 等待线程结束
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    
    printf("程序结束\n");
    
    return 0;
}
```

```
死锁的发生过程：

时间线                          线程 A                    线程 B
─────────────────────────────────────────────────────────────────
T1                             获取锁 1 ✓
T2                                                         获取锁 2 ✓
T3                             尝试获取锁 2 → 阻塞等待
T4                                                         尝试获取锁 1 → 阻塞等待
─────────────────────────────────────────────────────────────────
结果：两个线程都在等待对方释放锁，永远无法继续执行
```

解决方案：

1. **按固定顺序获取锁**：所有线程都先获取锁 1，再获取锁 2
2. **使用超时机制**：获取锁时设置超时时间，超时后放弃
3. **使用死锁检测**：操作系统检测死锁并强制释放某些锁

```c
// 解决方案：按固定顺序获取锁
void* thread_a_fixed(void* arg) {
    // 线程 A 先获取锁 1，再获取锁 2
    pthread_mutex_lock(&lock1);
    pthread_mutex_lock(&lock2);
    
    // 工作...
    
    pthread_mutex_unlock(&lock2);
    pthread_mutex_unlock(&lock1);
    
    return NULL;
}

void* thread_b_fixed(void* arg) {
    // 线程 B 也先获取锁 1，再获取锁 2（相同顺序）
    pthread_mutex_lock(&lock1);
    pthread_mutex_lock(&lock2);
    
    // 工作...
    
    pthread_mutex_unlock(&lock2);
    pthread_mutex_unlock(&lock1);
    
    return NULL;
}
```

## 4.8 新手常见误区

### 误区 1："线程比进程轻量，所以应该总是使用线程"

不对。线程确实比进程轻量，创建快、切换快、通信方便。但线程也有自己的问题：

1. **共享资源带来同步问题**：多个线程共享进程的内存，需要小心处理同步，否则会出现数据竞争
2. **一个线程崩溃会导致整个进程崩溃**：因为线程共享进程的资源，一个线程出错可能导致整个进程崩溃
3. **调试困难**：多线程程序的执行顺序不确定，调试起来比单线程程序困难得多

```c
// 错误理解：线程总是比进程好
// 正确理解：线程和进程各有优缺点，要根据场景选择

// 适合使用线程的场景：
// - 需要频繁切换的任务
// - 需要频繁通信的任务
// - 任务之间需要共享大量数据

// 适合使用进程的场景：
// - 任务之间需要隔离，一个崩溃不影响其他
// - 任务之间不需要频繁通信
// - 需要更高的安全性
```

### 误区 2："多线程程序一定比单线程程序快"

不对。多线程程序只有在以下情况下才会比单线程程序快：

1. **有多个 CPU 核心**：如果只有一个核心，多线程只是轮流执行，不会真正并行
2. **任务可以并行**：如果任务之间有依赖关系，必须按顺序执行，多线程也不会更快
3. **线程开销小于收益**：创建和切换线程也有开销，如果任务太小，开销可能大于收益

```c
// 错误理解：多线程总是更快
// 正确理解：多线程只在特定场景下更快

// 单核 CPU 上的多线程：
// 线程A → 线程B → 线程A → 线程B（轮流执行，不是真正并行）

// 多核 CPU 上的多线程：
// 核心1：线程A
// 核心2：线程B（真正并行）
```

### 误区 3："共享内存不需要加锁"

不对。共享内存虽然方便，但多个线程同时读写共享内存时，必须加锁保护，否则会出现数据竞争。

```c
// 错误理解：共享内存可以直接读写
// 正确理解：共享内存需要加锁保护

// 错误做法：
void* increment_wrong(void* arg) {
    for (int i = 0; i < 100000; i++) {
        counter++;  // 没有加锁，会出现数据竞争
    }
    return NULL;
}

// 正确做法：
void* increment_correct(void* arg) {
    for (int i = 0; i < 100000; i++) {
        pthread_mutex_lock(&lock);  // 加锁
        counter++;
        pthread_mutex_unlock(&lock);  // 解锁
    }
    return NULL;
}
```

### 误区 4："死锁是可以避免的，只要小心一点"

不对。死锁是并发编程中很难完全避免的问题。虽然可以通过一些策略（如按固定顺序获取锁）来降低死锁的概率，但在复杂的系统中，完全避免死锁几乎不可能。

```c
// 错误理解：只要小心就能避免死锁
// 正确理解：死锁很难完全避免，需要设计良好的锁策略

// 死锁的四个必要条件（必须同时满足才会发生死锁）：
// 1. 互斥条件：资源同一时刻只能被一个线程持有
// 2. 持有并等待：线程持有至少一个资源，同时等待其他资源
// 3. 不可抢占：资源只能由持有者主动释放
// 4. 循环等待：存在一个线程等待环

// 破坏其中任何一个条件就可以避免死锁，但可能会带来其他问题
```

### 误区 5："用户级线程比内核级线程好"

不对。用户级线程和内核级线程各有优缺点，要根据场景选择。

- **用户级线程**：切换快，但无法利用多核，一个线程阻塞会导致整个进程阻塞
- **内核级线程**：可以利用多核，一个线程阻塞不影响其他线程，但切换开销大

```c
// 错误理解：用户级线程总是更好
// 正确理解：要根据场景选择

// 适合使用用户级线程的场景：
// - 单核 CPU
// - 需要快速切换
// - 不需要真正的并行

// 适合使用内核级线程的场景：
// - 多核 CPU
// - 需要真正的并行
// - 需要更好的响应性
```

### 练习 3（挑战）：综合练习

设计一个多线程程序，模拟生产者-消费者问题。创建一个共享缓冲区（大小为 5），3 个生产者线程和 2 个消费者线程。生产者向缓冲区添加数据（1-100），消费者从缓冲区取出数据并打印。使用互斥锁和条件变量实现同步。

提示：
- 使用互斥锁保护共享缓冲区
- 使用条件变量实现生产者和消费者之间的同步
- 缓冲区满时生产者等待，缓冲区空时消费者等待

<details>
<summary>点击查看答案</summary>

参考答案：

```c
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

// 缓冲区大小
#define BUFFER_SIZE 5

// 共享缓冲区
int buffer[BUFFER_SIZE];
int count = 0;  // 缓冲区中物品的数量

// 互斥锁
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;

// 条件变量
pthread_cond_t producer_cond = PTHREAD_COND_INITIALIZER;
pthread_cond_t consumer_cond = PTHREAD_COND_INITIALIZER;

// 生产者线程函数
void* producer(void* arg) {
    int id = *(int*)arg;
    
    // 生产 10 个物品
    for (int i = 1; i <= 10; i++) {
        // 加锁
        pthread_mutex_lock(&lock);
        
        // 缓冲区满时等待
        while (count == BUFFER_SIZE) {
            printf("生产者 %d：缓冲区满，等待...\n", id);
            pthread_cond_wait(&producer_cond, &lock);
        }
        
        // 生产物品
        buffer[count++] = i;
        printf("生产者 %d：生产物品 %d，缓冲区数量 = %d\n", id, i, count);
        
        // 唤醒消费者
        pthread_cond_signal(&consumer_cond);
        
        // 解锁
        pthread_mutex_unlock(&lock);
        
        // 模拟生产时间
        usleep(100000);  // 0.1 秒
    }
    
    return NULL;
}

// 消费者线程函数
void* consumer(void* arg) {
    int id = *(int*)arg;
    
    // 消费 15 个物品
    for (int i = 0; i < 15; i++) {
        // 加锁
        pthread_mutex_lock(&lock);
        
        // 缓冲区空时等待
        while (count == 0) {
            printf("消费者 %d：缓冲区空，等待...\n", id);
            pthread_cond_wait(&consumer_cond, &lock);
        }
        
        // 消费物品
        int item = buffer[--count];
        printf("消费者 %d：消费物品 %d，缓冲区数量 = %d\n", id, item, count);
        
        // 唤醒生产者
        pthread_cond_signal(&producer_cond);
        
        // 解锁
        pthread_mutex_unlock(&lock);
        
        // 模拟消费时间
        usleep(150000);  // 0.15 秒
    }
    
    return NULL;
}

int main() {
    // 定义生产者和消费者线程
    pthread_t producers[3];
    pthread_t consumers[2];
    
    // 定义线程 ID
    int producer_ids[3] = {1, 2, 3};
    int consumer_ids[2] = {1, 2};
    
    // 创建生产者线程
    for (int i = 0; i < 3; i++) {
        pthread_create(&producers[i], NULL, producer, &producer_ids[i]);
    }
    
    // 创建消费者线程
    for (int i = 0; i < 2; i++) {
        pthread_create(&consumers[i], NULL, consumer, &consumer_ids[i]);
    }
    
    // 等待所有线程结束
    for (int i = 0; i < 3; i++) {
        pthread_join(producers[i], NULL);
    }
    for (int i = 0; i < 2; i++) {
        pthread_join(consumers[i], NULL);
    }
    
    printf("所有生产者和消费者已完成\n");
    
    // 销毁互斥锁和条件变量
    pthread_mutex_destroy(&lock);
    pthread_cond_destroy(&producer_cond);
    pthread_cond_destroy(&consumer_cond);
    
    return 0;
}
```
