# 第二章：操作系统结构

## 内核态与用户态

现代操作系统通过**双模式**（Dual Mode）运行来保护系统资源。CPU 提供了两种不同的执行模式：

| 模式 | 别名 | 权限 | 运行内容 |
| --- | --- | --- | --- |
| 内核态（Kernel Mode） | 特权模式、管态 | 可执行所有指令，访问所有资源 | 操作系统内核代码 |
| 用户态（User Mode） | 非特权模式、目态 | 只能执行非特权指令 | 用户程序 |

### 为什么需要两种模式？

::: info
如果所有程序都在内核态运行，一个有 Bug 的程序就可能覆盖操作系统的代码或数据，甚至破坏其他进程的数据。双模式机制是操作系统安全的基础。
:::

### 模式切换

```
用户程序执行（用户态）
    │
    ├── 系统调用 ──> 陷入内核 ──> 内核态执行
    │                                │
    │                                ├── 执行完毕 ──> 返回用户态
    │                                │
    ├── 中断发生 ──> 保存现场 ──> 内核态执行中断处理
    │                                │
    │                                ├── 处理完毕 ──> 恢复现场 ──> 返回用户态
    │
    └── 执行特权指令 ──> 触发异常 ──> 操作系统终止程序
```

::: tip
从用户态切换到内核态的唯一途径是**中断**或**异常（Exception）**。用户程序不能主动切换到内核态后继续执行自己的代码。
:::

## 系统调用

系统调用（System Call）是用户程序请求操作系统服务的接口。它是用户态与内核态之间的桥梁。

### 常见的系统调用分类

| 类别 | 示例 | 说明 |
| --- | --- | --- |
| 进程控制 | `fork()`, `exit()`, `wait()` | 创建、终止、等待进程 |
| 文件管理 | `open()`, `read()`, `write()`, `close()` | 文件的打开、读写、关闭 |
| 设备管理 | `ioctl()`, `read()`, `write()` | 设备请求和控制 |
| 信息维护 | `getpid()`, `alarm()`, `sleep()` | 获取/设置系统信息 |
| 通信 | `pipe()`, `shmget()`, `socket()` | 进程间通信 |
| 保护 | `chmod()`, `chown()` | 访问控制 |

### 系统调用的执行过程

以 Linux 下 `write()` 系统调用为例：

```c
#include <unistd.h>
#include <stdio.h>

int main() {
    char msg[] = "Hello, OS!\n";
    // write 是一个系统调用
    // 参数：文件描述符、缓冲区、字节数
    write(STDOUT_FILENO, msg, sizeof(msg) - 1);
    return 0;
}
```

执行流程：

```
1. 用户程序调用 write()（用户态 C 库函数）
2. C 库将系统调用号存入寄存器（如 eax = 4）
3. 执行 trap 指令（如 int 0x80 或 syscall）
4. CPU 切换到内核态，跳转到系统调用处理入口
5. 内核根据调用号查表，找到对应的处理函数 sys_write()
6. 执行实际的 I/O 操作
7. 将结果存入寄存器，切换回用户态
8. 用户程序继续执行
```

::: info
在 Linux 中，系统调用号存放在 `eax` 寄存器（x86）或 `x8` 寄存器（x86_64）中。参数分别存放在 `ebx`、`ecx`、`edx` 等寄存器中。
:::

### POSIX 与 Win32 API

| 标准 | 适用系统 | 示例 |
| --- | --- | --- |
| POSIX | UNIX/Linux/macOS | `fork()`, `pthread_create()`, `open()` |
| Win32 API | Windows | `CreateProcess()`, `CreateFile()`, `CreateThread()` |

```c
// POSIX 创建进程
pid_t pid = fork();

// Win32 创建进程
BOOL result = CreateProcess(
    NULL,           // 应用名称
    "notepad.exe",  // 命令行
    NULL, NULL,     // 安全属性
    FALSE,          // 不继承句柄
    0,              // 创建标志
    NULL, NULL,     // 环境/目录
    &si, &pi        // 启动信息/进程信息
);
```

## 中断机制

中断是操作系统响应外部事件的核心机制。没有中断，操作系统就无法及时响应 I/O 完成、硬件错误等事件。

### 中断的分类

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 外中断（硬件中断） | 由 CPU 外部的硬件设备发出 | 键盘输入、定时器中断、I/O 完成 |
| 内中断（异常） | 由 CPU 执行指令时内部产生 | 除零错误、缺页异常、非法指令 |
| 陷入（Trap） | 由程序主动执行 trap 指令产生 | 系统调用 |

```
中断来源分类：

┌─────────────────────────────────────────┐
│                 中断                     │
├──────────────┬──────────────────────────┤
│   外中断      │        内中断            │
│  (异步)      │       (同步)             │
├──────────────┼────────────┬─────────────┤
│  可屏蔽中断   │  不可屏蔽  │   陷入      │
│  (键盘/定时器)│  (硬件故障) │  (系统调用)  │
└──────────────┴────────────┴─────────────┘
```

### 中断处理过程

```
1. 设备发出中断信号
2. CPU 完成当前指令后检查中断请求
3. CPU 保存当前程序计数器（PC）和寄存器状态
4. CPU 根据中断向量表找到对应的处理程序入口
5. 执行中断服务程序（ISR）
6. 恢复被中断程序的现场
7. 继续执行被中断的程序
```

### 中断向量表

中断向量表（Interrupt Vector Table, IVT）存储了每个中断对应的处理程序入口地址。

| 中断号 | 类型 | 说明 |
| --- | --- | --- |
| 0 | 异常 | 除零错误 |
| 6 | 异常 | 非法指令 |
| 13 | 异常 | 通用保护异常 |
| 14 | 异常 | 缺页异常 |
| 32 | 外中断 | 定时器中断 |
| 33 | 外中断 | 键盘中断 |
| 128 (0x80) | 陷入 | Linux 系统调用（x86） |

::: tip
现代操作系统使用**中断描述符表（IDT）**代替传统的中断向量表。IDT 支持更丰富的中断类型和更灵活的处理方式。
:::

## 操作系统结构

### 简单结构

早期操作系统（如 MS-DOS）没有明确的模块划分，代码高度耦合。

```
┌──────────────────┐
│   应用程序        │
├──────────────────┤
│   BIOS / DOS     │  ← 没有清晰的模块边界
├──────────────────┤
│   硬件           │
└──────────────────┘
```

### 分层结构

将操作系统划分为多个层次，每层只使用下一层提供的服务。

```
┌──────────────────┐
│  第 N 层：用户界面 │
├──────────────────┤
│  第 N-1 层：...   │
├──────────────────┤
│    ...            │
├──────────────────┤
│  第 1 层：硬件抽象 │
├──────────────────┤
│  第 0 层：硬件    │
└──────────────────┘
```

::: info
分层结构的优点是**模块化**和**易于调试**。缺点是层次间调用可能带来性能开销，且层次划分有时不够灵活。
:::

### 微内核结构

只将最基本的功能放入内核，其余功能以用户态进程（服务）的形式运行。

| 微内核提供的功能 | 用户态服务 |
| --- | --- |
| 进程间通信（IPC） | 文件系统服务 |
| 基本调度 | 内存管理服务 |
| 基本地址空间 | 设备驱动服务 |

::: tip
微内核的优点是可靠性高（一个服务崩溃不影响系统）、安全性好、易于扩展。缺点是 IPC 开销大，性能可能低于宏内核。
:::

## 本章小结

- 操作系统通过**内核态**和**用户态**双模式保护系统资源
- **系统调用**是用户程序请求内核服务的唯一接口
- **中断**分为外中断（硬件中断）、内中断（异常）和陷入（系统调用）
- 中断处理过程：保存现场 → 查中断向量表 → 执行处理程序 → 恢复现场
- 操作系统结构经历了简单结构 → 分层结构 → 微内核结构的演进
