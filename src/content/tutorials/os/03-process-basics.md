# 第三章：进程管理基础

## 本章导读

在学这一章之前，你可能会有这些疑问：

- 进程到底是什么？它和程序有什么区别？
- 进程有哪几种状态？它们之间是怎么切换的？
- 操作系统是怎么管理成千上万个进程的？
- 进程之间怎么通信？为什么不能直接访问彼此的内存？

这一章就是为了解答这些问题。我们会先搞清楚进程的概念，再学习进程的状态转换，然后了解操作系统是怎么通过 PCB 管理进程的，最后看看进程之间是怎么通信的。学完之后，你会对"运行中的程序"有一个完整的认识。

---

## 1 为什么需要进程？

### 痛点分析

想象一下，如果没有进程的概念，操作系统会面临什么问题？

1. 你同时打开浏览器、微信、音乐播放器，操作系统怎么知道哪个程序在用 CPU？
2. 浏览器卡死了，操作系统怎么只关掉浏览器，而不影响其他程序？
3. 两个程序同时要打印，操作系统怎么协调谁先谁后？
4. 程序 A 想把自己计算的结果给程序 B，怎么传递？

这就好比一个餐厅同时来了 100 桌客人，但没有"桌号"的概念。服务员不知道哪桌点了什么菜，不知道哪桌要结账，不知道哪桌在等位。

### 解决方案

操作系统引入了"进程"的概念。每个运行中的程序都是一个进程，有自己的"身份证号"（PID）、"状态"（在运行/在等待/结束了）、"资源"（占用的内存、打开的文件）。

打个比方：

> 进程就像餐厅里的每一桌客人。每桌有自己的桌号（PID），有自己的状态（点菜中/用餐中/结账中），有自己的资源（点的菜、用的餐具）。服务员（操作系统）根据桌号管理每一桌，知道哪桌需要什么服务。

```
没有进程：操作系统看到的是一堆代码在运行
  程序A的代码 + 程序B的代码 + 程序C的代码 → 混在一起，分不清谁是谁

有了进程：操作系统看到的是一个个独立的"执行单元"
  进程1（程序A）：PID=1001，状态=运行，占用内存=100MB
  进程2（程序B）：PID=1002，状态=等待，占用内存=50MB
  进程3（程序C）：PID=1003，状态=就绪，占用内存=200MB
```

> 一句话总结：进程是操作系统管理运行中程序的基本单位，让多任务管理变得可能。

## 2 进程的概念

### 什么是进程

**进程（Process）** 是操作系统进行资源分配和调度的基本单位。简单来说，进程是**正在运行的程序的实例**。

打个比方：

> 程序就像菜谱，是静态的、永久存在的。进程就像按照菜谱做出来的一道道菜，是动态的、有生命周期的。同一份菜谱可以同时做很多道菜（一个程序可以同时运行多个实例）。

### 进程与程序的区别

| 对比项 | 程序（Program） | 进程（Process） | 生活化类比 |
| --- | --- | --- | --- |
| 本质 | 静态的代码文件 | 动态的执行过程 | 像菜谱 vs 正在做的菜 |
| 生命周期 | 永久存在 | 有创建、执行、消亡的过程 | 像菜谱永远在，但菜做完就没了 |
| 资源占用 | 不占用运行资源 | 占用 CPU、内存等资源 | 像菜谱不占盘子，但菜要占盘子 |
| 并发性 | 无 | 具有并发性 | 像菜谱不能同时吃，但可以多桌同时用餐 |
| 对应关系 | 一个程序可对应多个进程 | 一个进程对应一个程序（或多个） | 像一份菜谱可以同时做很多份菜 |

```c
// 示例：同一个程序可以运行多个实例
#include <stdio.h>
#include <unistd.h>

int main() {
    // 这个程序可以同时运行多个实例
    // 每个实例都是一个独立的进程
    printf("我是进程，PID = %d\n", getpid());
    sleep(10);  // 暂停 10 秒，让你有时间启动多个实例
    return 0;
}
```

```bash
# 在终端运行多次，每次都会创建一个新的进程
./my_program &  # 后台运行第一个实例
./my_program &  # 后台运行第二个实例
./my_program &  # 后台运行第三个实例

# 查看进程
ps aux | grep my_program
```

### 进程的组成

```
进程 = 程序段 + 数据段 + PCB（进程控制块）
```

- **程序段**：要执行的代码（就像菜谱）
- **数据段**：程序运行所需的数据（就像做菜的原料）
- **PCB**：描述进程状态、资源使用情况的数据结构（就像这桌客人的点菜单）

## 3 进程的状态与转换

### 五状态模型

进程在生命周期中会经历不同的状态。就像一个人在餐厅用餐，会经历"等位→入座→点菜→用餐→结账"几个阶段。

```
                    创建
                     |
                     v
              +-------------+
              |   新创建     |  <-- 刚创建的进程，还没准备好
              +------+------+
                     | 被调度
                     v
              +-------------+
         +--->|   运行       |<---+
         |    +------+------+    |
         |           |           |
    I/O完成|     时间片到|      阻塞结束
    或事件 |           v           |
         |    +-------------+    |
         |    |   就绪       |    |  <-- 万事俱备，只欠 CPU
         |    +------+------+    |
         |           |           |
         |           | 请求I/O   |
         |           v           |
         |    +-------------+    |
         +----|   阻塞       |----+  <-- 等待某个事件发生
              +------+------+
                     | I/O完成
                     v
              +-------------+
              |   终止       |  <-- 进程结束
              +-------------+
```

| 状态 | 说明 | 生活化类比 |
| --- | --- | --- |
| 新创建（New） | 进程刚被创建，尚未完全就绪 | 像客人刚进餐厅，还没安排座位 |
| 就绪（Ready） | 已分配到除 CPU 外的所有资源，等待 CPU | 像客人已入座，等服务员来点菜 |
| 运行（Running） | 正在 CPU 上执行 | 像客人正在点菜、用餐 |
| 阻塞（Blocked/Waiting） | 等待某个事件发生（如 I/O 完成、信号量） | 像客人等菜上桌，菜没来就不能吃 |
| 终止（Terminated） | 进程执行完毕或被强制终止 | 像客人结账离开 |

### 状态转换条件

| 转换 | 触发条件 | 生活化类比 |
| --- | --- | --- |
| 就绪 → 运行 | 调度器选中该进程，分配 CPU | 像服务员开始为这桌点菜 |
| 运行 → 就绪 | 时间片用完或被更高优先级进程抢占 | 像服务员说"我先去服务其他桌，等下再来" |
| 运行 → 阻塞 | 进程主动请求 I/O 或等待某事件 | 像客人点完菜，等厨房做菜 |
| 阻塞 → 就绪 | 等待的事件已完成（如 I/O 结束） | 像菜做好了，服务员端上桌 |

```c
// 示例：进程状态转换
#include <stdio.h>
#include <unistd.h>

int main() {
    // 就绪状态：进程已创建，等待 CPU
    printf("进程已创建，PID = %d\n", getpid());
    
    // 运行状态：正在执行代码
    for (int i = 0; i < 5; i++) {
        printf("运行中... %d\n", i);
        sleep(1);  // 模拟耗时操作
    }
    
    // 阻塞状态：等待 I/O（这里是等待用户输入）
    char input[100];
    printf("请输入内容：");
    scanf("%s", input);  // 进程阻塞，等待用户输入
    printf("收到输入: %s\n", input);
    
    // 终止状态：进程结束
    printf("进程即将终止\n");
    return 0;
}
```

```
注意：就绪 → 阻塞 的转换不会发生。
因为处于就绪状态的进程还没有开始运行，不可能主动发起 I/O 请求。

就像客人还没入座（就绪），不可能开始等菜（阻塞）。
```

### 七状态模型

在五状态模型基础上增加**挂起（Suspend）** 状态：

| 状态 | 说明 | 生活化类比 |
| --- | --- | --- |
| 就绪挂起（Ready/Suspend） | 进程在就绪但被换出到外存 | 像客人被安排到门外等位，不在餐厅里 |
| 阻塞挂起（Blocked/Suspend） | 进程在阻塞且被换出到外存 | 像客人点的菜要等很久，他先去逛街了 |

引入挂起状态的原因：

1. 内存不足时，将部分进程换出到磁盘（就像餐厅满了，让一些客人去门外等）
2. 用户需要暂停自己的进程（就像客人说"我先去个洗手间"）
3. 操作系统需要释放内存空间（就像餐厅要清理座位给新客人）

## 4 进程控制块（PCB）

**进程控制块（Process Control Block, PCB）** 是操作系统用来描述和管理进程的数据结构。每个进程有且仅有一个 PCB。

打个比方：

> PCB 就像餐厅里每桌客人的"点菜单"。上面记录了这桌客人的桌号（PID）、状态（在点菜/在用餐/在等菜）、点了什么菜（打开的文件）、用了多少资源（占用多少内存）等信息。服务员（操作系统）通过看点菜单来管理每一桌。

### PCB 包含的信息

```c
struct PCB {
    // 1. 进程标识 - 相当于"桌号"
    int pid;                // 进程 ID，唯一标识一个进程
    int ppid;               // 父进程 ID，谁创建了这个进程
    int uid;                // 用户 ID，哪个用户创建的
    
    // 2. 进程状态 - 相当于"这桌客人在干嘛"
    int state;              // 当前状态（就绪/运行/阻塞）
    int priority;           // 优先级，VIP 客人优先服务
    
    // 3. 处理器状态（上下文信息） - 相当于"客人刚才说到哪了"
    int registers[16];      // 通用寄存器，保存进程执行到哪了
    int pc;                 // 程序计数器，下一条要执行的指令地址
    int psw;                // 程序状态字，记录 CPU 的状态
    
    // 4. 进程调度信息 - 相当于"这桌客人等了多久"
    int queue_priority;     // 在就绪队列中的优先级
    int cpu_time_used;      // 已使用的 CPU 时间
    
    // 5. 进程控制信息 - 相当于"这桌客人点了什么菜"
    int memory_base;        // 内存基址，进程在内存中的起始位置
    int memory_limit;       // 内存界限，进程能使用的内存范围
    int open_files[10];     // 打开的文件列表，进程打开了哪些文件
    int signal_mask;        // 信号掩码，进程屏蔽了哪些信号
};
```

| PCB 信息类别 | 包含内容 | 生活化类比 |
| --- | --- | --- |
| 进程标识 | PID、PPID、UID | 像桌号、谁带来的、哪个服务员负责 |
| 处理机状态 | 通用寄存器、PC、PSW | 像客人刚才聊到哪了，下次从哪继续 |
| 进程调度信息 | 状态、优先级、已用 CPU 时间 | 像客人等了多久、是不是 VIP |
| 进程控制信息 | 内存信息、打开文件、信号掩码 | 像客人点了什么菜、用了哪些餐具 |

```c
// 示例：上下文切换
// 当进程 A 切换到进程 B 时，操作系统需要：

// 1. 保存进程 A 的现场
void context_switch_A_to_B() {
    // 把进程 A 的寄存器值保存到它的 PCB
    process_A.pcb.registers[0] = R0;  // 保存 R0 寄存器
    process_A.pcb.registers[1] = R1;  // 保存 R1 寄存器
    process_A.pcb.pc = PC;            // 保存程序计数器
    process_A.pcb.state = READY;      // 进程 A 变为就绪状态
    
    // 2. 恢复进程 B 的现场
    // 从进程 B 的 PCB 中恢复寄存器值
    R0 = process_B.pcb.registers[0];  // 恢复 R0 寄存器
    R1 = process_B.pcb.registers[1];  // 恢复 R1 寄存器
    PC = process_B.pcb.pc;            // 恢复程序计数器
    process_B.pcb.state = RUNNING;    // 进程 B 变为运行状态
    
    // 3. 跳转到进程 B 的下一条指令继续执行
}
```

## 5 进程控制

操作系统通过一系列原语（Primitive）来管理进程的生命周期。原语是不可中断的操作，要么全做，要么全不做。

### 进程创建

```c
// Linux 中使用 fork() 创建新进程
#include <unistd.h>   // 包含 fork()、getpid() 等函数声明
#include <stdio.h>    // 包含 printf() 函数声明
#include <sys/wait.h> // 包含 wait() 函数声明

int main() {
    // fork() 创建子进程，返回值有两个可能：
    // - 在父进程中：返回子进程的 PID（大于 0）
    // - 在子进程中：返回 0
    // - 如果失败：返回 -1
    pid_t pid = fork();  // 创建子进程
    
    if (pid < 0) {
        // fork 失败
        perror("fork failed");  // 打印错误信息
    } else if (pid == 0) {
        // 子进程执行的代码
        // getpid() 返回当前进程的 PID
        printf("我是子进程，PID = %d\n", getpid());
        printf("我的父进程 PID = %d\n", getppid());
    } else {
        // 父进程执行的代码
        // pid 就是子进程的 PID
        printf("我是父进程，PID = %d\n", getpid());
        printf("子进程 PID = %d\n", pid);
        wait(NULL);  // 等待子进程结束，防止产生僵尸进程
    }
    
    return 0;
}
```

创建进程时操作系统需要：

1. 为新进程分配 PCB 和内存空间（就像给新客人安排桌位）
2. 初始化 PCB（PID、状态、优先级等）（就像填写点菜单）
3. 将父进程的数据复制到子进程（就像给新客人一份菜单）
4. 将子进程插入就绪队列（就像让新客人在门口等位）

### 进程终止

```c
#include <stdlib.h>  // 包含 exit() 函数声明
#include <unistd.h>  // 包含 _exit() 函数声明

int main() {
    // 正常终止方式 1：调用 exit()
    // exit(0) 表示正常退出，0 是返回给父进程的状态码
    exit(0);  // 退出并返回状态码 0
    
    // 正常终止方式 2：在 main 函数中 return
    return 0;  // 等价于 exit(0)
    
    // 异常终止：调用 abort()
    // abort();  // 发送 SIGABRT 信号，强制终止进程
}
```

进程终止时操作系统需要：

1. 查询 PCB 获取进程状态（看看这桌客人吃得怎么样了）
2. 如果正在运行，终止执行，释放 CPU（让客人停止用餐）
3. 如果有子进程，将其转交给 init 进程（孤儿进程）（客人走了，他带来的朋友由餐厅照顾）
4. 回收进程占有的所有资源（内存、文件等）（清理桌子、收回餐具）
5. 删除 PCB（把这桌的记录从点菜单上划掉）

### 进程阻塞与唤醒

```c
// 阻塞：进程主动等待
#include <stdio.h>

int main() {
    char input[100];  // 定义缓冲区
    
    // scanf() 会阻塞进程，等待用户输入
    // 进程从运行状态变为阻塞状态
    printf("请输入内容：");
    scanf("%s", input);  // 进程阻塞，等待输入完成
    
    // 输入完成后，进程被唤醒，从阻塞状态变为就绪状态
    printf("收到输入: %s\n", input);
    
    return 0;
}
```

```c
// 唤醒：由操作系统或其他进程完成
// 例如 I/O 完成中断触发操作系统唤醒等待该 I/O 的进程

// 示例：父进程等待子进程完成
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    pid_t pid = fork();  // 创建子进程
    
    if (pid == 0) {
        // 子进程
        printf("子进程开始运行\n");
        sleep(3);  // 模拟耗时操作，子进程阻塞 3 秒
        printf("子进程运行完成\n");
        exit(0);  // 子进程终止
    } else {
        // 父进程
        printf("父进程等待子进程完成...\n");
        // wait() 会阻塞父进程，直到子进程终止
        // 子进程终止后，父进程被唤醒
        wait(NULL);
        printf("父进程：子进程已完成\n");
    }
    
    return 0;
}
```

```
注意：进程的阻塞和唤醒必须成对出现。
阻塞是进程主动行为（就像客人说"我等菜"），
唤醒通常由操作系统或另一个进程完成（就像菜做好了，服务员通知客人）。
```

## 6 进程通信

进程之间可以交换信息，常见的通信方式：

| 方式 | 说明 | 特点 | 生活化类比 |
| --- | --- | --- | --- |
| 管道（Pipe） | 半双工的数据通道 | 只能用于有亲缘关系的进程 | 像父子之间的传话筒 |
| 消息队列 | 消息的链表 | 内核维护，可跨进程通信 | 像餐厅的公告板，谁都可以看 |
| 共享内存 | 多个进程映射同一块内存 | 最快的 IPC 方式 | 像多人共用的白板 |
| 信号量（Semaphore） | 用于同步的计数器 | 主要用于进程同步 | 像红绿灯，控制谁先走 |
| 信号（Signal） | 异步通知机制 | 用于通知进程某事件发生 | 像敲门，通知屋里的人 |
| 套接字（Socket） | 网络通信接口 | 可用于不同机器间的进程通信 | 像打电话，可以打给任何人 |

### 管道示例

```c
// 管道示例：父子进程之间通信
#include <unistd.h>   // 包含 pipe()、close()、read()、write() 函数声明
#include <string.h>   // 包含 strlen() 函数声明
#include <stdio.h>    // 包含 printf() 函数声明

int main() {
    int fd[2];        // fd[0] 是读端，fd[1] 是写端
    pipe(fd);         // 创建管道，fd 数组存储读端和写端的文件描述符
    
    pid_t pid = fork();  // 创建子进程
    
    if (pid == 0) {
        // 子进程：写端
        close(fd[0]);   // 关闭读端，子进程只写不读
        
        char msg[] = "Hello from child!";  // 要发送的消息
        write(fd[1], msg, strlen(msg));    // 向管道写入消息
        
        close(fd[1]);   // 关闭写端
    } else {
        // 父进程：读端
        close(fd[1]);   // 关闭写端，父进程只读不写
        
        char buf[100];  // 接收缓冲区
        read(fd[0], buf, sizeof(buf));  // 从管道读取消息
        printf("收到: %s\n", buf);
        
        close(fd[0]);   // 关闭读端
    }
    
    return 0;
}
```

### 共享内存示例

```c
// 共享内存示例：两个进程共享同一块内存
#include <stdio.h>
#include <sys/shm.h>  // 包含共享内存函数声明
#include <string.h>

int main() {
    // 创建共享内存段，大小为 1024 字节
    int shmid = shmget(IPC_PRIVATE, 1024, 0666);
    
    // 将共享内存映射到当前进程
    char* shared = (char*)shmat(shmid, NULL, 0);
    
    // 写入数据到共享内存
    strcpy(shared, "Hello, shared memory!");
    
    // 创建子进程
    pid_t pid = fork();
    
    if (pid == 0) {
        // 子进程：读取共享内存中的数据
        printf("子进程读取: %s\n", shared);
    } else {
        // 父进程：等待子进程完成
        wait(NULL);
        printf("父进程完成\n");
    }
    
    // 解除共享内存映射
    shmdt(shared);
    
    // 删除共享内存段
    shmctl(shmid, IPC_RMID, NULL);
    
    return 0;
}
```

## 7 对比表格

| 对比项 | 进程 | 程序 |
| --- | --- | --- |
| 本质 | 动态的执行过程 | 静态的代码文件 |
| 生命周期 | 有创建、执行、消亡 | 永久存在 |
| 资源占用 | 占用 CPU、内存等 | 不占用运行资源 |
| 并发性 | 具有并发性 | 无 |
| 组成 | 程序段 + 数据段 + PCB | 只有代码 |

| 对比项 | 阻塞 | 就绪 |
| --- | --- | --- |
| 等待对象 | 等待某个事件发生 | 等待 CPU |
| 转换条件 | 事件发生后变为就绪 | 被调度后变为运行 |
| 主动/被动 | 主动发起（请求 I/O） | 被动等待（被调度） |

## 8 新手常见误区

### 误区 1："进程就是程序"

不对。程序是静态的代码文件，进程是动态的执行过程。就像菜谱和正在做的菜的区别。同一个程序可以同时运行多个实例，每个实例都是一个独立的进程。

```c
// 错误理解：进程 = 程序
// 正确理解：进程 = 程序 + 数据 + PCB

// 同一个程序可以创建多个进程
#include <unistd.h>
#include <stdio.h>

int main() {
    // 这个程序运行一次，创建一个进程
    // 如果运行 3 次，就会创建 3 个进程
    printf("PID = %d\n", getpid());
    return 0;
}
```

### 误区 2："就绪状态的进程可以直接变为阻塞状态"

不对。就绪 → 阻塞的转换不会发生。因为处于就绪状态的进程还没有开始运行，不可能主动发起 I/O 请求。只有运行中的进程才能主动请求 I/O，变为阻塞状态。

```
错误的状态转换：
  就绪 → 阻塞（不会发生）

正确的状态转换：
  就绪 → 运行 → 阻塞
```

### 误区 3："进程终止后，PCB 还在"

不对。进程终止时，操作系统会回收进程的所有资源，包括 PCB。PCB 是进程存在的唯一标志，PCB 被删除，进程就不存在了。

```c
// 进程终止后，PCB 被删除
#include <stdlib.h>

int main() {
    exit(0);  // 进程终止，操作系统会：
              // 1. 回收内存
              // 2. 关闭文件
              // 3. 删除 PCB
              // 进程彻底消失
}
```

### 误区 4："管道可以用于任意两个进程之间通信"

不对。管道只能用于有亲缘关系的进程（父子进程、兄弟进程）之间通信。如果要用于任意两个进程之间通信，需要使用命名管道（FIFO）、消息队列、共享内存或套接字。

```c
// 错误：试图用普通管道通信两个无关进程
// 正确：使用命名管道（FIFO）或套接字

// 命名管道示例
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>

int main() {
    // 创建命名管道
    mkfifo("myfifo", 0666);
    
    // 现在任意两个进程都可以通过 "myfifo" 通信
    int fd = open("myfifo", O_WRONLY);  // 打开写端
    write(fd, "Hello", 5);              // 写入数据
    close(fd);
    
    return 0;
}
```

### 误区 5："共享内存是最快的通信方式，所以应该总是使用共享内存"

共享内存确实是最快的 IPC 方式，但它需要同步机制（如信号量）来协调多个进程的访问，否则会出现数据竞争问题。如果只是简单的通知，使用信号或管道可能更合适。

```c
// 共享内存需要同步机制
#include <sys/shm.h>
#include <sys/sem.h>

int main() {
    int shmid = shmget(IPC_PRIVATE, 1024, 0666);  // 创建共享内存
    int semid = semget(IPC_PRIVATE, 1, 0666);     // 创建信号量
    
    // 使用信号量来同步对共享内存的访问
    // 否则多个进程同时读写共享内存会导致数据混乱
    
    return 0;
}
```

### 练习 1：基础练习

画出进程的五状态模型，并说明每个状态转换的触发条件。

<details>
<summary>点击查看答案</summary>

参考答案：

五状态模型：

```
新创建 → 就绪 → 运行 → 终止
                ↓↑
              阻塞
```

状态转换条件：

1. 新创建 → 就绪：进程创建完成，插入就绪队列
2. 就绪 → 运行：被调度器选中，分配 CPU
3. 运行 → 就绪：时间片用完或被更高优先级进程抢占
4. 运行 → 阻塞：主动请求 I/O 或等待某事件
5. 阻塞 → 就绪：等待的事件已完成（如 I/O 结束）
6. 运行 → 终止：进程执行完毕或被强制终止

### 练习 2：进阶练习

用代码实现一个简单的父子进程通信：父进程创建一个管道，子进程向管道写入消息，父进程从管道读取消息。

<details>
<summary>点击查看答案</summary>

参考答案：

```c
#include <unistd.h>
#include <stdio.h>
#include <string.h>
#include <sys/wait.h>

int main() {
    int fd[2];  // fd[0] 读端，fd[1] 写端
    
    // 创建管道
    if (pipe(fd) == -1) {
        perror("pipe failed");
        return 1;
    }
    
    // 创建子进程
    pid_t pid = fork();
    
    if (pid == 0) {
        // 子进程：写入消息
        close(fd[0]);  // 关闭读端
        
        char msg[] = "Hello, parent!";
        write(fd[1], msg, strlen(msg));
        printf("子进程：消息已发送\n");
        
        close(fd[1]);  // 关闭写端
    } else {
        // 父进程：读取消息
        close(fd[1]);  // 关闭写端
        
        char buf[100];
        read(fd[0], buf, sizeof(buf));
        printf("父进程：收到消息: %s\n", buf);
        
        close(fd[0]);  // 关闭读端
        wait(NULL);    // 等待子进程结束
    }
    
    return 0;
}
```

### 练习 3（挑战）：综合练习

设计一个场景：父进程创建两个子进程，子进程 1 负责计算 1+2+...+100，子进程 2 负责计算 1*2*3*...*10。父进程等待两个子进程完成后，输出结果。

提示：使用管道或共享内存进行进程间通信。

<details>
<summary>点击查看答案</summary>

参考答案：

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>
#include <sys/shm.h>

int main() {
    // 创建共享内存，用于子进程 1 传递结果
    int shm1 = shmget(IPC_PRIVATE, sizeof(int), 0666);
    
    // 创建共享内存，用于子进程 2 传递结果
    int shm2 = shmget(IPC_PRIVATE, sizeof(int), 0666);
    
    // 创建子进程 1
    pid_t pid1 = fork();
    if (pid1 == 0) {
        // 子进程 1：计算 1+2+...+100
        int* result = (int*)shmat(shm1, NULL, 0);
        *result = 0;
        for (int i = 1; i <= 100; i++) {
            *result += i;
        }
        printf("子进程 1：计算完成，结果 = %d\n", *result);
        shmdt(result);
        exit(0);
    }
    
    // 创建子进程 2
    pid_t pid2 = fork();
    if (pid2 == 0) {
        // 子进程 2：计算 1*2*3*...*10
        int* result = (int*)shmat(shm2, NULL, 0);
        *result = 1;
        for (int i = 1; i <= 10; i++) {
            *result *= i;
        }
        printf("子进程 2：计算完成，结果 = %d\n", *result);
        shmdt(result);
        exit(0);
    }
    
    // 父进程：等待两个子进程完成
    wait(NULL);
    wait(NULL);
    
    // 读取结果
    int* result1 = (int*)shmat(shm1, NULL, 0);
    int* result2 = (int*)shmat(shm2, NULL, 0);
    
    printf("父进程：子进程 1 的结果 = %d\n", *result1);
    printf("父进程：子进程 2 的结果 = %d\n", *result2);
    
    // 清理共享内存
    shmdt(result1);
    shmdt(result2);
    shmctl(shm1, IPC_RMID, NULL);
    shmctl(shm2, IPC_RMID, NULL);
    
    return 0;
}
```

</details>
