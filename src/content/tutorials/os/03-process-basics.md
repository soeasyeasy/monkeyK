# 第三章：进程管理基础

## 进程的概念

**进程（Process）** 是操作系统进行资源分配和调度的基本单位。简单来说，进程是**正在运行的程序的实例**。

### 进程与程序的区别

| 对比项 | 程序（Program） | 进程（Process） |
| --- | --- | --- |
| 本质 | 静态的代码文件 | 动态的执行过程 |
| 生命周期 | 永久存在 | 有创建、执行、消亡的过程 |
| 资源占用 | 不占用运行资源 | 占用 CPU、内存等资源 |
| 并发性 | 无 | 具有并发性 |
| 对应关系 | 一个程序可对应多个进程 | 一个进程对应一个程序（或多个） |

::: info
同一个程序（如 Chrome）可以同时运行多个实例，每个实例就是一个独立的进程。
:::

### 进程的组成

```
进程 = 程序段 + 数据段 + PCB（进程控制块）
```

- **程序段**：要执行的代码
- **数据段**：程序运行所需的数据（变量、常量等）
- **PCB**：描述进程状态、资源使用情况的数据结构

## 进程的状态与转换

### 五状态模型

进程在生命周期中会经历不同的状态：

```
                    创建
                     │
                     ▼
              ┌─────────────┐
              │   新创建     │
              └──────┬──────┘
                     │ 被调度
                     ▼
              ┌─────────────┐
         ┌───>│   运行       │<───┐
         │    └──────┬──────┘    │
         │           │           │
    I/O完成│     时间片到│      阻塞结束
    或事件 │           ▼           │
         │    ┌─────────────┐    │
         │    │   就绪       │    │
         │    └─────────────┘    │
         │           │           │
         │           │ 请求I/O   │
         │           ▼           │
         │    ┌─────────────┐    │
         └────│   阻塞       │────┘
              └──────┬──────┘
                     │ I/O完成
                     ▼
              ┌─────────────┐
              │   终止       │
              └─────────────┘
```

| 状态 | 说明 |
| --- | --- |
| 新创建（New） | 进程刚被创建，尚未完全就绪 |
| 就绪（Ready） | 已分配到除 CPU 外的所有资源，等待 CPU |
| 运行（Running） | 正在 CPU 上执行 |
| 阻塞（Blocked/Waiting） | 等待某个事件发生（如 I/O 完成、信号量） |
| 终止（Terminated） | 进程执行完毕或被强制终止 |

### 状态转换条件

| 转换 | 触发条件 |
| --- | --- |
| 就绪 → 运行 | 调度器选中该进程，分配 CPU |
| 运行 → 就绪 | 时间片用完或被更高优先级进程抢占 |
| 运行 → 阻塞 | 进程主动请求 I/O 或等待某事件 |
| 阻塞 → 就绪 | 等待的事件已完成（如 I/O 结束） |

::: tip
**就绪 → 阻塞** 的转换**不会发生**。因为处于就绪状态的进程还没有开始运行，不可能主动发起 I/O 请求。
:::

### 七状态模型

在五状态模型基础上增加**挂起（Suspend）** 状态：

| 状态 | 说明 |
| --- | --- |
| 就绪挂起（Ready/Suspend） | 进程在就绪但被换出到外存 |
| 阻塞挂起（Blocked/Suspend） | 进程在阻塞且被换出到外存 |

引入挂起状态的原因：
- 内存不足时，将部分进程换出到磁盘
- 用户需要暂停自己的进程
- 操作系统需要释放内存空间

## 进程控制块（PCB）

**进程控制块（Process Control Block, PCB）** 是操作系统用来描述和管理进程的数据结构。每个进程有且仅有一个 PCB。

### PCB 包含的信息

```c
struct PCB {
    // 1. 进程标识
    int pid;                // 进程 ID
    int ppid;               // 父进程 ID
    int uid;                // 用户 ID

    // 2. 进程状态
    int state;              // 当前状态（就绪/运行/阻塞）
    int priority;           // 优先级

    // 3. 处理器状态（上下文信息）
    int registers[16];      // 通用寄存器
    int pc;                 // 程序计数器
    int psw;                // 程序状态字

    // 4. 进程调度信息
    int queue_priority;     // 在就绪队列中的优先级
    int cpu_time_used;      // 已使用的 CPU 时间

    // 5. 进程控制信息
    int memory_base;        // 内存基址
    int memory_limit;       // 内存界限
    int open_files[10];     // 打开的文件列表
    int signal_mask;        // 信号掩码
};
```

| PCB 信息类别 | 包含内容 |
| --- | --- |
| 进程标识 | PID、PPID、UID |
| 处理机状态 | 通用寄存器、PC、PSW |
| 进程调度信息 | 状态、优先级、已用 CPU 时间 |
| 进程控制信息 | 内存信息、打开文件、信号掩码 |

::: info
当发生进程切换时，操作系统会将当前进程的 CPU 寄存器值保存到其 PCB 中，然后从目标进程的 PCB 中恢复寄存器值。这个过程称为**上下文切换（Context Switch）**。
:::

## 进程控制

操作系统通过一系列原语（Primitive）来管理进程的生命周期。

### 进程创建

```c
// Linux 中使用 fork() 创建新进程
#include <unistd.h>
#include <stdio.h>
#include <sys/wait.h>

int main() {
    pid_t pid = fork();  // 创建子进程

    if (pid < 0) {
        perror("fork failed");
    } else if (pid == 0) {
        // 子进程
        printf("我是子进程，PID = %d\n", getpid());
    } else {
        // 父进程
        printf("我是父进程，PID = %d，子进程 PID = %d\n", getpid(), pid);
        wait(NULL);  // 等待子进程结束
    }
    return 0;
}
```

创建进程时操作系统需要：
1. 为新进程分配 PCB 和内存空间
2. 初始化 PCB（PID、状态、优先级等）
3. 将父进程的数据复制到子进程
4. 将子进程插入就绪队列

### 进程终止

```c
#include <stdlib.h>
#include <unistd.h>

int main() {
    // 正常终止
    exit(0);       // 退出并返回状态码 0

    // 或者在 main 中
    return 0;      // 等价于 exit(0)
}
```

进程终止时操作系统需要：
1. 查询 PCB 获取进程状态
2. 如果正在运行，终止执行，释放 CPU
3. 如果有子进程，将其转交给 init 进程（孤儿进程）
4. 回收进程占有的所有资源（内存、文件等）
5. 删除 PCB

### 进程阻塞与唤醒

```c
// 阻塞：进程主动等待
// 例如等待用户输入
char input[100];
scanf("%s", input);  // 进程阻塞，等待输入完成

// 唤醒：由操作系统或其他进程完成
// 例如 I/O 完成中断触发操作系统唤醒等待该 I/O 的进程
```

::: tip
进程的阻塞和唤醒必须成对出现。阻塞是进程主动行为，唤醒通常由操作系统或另一个进程完成。
:::

## 进程通信

进程之间可以交换信息，常见的通信方式：

| 方式 | 说明 | 特点 |
| --- | --- | --- |
| 管道（Pipe） | 半双工的数据通道 | 只能用于有亲缘关系的进程 |
| 消息队列 | 消息的链表 | 内核维护，可跨进程通信 |
| 共享内存 | 多个进程映射同一块内存 | 最快的 IPC 方式 |
| 信号量（Semaphore） | 用于同步的计数器 | 主要用于进程同步 |
| 信号（Signal） | 异步通知机制 | 用于通知进程某事件发生 |
| 套接字（Socket） | 网络通信接口 | 可用于不同机器间的进程通信 |

```c
// 管道示例
#include <unistd.h>
#include <string.h>

int main() {
    int fd[2];
    pipe(fd);  // 创建管道

    pid_t pid = fork();
    if (pid == 0) {
        // 子进程：写端
        close(fd[0]);  // 关闭读端
        char msg[] = "Hello from child!";
        write(fd[1], msg, strlen(msg));
    } else {
        // 父进程：读端
        close(fd[1]);  // 关闭写端
        char buf[100];
        read(fd[0], buf, sizeof(buf));
        printf("收到: %s\n", buf);
    }
    return 0;
}
```

## 本章小结

- 进程是正在运行的程序，是资源分配和调度的基本单位
- 进程有五种基本状态：新创建、就绪、运行、阻塞、终止
- **PCB** 是操作系统管理进程的核心数据结构，包含进程的所有信息
- 进程控制原语包括：创建、终止、阻塞、唤醒、挂起
- 进程间通信方式包括管道、消息队列、共享内存、信号量、信号和套接字
