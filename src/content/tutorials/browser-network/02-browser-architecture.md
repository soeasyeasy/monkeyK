# 第二章：浏览器架构

## 浏览器进程架构

现代浏览器采用多进程架构，每个标签页、插件和扩展都在独立进程中运行，提高了稳定性和安全性。

### 主要进程类型

| 进程 | 职责 |
| --- | --- |
| 浏览器进程 | 管理 UI、书签、前后退、网络请求 |
| 渲染进程 | 解析 HTML/CSS、执行 JavaScript、绘制页面 |
| GPU 进程 | 处理 GPU 相关任务，加速图形渲染 |
| 扩展进程 | 运行浏览器扩展和插件 |
| 网络进程 | 处理网络请求，管理缓存 |

## 渲染进程内部结构

渲染进程是浏览器的核心，负责将网页代码转换为用户可见的页面。

### 关键组件

```
渲染进程
├── JavaScript 引擎
│   ├── V8 (Chrome/Edge)
│   ├── SpiderMonkey (Firefox)
│   └── JavaScriptCore (Safari)
├── 渲染引擎
│   ├── Blink (Chrome/Edge)
│   ├── Gecko (Firefox)
│   └── WebKit (Safari)
├── 布局模块
├── 绘制模块
└── 合成模块
```

## JavaScript 引擎

JavaScript 引擎负责解析和执行 JavaScript 代码。现代引擎采用 JIT（即时编译）技术，将 JavaScript 编译为机器码，大幅提升执行速度。

### V8 引擎工作流程

1. **解析阶段**：将源代码解析为 AST（抽象语法树）
2. **编译阶段**：将 AST 编译为字节码
3. **优化阶段**：使用 JIT 编译器将热点代码优化为机器码
4. **执行阶段**：执行机器码

## 渲染引擎

渲染引擎负责解析 HTML 和 CSS，构建 DOM 树和 CSSOM 树，最终渲染页面。

### 渲染流程

1. **解析 HTML** → 构建 DOM 树
2. **解析 CSS** → 构建 CSSOM 树
3. **合并 DOM 和 CSSOM** → 构建渲染树
4. **布局（Layout）** → 计算元素位置和大小
5. **绘制（Paint）** → 绘制像素到屏幕
6. **合成（Composite）** → 分层合成最终画面

## 浏览器存储

浏览器提供多种存储机制：

| 存储方式 | 容量 | 生命周期 | 特点 |
| --- | --- | --- | --- |
| Cookie | 4KB | 可设置 | 每次请求自动携带 |
| LocalStorage | 5-10MB | 永久 | 仅客户端，不自动发送 |
| SessionStorage | 5-10MB | 会话期间 | 关闭标签页即清除 |
| IndexedDB | 大容量 | 永久 | 结构化存储，支持事务 |
| Cache API | 大容量 | 永久 | 用于 Service Worker 缓存 |

## 本章小结

浏览器的多进程架构提高了稳定性和安全性，渲染引擎和 JavaScript 引擎是核心组件。理解浏览器内部工作机制，有助于我们编写更高效的代码。
