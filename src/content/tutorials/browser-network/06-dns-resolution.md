# 第六章：DNS 解析过程

## DNS 概述

DNS（Domain Name System）是域名系统，用于将域名转换为 IP 地址。

### 为什么需要 DNS

- 人类易记域名：www.example.com
- 计算机使用 IP：192.168.1.1
- DNS 充当翻译器

## DNS 解析流程

当你在浏览器输入域名时，DNS 解析按以下顺序进行：

### 1. 浏览器缓存
浏览器会缓存 DNS 记录，优先从缓存中查找。

### 2. 操作系统缓存
如果浏览器缓存未命中，查询操作系统缓存。

### 3. Hosts 文件
检查本地 hosts 文件（`/etc/hosts` 或 `C:\Windows\System32\drivers\etc\hosts`）。

### 4. 本地 DNS 服务器
向 ISP 提供的本地 DNS 服务器发起查询。

### 5. 根域名服务器
本地 DNS 服务器向根域名服务器查询。

### 6. 顶级域名服务器
根服务器返回顶级域名（如 .com）服务器地址。

### 7. 权威域名服务器
顶级域名服务器返回权威域名服务器地址。

### 8. 返回 IP 地址
权威域名服务器返回域名对应的 IP 地址。

## DNS 记录类型

| 记录类型 | 用途 | 示例 |
| --- | --- | --- |
| A | IPv4 地址 | 192.168.1.1 |
| AAAA | IPv6 地址 | 2001:0db8:85a3::8a2e |
| CNAME | 别名指向 | www.example.com → example.com |
| MX | 邮件服务器 | mail.example.com |
| TXT | 文本记录 | 验证、SPF 记录 |
| NS | 域名服务器 | ns1.example.com |
| SOA | 起始授权机构 | 域名管理信息 |

## DNS 查询方式

### 递归查询
客户端向本地 DNS 服务器发起递归查询，本地 DNS 服务器负责返回最终结果。

```
客户端 → 本地 DNS → 根 DNS → 顶级 DNS → 权威 DNS → 返回结果
```

### 迭代查询
本地 DNS 服务器向其他服务器迭代查询，每次返回下一步查询的地址。

```
客户端 → 本地 DNS
本地 DNS → 根 DNS（返回顶级 DNS 地址）
本地 DNS → 顶级 DNS（返回权威 DNS 地址）
本地 DNS → 权威 DNS（返回 IP 地址）
本地 DNS → 客户端
```

## DNS 缓存

### 缓存层级

| 层级 | 位置 | TTL | 说明 |
| --- | --- | --- | --- |
| 浏览器 | 内存 | 短 | 最快，容量小 |
| 操作系统 | 内存 | 中 | 系统级缓存 |
| 本地 DNS | 磁盘/内存 | 长 | ISP 维护 |
| 根/顶级 | 分布式 | 长 | 全球分布 |

### TTL（Time To Live）
DNS 记录的生存时间，超过 TTL 后缓存失效，需要重新查询。

## DNS 优化

### 预解析
在 HTML 中使用 `dns-prefetch` 提前解析域名：
```html
<link rel="dns-prefetch" href="//example.com">
```

### 使用 CDN
CDN 通过分布式节点加速 DNS 解析和资源加载。

### 减少 DNS 查询
- 合并子域名
- 使用长连接
- 避免过多外部资源

## DNS 安全

### DNS 劫持
攻击者篡改 DNS 解析结果，将用户引导到恶意网站。

### DNS 缓存投毒
攻击者向 DNS 缓存注入虚假记录。

### DNSSEC
DNS 安全扩展，通过数字签名验证 DNS 数据的真实性。

## 本章小结

DNS 是互联网的基础设施，将易记的域名转换为 IP 地址。理解 DNS 解析流程和缓存机制，有助于优化网站性能和排查网络问题。
