# 第三章：网络基础概念

## 客户端-服务器模型

网络通信的基础是客户端-服务器模型：

| 角色 | 职责 | 示例 |
| --- | --- | --- |
| 客户端 | 发起请求，等待响应 | 浏览器、移动应用 |
| 服务器 | 接收请求，返回响应 | Web 服务器、API 服务器 |

### 请求-响应流程

1. 客户端建立连接
2. 客户端发送请求
3. 服务器处理请求
4. 服务器返回响应
5. 客户端接收响应
6. 连接关闭或保持

## 网络协议分层

网络协议采用分层设计，每层负责不同的功能。

### OSI 七层模型

| 层次 | 名称 | 功能 | 协议示例 |
| --- | --- | --- | --- |
| 7 | 应用层 | 提供用户接口 | HTTP、FTP、SMTP |
| 6 | 表示层 | 数据格式转换 | SSL/TLS |
| 5 | 会话层 | 管理会话 | NetBIOS |
| 4 | 传输层 | 端到端通信 | TCP、UDP |
| 3 | 网络层 | 路由选择 | IP、ICMP |
| 2 | 数据链路层 | 帧传输 | Ethernet、Wi-Fi |
| 1 | 物理层 | 比特流传输 | 光纤、电缆 |

### TCP/IP 四层模型

实际应用中，通常使用简化的四层模型：

```
应用层    ← HTTP、FTP、DNS
传输层    ← TCP、UDP
网络层    ← IP、ICMP
网络接口层 ← Ethernet、Wi-Fi
```

## 数据封装

数据在网络中传输时，每层都会添加自己的头部信息，这个过程称为数据封装。

### 封装过程

```
应用层数据
    ↓
添加传输层头部（TCP/UDP）→ 段（Segment）
    ↓
添加网络层头部（IP）→ 包（Packet）
    ↓
添加数据链路层头部 → 帧（Frame）
    ↓
转换为比特流传输
```

### 解封装过程

接收端按相反顺序处理：

1. 物理层接收比特流
2. 数据链路层去除帧头部
3. 网络层去除 IP 头部
4. 传输层去除 TCP/UDP 头部
5. 应用层获取原始数据

## 网络地址

### IP 地址

IP 地址用于唯一标识网络中的设备：

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| IPv4 | 32 位，点分十进制 | 192.168.1.1 |
| IPv6 | 128 位，冒号十六进制 | 2001:0db8:85a3::8a2e:0370:7334 |

### 端口号

端口号用于标识设备上的不同服务：

| 端口范围 | 用途 |
| --- | --- |
| 0-1023 | 知名端口（HTTP:80, HTTPS:443） |
| 1024-49151 | 注册端口 |
| 49152-65535 | 动态端口 |

## 本章小结

网络通信基于客户端-服务器模型，采用分层协议设计。数据在传输过程中经过多次封装和解封装，每层添加或去除相应的头部信息。理解这些基础概念是学习网络协议的前提。
