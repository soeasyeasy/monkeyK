# 第七章：TCP/IP 协议栈

## TCP/IP 概述

TCP/IP 是互联网的基础协议栈，由传输控制协议（TCP）和网际协议（IP）组成。

### 协议栈层次

| 层次 | 协议 | 功能 |
| --- | --- | --- |
| 应用层 | HTTP、FTP、DNS | 提供用户服务 |
| 传输层 | TCP、UDP | 端到端通信 |
| 网络层 | IP、ICMP | 路由选择 |
| 网络接口层 | Ethernet、Wi-Fi | 物理传输 |

## TCP vs UDP

| 特性 | TCP | UDP |
| --- | --- | --- |
| 连接方式 | 面向连接 | 无连接 |
| 可靠性 | 可靠传输 | 不可靠 |
| 顺序保证 | 保证顺序 | 不保证 |
| 流量控制 | 有 | 无 |
| 拥塞控制 | 有 | 无 |
| 传输速度 | 较慢 | 较快 |
| 头部开销 | 20 字节 | 8 字节 |
| 应用场景 | 网页、文件传输 | 视频、游戏 |

## TCP 三次握手

建立 TCP 连接需要三次握手：

```
客户端                    服务器
  |                         |
  |--- SYN (seq=x) -------->|  第一次握手
  |                         |
  |<-- SYN+ACK (seq=y,      |  第二次握手
  |    ack=x+1) ------------|
  |                         |
  |--- ACK (ack=y+1) ------>|  第三次握手
  |                         |
  |===== 连接建立 ==========|
```

### 握手过程详解

1. **第一次握手**：客户端发送 SYN 包，进入 SYN_SENT 状态
2. **第二次握手**：服务器收到 SYN，回复 SYN+ACK，进入 SYN_RCVD 状态
3. **第三次握手**：客户端收到 SYN+ACK，回复 ACK，双方进入 ESTABLISHED 状态

### 为什么需要三次握手

- 防止已失效的连接请求到达服务器
- 双方确认彼此的发送和接收能力
- 同步序列号

## TCP 四次挥手

断开 TCP 连接需要四次挥手：

```
客户端                    服务器
  |                         |
  |--- FIN (seq=u) -------->|  第一次挥手
  |                         |
  |<-- ACK (ack=u+1) -------|  第二次挥手
  |                         |
  |===== 客户端进入 FIN-WAIT-2 =====|
  |                         |
  |<-- FIN (seq=w) ---------|  第三次挥手
  |                         |
  |--- ACK (ack=w+1) ------>|  第四次挥手
  |                         |
  |===== 连接关闭 ==========|
```

### 挥手过程详解

1. **第一次挥手**：客户端发送 FIN，请求关闭连接
2. **第二次挥手**：服务器确认收到 FIN
3. **第三次挥手**：服务器也发送 FIN，请求关闭连接
4. **第四次挥手**：客户端确认收到 FIN

### 为什么需要四次挥手

- TCP 是全双工通信，每个方向需要单独关闭
- 服务器可能还有数据要发送
- 确保双方都能正常关闭连接

## TCP 可靠传输机制

### 序列号与确认号
- **序列号**：标识数据段的顺序
- **确认号**：确认已接收的数据，期望接收的下一个序列号

### 超时重传
发送方在超时未收到确认时，会重传数据。

### 滑动窗口
- 控制发送方发送数据的速率
- 接收方通过窗口大小告知发送方自己的接收能力

### 流量控制
接收方通过调整窗口大小，控制发送方的发送速率，防止接收方缓冲区溢出。

### 拥塞控制
- **慢启动**：逐步增加发送窗口
- **拥塞避免**：线性增长
- **快速重传**：收到 3 个重复 ACK 立即重传
- **快速恢复**：避免窗口过小

## TCP 头部结构

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| 源端口 | 16 位 | 发送方端口 |
| 目的端口 | 16 位 | 接收方端口 |
| 序列号 | 32 位 | 数据段序号 |
| 确认号 | 32 位 | 期望接收的序号 |
| 数据偏移 | 4 位 | 头部长度 |
| 标志位 | 6 位 | SYN、ACK、FIN 等 |
| 窗口大小 | 16 位 | 接收窗口大小 |
| 校验和 | 16 位 | 数据完整性 |
| 紧急指针 | 16 位 | 紧急数据位置 |

## 本章小结

TCP 提供可靠的、面向连接的传输服务，通过三次握手建立连接，四次挥手断开连接。序列号、确认号、超时重传、滑动窗口等机制保证了数据的可靠传输。理解 TCP/IP 协议栈对于网络编程和性能优化至关重要。
