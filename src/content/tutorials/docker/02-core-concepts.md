# 第2章：核心概念详解

## 本章导读

在学这一章之前，你可能会有这些疑问：

- 镜像和容器到底有什么区别？
- 仓库是什么？为什么要用仓库？
- 这三个概念之间是什么关系？
- 为什么镜像是分层的？

这一章会彻底搞懂 Docker 的三大核心概念：**镜像（Image）、容器（Container）、仓库（Registry）**。理解了它们，后面的所有操作都会变得简单。

---

## 1 为什么需要理解这些概念？

### 痛点分析

很多新手学 Docker 时，上来就背命令，结果：

- 不知道 `docker run` 的镜像和容器是什么关系
- 不明白为什么删除容器后，数据可能丢失
- 搞不清镜像和容器的区别，经常混淆

### 解决方案

打个比方：

> 想象你要开一家连锁餐厅：
>
> - **镜像** 就是你的 **菜谱**——详细记录了怎么做菜、用什么食材
> - **容器** 就是 **做出来的菜**——按照菜谱做出来的实际菜品
> - **仓库** 就是 **菜谱库**——存放各种菜谱的地方，你可以从那里获取菜谱
>
> 菜谱（镜像）是只读的，你可以按照它做出无数道菜（容器）。每道菜都是独立的，但都遵循同一份菜谱。

---

## 2 镜像（Image）

### 概念解释

**镜像** 是一个只读的模板，包含了运行应用所需的一切：

- 操作系统（如 Ubuntu、Alpine）
- 运行环境（如 Node.js、Python、Java）
- 应用代码
- 依赖库
- 配置文件

打个比方：

> 镜像就像一张 **光盘（CD）**。光盘里刻录了完整的软件，你可以用它来安装程序，但光盘本身是只读的，不能修改。

### 镜像的分层结构

Docker 镜像是由一层一层的文件系统组成的，每一层都是只读的。

```
┌─────────────────────────┐
│      应用代码层          │  ← 你的代码
├─────────────────────────┤
│      配置文件层          │  ← 配置
├─────────────────────────┤
│      依赖安装层          │  ← npm install 等
├─────────────────────────┤
│      运行环境层          │  ← Node.js
├─────────────────────────┤
│      基础操作系统层       │  ← Ubuntu/Alpine
└─────────────────────────┘
```

为什么要分层？

- **共享资源**：多个镜像可以共享相同的底层（如 Ubuntu 基础层），节省空间
- **快速构建**：修改代码时，只需要重建代码层，其他层可以复用缓存
- **增量传输**：拉取镜像时，如果某一层已经存在，就不需要重复下载

### 查看镜像

```bash
# ❶ 查看本地所有镜像
docker images

# 输出示例：
# REPOSITORY    TAG       IMAGE ID       CREATED        SIZE
# nginx         latest    605c77e624dd   2 weeks ago    141MB
# ubuntu        22.04     5cce9e5d4567   3 weeks ago    77.8MB

# ❷ 查看镜像的详细信息
docker inspect nginx

# ❸ 查看镜像的构建历史（每一层是怎么来的）
docker history nginx
```

## 3 容器（Container）

### 概念解释

**容器** 是镜像的运行实例。如果说镜像是"菜谱"，容器就是"做出来的菜"。

容器在镜像的基础上增加了一个 **可写层**：

```
┌─────────────────────────┐
│      可写层（容器层）     │  ← 容器运行时添加，可修改
├─────────────────────────┤
│      应用代码层（只读）   │
├─────────────────────────┤
│      配置文件层（只读）   │
├─────────────────────────┤
│      依赖安装层（只读）   │
├─────────────────────────┤
│      运行环境层（只读）   │
├─────────────────────────┤
│      基础操作系统层（只读）│
└─────────────────────────┘
```

打个比方：

> 镜像就像 **PDF 文件**——只读的，不能修改。
>
> 容器就像 **在 PDF 上做了批注**——你可以在上面写字、画圈，但这些修改只存在于你的这份副本上，不会影响原始的 PDF。

### 容器的生命周期

```
创建 → 运行 → 停止 → 删除
 │      │      │      │
 │      │      │      └─ 容器被彻底删除
 │      │      └─ 容器停止，但数据还在（可重启）
 │      └─ 容器正在运行
 └─ 从镜像创建容器
```

### 容器 vs 镜像

| 特性 | 镜像 | 容器 |
| --- | --- | --- |
| 本质 | 只读模板 | 运行中的实例 |
| 可修改性 | 不可修改 | 可以修改（可写层） |
| 数量关系 | 一个镜像可以创建多个容器 | 一个容器只能来自一个镜像 |
| 生命周期 | 永久存在 | 可以启动、停止、删除 |
| 类比 | 类（Class） | 对象（Instance） |
| 类比 | 菜谱 | 做出来的菜 |

### 查看容器

```bash
# ❶ 查看正在运行的容器
docker ps

# ❷ 查看所有容器（包括已停止的）
docker ps -a

# ❸ 查看容器的详细信息
docker inspect my-container

# ❹ 查看容器的日志
docker logs my-container
```

## 4 仓库（Registry）

### 概念解释

**仓库** 是存放镜像的地方。就像 App Store 存放应用一样，Docker 仓库存放各种镜像。

打个比方：

> 仓库就像 **图书馆**——里面存放着各种各样的书（镜像）。你可以去图书馆借书（拉取镜像），也可以把自己写的书放到图书馆（推送镜像）。

### Docker Hub

[Docker Hub](https://hub.docker.com/) 是 Docker 官方的公共仓库，也是默认的仓库。它提供了大量官方镜像：

- `nginx`：Web 服务器
- `mysql`：数据库
- `redis`：缓存
- `node`：Node.js 运行环境
- `python`：Python 运行环境

### 仓库的分类

| 类型 | 说明 | 示例 |
| --- | --- | --- |
| 公共仓库 | 所有人都可以访问 | Docker Hub、阿里云镜像仓库 |
| 私有仓库 | 只有授权用户可以访问 | 公司内部的 Harbor、AWS ECR |
| 本地仓库 | 本地搭建的仓库 | 用 Registry 镜像搭建 |

### 镜像命名规则

镜像的完整命名格式：

```
[仓库地址/]用户名/仓库名:标签
```

示例：

```bash
# ❶ 官方镜像（省略了 docker.io/library/）
nginx:latest
# 完整写法：docker.io/library/nginx:latest

# ❷ 用户镜像
myuser/myapp:v1.0
# 完整写法：docker.io/myuser/myapp:v1.0

# ❸ 私有仓库镜像
registry.company.com/myapp:latest
```

标签（Tag）说明：

- `latest`：最新版本（默认）
- `v1.0`、`v2.3.1`：指定版本
- `alpine`：基于 Alpine Linux 的精简版
- `slim`：精简版

### 仓库操作

```bash
# ❶ 搜索镜像
docker search nginx

# ❷ 拉取镜像
docker pull nginx:latest

# ❸ 推送镜像（需要先登录）
docker login
docker push myuser/myapp:v1.0

# ❹ 给镜像打标签
docker tag nginx:latest myuser/nginx:v1.0
```

## 5 三者关系图解

```
                    ┌─────────────────┐
                    │   仓库 Registry  │
                    │  (Docker Hub)   │
                    └────────┬────────┘
                             │
                      拉取/推送
                             │
                    ┌────────▼────────┐
                    │   镜像 Image    │
                    │  (只读模板)     │
                    └────────┬────────┘
                             │
                      创建/运行
                             │
                    ┌────────▼────────┐
                    │   容器 Container │
                    │  (运行实例)      │
                    └─────────────────┘
```

工作流程：

1. 从 **仓库** 拉取 **镜像** 到本地
2. 用 **镜像** 创建并运行 **容器**
3. 可以修改 **容器**，但这些修改不会回到 **镜像**
4. 可以把修改后的 **容器** 打包成新的 **镜像**，推送到 **仓库**

## 6 核心知识点总结

| 概念 | 说明 | 类比 |
| --- | --- | --- |
| 镜像（Image） | 只读模板，包含运行环境 | 菜谱、PDF、类 |
| 容器（Container） | 镜像的运行实例 | 做出来的菜、批注的 PDF、对象 |
| 仓库（Registry） | 存放镜像的地方 | 图书馆、App Store |
| 镜像分层 | 由多层只读文件系统组成 | 千层饼 |
| 容器可写层 | 容器运行时添加的可写层 | 在 PDF 上做批注 |

## 7 新手常见误区

### 误区 1："删除容器，镜像也会删除"

**错！** 容器和镜像是独立的。删除容器只是删除了运行实例，镜像还在本地。你可以用同一个镜像创建无数个容器。

```bash
# 删除容器不会删除镜像
docker rm my-container

# 镜像还在
docker images
```

### 误区 2："修改容器，镜像也会变"

不是的。镜像是只读的，你对容器做的任何修改都只存在于容器的可写层。如果你想要保存修改，需要：

- 把容器提交为新镜像：`docker commit`
- 或者使用数据卷（后面会学）

### 误区 3："镜像越大越好"

不是的。大的镜像意味着：

- 下载慢
- 占用磁盘多
- 启动慢

好的实践是使用精简的基础镜像（如 `alpine`），只安装必要的依赖。

### 误区 4："容器就是轻量级虚拟机"

虽然容器和虚拟机很像，但容器共享宿主机内核，隔离性不如虚拟机。不要把容器当作完全隔离的环境，对于需要强隔离的场景，还是应该用虚拟机。

## 8 动手练习

### 练习 1：镜像操作

拉取 `nginx` 和 `ubuntu` 镜像，查看它们的详细信息和构建历史。

<details>
<summary>点击查看答案</summary>

```bash
# ❶ 拉取镜像
docker pull nginx:latest
docker pull ubuntu:22.04

# ❷ 查看所有镜像
docker images

# ❸ 查看 nginx 镜像的详细信息
docker inspect nginx:latest

# ❹ 查看 nginx 镜像的构建历史
docker history nginx:latest

# ❺ 查看 ubuntu 镜像的构建历史
docker history ubuntu:22.04
```

你会发现 nginx 镜像有很多层，每一层对应 Dockerfile 中的一条指令。

</details>

### 练习 2：容器操作

用 `ubuntu` 镜像创建一个容器，进入容器内部，查看系统信息。

<details>
<summary>点击查看答案</summary>

```bash
# ❶ 以交互模式运行容器
docker run -it --name my-ubuntu ubuntu:22.04 bash

# ❷ 在容器内执行命令
cat /etc/os-release
# 查看系统版本

whoami
# 输出：root

ls -la
# 查看根目录

# ❸ 退出容器
exit

# ❹ 查看容器状态
docker ps -a
# 你会发现 my-ubuntu 容器状态是 Exited

# ❺ 重新启动容器
docker start my-ubuntu

# ❻ 再次进入容器
docker exec -it my-ubuntu bash

# ❼ 停止并删除容器
docker stop my-ubuntu
docker rm my-ubuntu
```

</details>

### 练习 3（挑战）：镜像与容器关系验证

验证"一个镜像可以创建多个容器"，并观察容器之间的独立性。

<details>
<summary>点击查看答案</summary>

```bash
# ❶ 用同一个 ubuntu 镜像创建两个容器
docker run -d --name container1 ubuntu:22.04 sleep 3600
docker run -d --name container2 ubuntu:22.04 sleep 3600

# ❷ 查看容器
docker ps
# 你会看到两个容器都在运行

# ❸ 进入 container1，创建一个文件
docker exec -it container1 bash
echo "Hello from container1" > /test.txt
exit

# ❹ 进入 container2，检查是否有这个文件
docker exec -it container2 bash
cat /test.txt
# 输出：cat: /test.txt: No such file or directory
# 说明容器之间是独立的

# ❺ 清理
docker stop container1 container2
docker rm container1 container2
```

这个实验证明了：同一个镜像创建的多个容器是完全独立的。

</details>
