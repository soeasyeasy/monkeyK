# 教程编写规范

## 核心原则

教程必须做到：**通俗易懂、结构完整、有原理有解释、新手友好**。

---

## 教程结构模板

每章教程必须包含以下 8 个部分：

### 1. 本章导读
- 列出新手常见疑问（3-4 个问题）
- 说明本章会解决什么问题
- 让读者知道学完能收获什么

### 2. 为什么需要这个技术
- 对比"没有这个技术时的痛点"
- 用生活化类比解释技术价值
- 用代码对比展示前后差异

### 3. 核心原理讲解
- 解释底层原理（如 Proxy、响应式系统等）
- 用通俗类比帮助理解
- 对比不同版本/方案的差异

### 4. 基础用法 + 逐行注释
- 每行代码都要有中文注释
- 解释"这行在做什么"和"为什么这样写"
- 用 ✅ ❌ 标记正确/错误写法

### 5. 对比表格
- 用表格清晰展示对比（如 ref vs reactive）
- 列出不同场景的选择建议

### 6. 新手常见误区
- 列出 3-5 个新手容易犯的错误
- 每个误区都要解释"为什么错"和"正确做法"

### 7. 动手练习
- 提供 3 个练习题（基础 → 进阶 → 挑战）
- 每个练习都要有折叠答案
- 答案代码要完整可运行

### 8. 下一章预告
- 简要说明下一章会学什么
- 引导学习路径

---

## 写作风格要求

### 语言风格
- 使用通俗易懂的口语化表达
- 避免学术化、晦涩的术语
- 多用"你"、"我们"拉近距离

### 类比要求
- 每个核心概念都要有生活化类比
- 类比要贴近新手的生活经验
- 示例：
  - Vue 数据驱动 → "像服务员帮你下单，不用自己跑厨房"
  - Proxy → "像给对象套了一层代理，所有操作都会被拦截"
  - 依赖收集 → "像快递员记下谁收了快递"

### 代码示例
- 代码要完整可运行
- 每行都要有注释
- 用 ✅ ❌ 标记正确/错误写法
- 复杂代码要分步骤讲解

### 表格使用
- 对比不同 API 时用表格
- 对比不同方案时用表格
- 列出选择建议时用表格
